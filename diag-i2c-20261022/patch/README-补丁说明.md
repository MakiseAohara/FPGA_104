# I2C 修复补丁 · 2026-10-22（已在板上验证）

> 来源：本机独立工程 PERIPH09 实测通过。三个文件覆盖到 `rtl\mmt\sensors\` 即可。

## 结论先说

交接里「SHT30 / MLX90640 一次应答都没有」的**根因是接线**；接线修好后两个从机立刻出现
（地址扫描 `P=02 A=33 B=44`）。修完接线后还剩一个**真实的 RTL bug**，就是本补丁修的。

## 三个补丁

| 文件 | 大小 | sha256 | 改了什么 |
|---|---|---|---|
| `mmt_i2c_master.v` | 20,881 B | `4b31f01d35ab3255afc0f9828ba02909c5daf8c9365af859ed153b8d37f98f6b` | ①读数据位把 SDA 释放从 ph1 挪到 **ph0** ②SCL 改**开漏** ③支持**时钟拉伸**+超时保护 |
| `mmt_sht30_ctrl.v` | 10,942 B | `f6dc8af8aa1fb7b876c6882169c6152a9a3002891cf55732a2d66c175ee7adff` | 单次测量命令 `0x2400` → **`0x2C06`**（0x2400 是「使能时钟拉伸」，注释写反了） |
| `mmt_sensor_subsystem.v` | 9,422 B | `c0a7b3bd4302ee6a98656bd2790331360a246def961d42f7b05723c488e55c34` | `m_tx_data` 16→**32** 位、`m_tx_len` 2→**3** 位（原来 `tx_len=4` 被截成 0，MLX 的 4 字节寄存器写失效） |

## 主 bug 的证据链

| 版本 | 现象 | 说明 |
|---|---|---|
| 原主机（推挽 SCL，SDA 在 ph1 末尾释放） | `B=6452 4BFF FFFF` | 温度半区完美（CRC 对），湿度半区 `FF` |
| 只把 SCL 改开漏 + 拉伸 | `B=64FF FFFF FFFF` | 更差：SDA 上升更慢，更容易撞 STOP |
| **加"ph0 提前释放 SDA"** | **`B=64A6 0D83 5A2A`** | 6 字节全到，两段 CRC 全对 |

机理：读数据位时原来只比 SCL 抬高早一个相位（100 kHz 下 2.5 µs）才放开 SDA；
10k 上拉 + 长线的上升时间与之同量级，从机看到「SCL 高 + SDA 上升」= **STOP**，于是提前结束发送。
提前到低电平一开始（2 个相位余量）后彻底消失。

## 改完后实测（PERIPH09，27 MHz 独立工程）

```
S=V T=0954 H=1410 I=V F=0011 P=0667
S=V T=0953 H=140F I=V F=0012 P=0667
```

- `S=V`：SHT30 有效，T=0x0954 → **23.88 °C**，H=0x1410 → **51.36 %RH**
- `I=V`、`F` 递增：MLX90640 正常出帧

## 应用方式

1. 把三个文件覆盖到工程的 `rtl\mmt\sensors\`。
2. 全树 diff 应只有这三个文件不同。
3. 重新跑完整流程（`v7_flow.ps1`），时序全正后烧录。

## 副作用与注意

- `scl_i` 现在**真的被使用了**（拉伸检测），因此不会再出现「`i_sensor_scl` 被综合器当未连接输入摘掉」。
- SCL 变成开漏后，高电平完全靠上拉，**上升沿变慢**；如果板子上拉偏弱（>10k）或线很长，可以降到 50 kHz。
- 拉伸超时约 0.6 s（24 位计数），超时会置 `err` 并正常收尾，不会死等。
- 本次只改了 RTL，没有动约束/peri；`drive_strength` 仍是 4（交接文档写的 2 是错的）。

## 3. PERIPH02 怎么看

串口：FTDI C 通道 / 当前 **COM15**，115200 8N1。上电后每 0.5 s 一行，形如：

```
PT=0 RD=11
PT=1 RD=01
PT=2 RD=10
PT=3 RD=00
```

每相位 3 秒循环；LED0 在 `PT=1`/`PT=3` 相位点亮（低有效），可肉眼对相位。

### 判据表（只读串口就能定位）

| 现象 | 结论 | 下一步 |
|---|---|---|
| `PT=0 RD=11`，其余三相位的 RD 都等于期望 | **pad 出+入都好，线也通** ⇒ 问题在从机地址/模块 | 回去改地址（SHT30 试 0x45；确认红外模块型号），或烧 PERIPH01 看 `S=V` |
| 某相位 RD 恒为 `11`（该拉低却读回高） | 那一路的 pad 输出或输入没接通 | 用万用表量模块对应脚（见下） |
| `PT=0` 就读到 `RD≠11` | 总线被外部拉住（短路/接反/模块短路） | 拔掉模块再测一次 |

### 万用表配合（可选但更准）

在 `PT=1`（只拉低 SCL）时量**模块的 SCL 脚**：

- **≈0 V** ⇒ 输出通路 + 接线都好（结论同上第一行）；
- **≈3.3 V** ⇒ FPGA 说在拉低、线却没低：引脚映射错 / 线断 / 模块把线拉住。

`PT=2` 时同样量模块 SDA 脚。

## 6. 实测记录（2026-10-22 00:2x，已烧 PERIPH02）

### 串口怎么读（重要）

本机 FT4232H 现在**只枚举出一个 VCP（COM12，D 通道）**，而板载 UART 在 **C 通道**，所以 `System.IO.Ports` 读不到（裸读 0 字节）。
直接开 **D2XX** 就能读：

```
ftd2xx 打开 index=2（C 通道），setBaudRate(115200)，setDataCharacteristics(8,1,NONE)，purge()
```
脚本：`_diag/d2xx_read.py`（用 `D:\Efinity\2026.1\python311\bin\python.exe` 跑）。
若要让 VCP 恢复成四个口，需要物理重插 USB 或管理员重启该设备——**重插会掉电，JTAG 位流丢失，要重新烧**。

### 实测输出

```
PT=0 RD=11
PT=1 RD=10
PT=2 RD=01
```

注意 **RD 的顺序是 `{SDA, SCL}`**（第一位 SDA，第二位 SCL），与本文 §3 表格里按 SCL 在前的写法相反。
换算后：

| 相位 | 驱动 | 实测 RD(SDA,SCL) | 含义 |
|---|---|---|---|
| PT=0 | 都不拉 | `11` | SDA=1、SCL=1，总线没被外部拉住 ✓ |
| PT=1 | 只拉低 SCL | `10` | SDA=1、**SCL=0** ⇒ SCL 的 pad 出+入都通 ✓ |
| PT=2 | 只拉低 SDA | `01` | **SDA=0**、SCL=1 ⇒ SDA 的 pad 出+入都通 ✓ |

### 这一步排除了什么

- ✅ 排除「pad 没建 / 输入通路坏 / 输出没驱动」——两条线的输出+输入回路都自洽。
- ❓ 仍未区分「引脚到排针的映射错/线断」与「从机地址不对」：pad 拉低时读回低只证明**芯片内部到球**没问题，
  不证明 J7 pin32/34 就是 C5/A4。

⇒ 下一步（PERIPH03，已构建）：独立地址扫描 0x08–0x77，串口出 `P=nn A=xx B=xx S=nn`。
`P>0` = 地址不对（改 SHT30_ADDR/MLX90640_ADDR）；`P=00` = 总线上没有人应答（线/模块）。

## 7. 重测结果（2026-10-22 00:5x，线重新接好之后）

### 7.1 地址扫描：两个从机都在

```
P=02 A=33 B=44 S=28      (连续 157+ 轮稳定)
```

- **0x33 = MLX90640**，**0x44 = SHT30**，都是默认地址，**不需要改任何 ADDR 参数**。
- 之前的 `P=00` 是接线没接好造成的，**不是硬件/地址/program 问题**。

### 7.2 真实传感器诊断（PERIPH01）

```
S=C T=0000 H=0000 I=V F=0011 P=0660
S=C T=0000 H=0000 I=V F=0012 P=0660
```

- `I=V`、`F` 递增：**MLX90640 红外帧正常**（P=0660 是原始 Ptat）。
- `S=C`：SHT30 应答正常，但 CRC 失败 ⇒ 温度/湿度不更新。

### 7.3 SHT30 原始字节（PERIPH05，100 kHz）

```
B=6452 4BFF FFFF E=0
```

| 字节 | 值 | 含义 |
|---|---|---|
| b0,b1 | `64 52` | S_T = 25682 → **T = 23.58 °C** |
| b2 | `4B` | CRC(0x64,0x52) = **0x4B，匹配** ✓ |
| b3..b5 | `FF FF FF` | 总线空闲：传感器发完温度就放开了 SDA |

⇒ 主机收发、地址、CRC 全对；**SHT30 只回了温度那一半，湿度半区缺失**。

降到 **10 kHz** 重测反而更差（只回 2 字节 `64 57 FF`）：说明这是**时间相关**的行为，
最符合“T 与 RH 两半之间需要时钟拉伸，而本主机 SCL 是推挽驱动、不支持拉伸”这一解释。

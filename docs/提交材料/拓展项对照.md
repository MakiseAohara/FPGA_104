## 说明（如实）

1. **① 的边界**：题面要求"通过 RGMII 接口上传到 PC 服务器"。上报**内容与协议**（类型/时间/位置/置信度/缩略图）已按题义实现并可运行；
   **物理链路**仍是 UART，且**本板无法改成 RGMII**：`Ti60F225I3-V4` 板载资源里没有以太网 PHY、没有 RJ45（见 `docs/工程全貌与学习地图.md` §2.2），
   J7 只引出 6 个通用 3.3V IO，而 RGMII 需要 txd×4 + txc + tx_ctl + rxd×4 + rxc + rx_ctl + mdc + mdio 共 14 个信号。
   早前「板载 PHY=YT8531SC」是把 HDMI 座型号 `HDMI_TXYT8531SH` 误读，已更正。
   工程侧已把厂商 GE demo 的 MAC/UDP RTL（35 个文件）并入 v7 工程并通过综合（`efx_map` 退出码 0、无 VERI-ERROR），
   但仍需外接 PHY 子板 + QSE 转接子卡才能上板，超出本工程硬件范围（`evidence/eth_rgmii/README.md`）。
2. **⑥ 的边界**：HTTP 服务跑在 PC 侧（读串口），不在 RISC-V 核内 —— 因为 ② 的软核没有以太网外设，且 ① 未接。
   演示效果等价：浏览器能看到实时画面缩略图、传感器数值、事件与报警状态。
3. **⑤ 的已知缺陷**：`MMT_LPCAM enter vts=0x5dc->0x1194` 与读回一致，但摄像头实际帧率没降（`camfps` 恒 59–60），
   已在 `out/lp7/report.md` 与 `evidence/v30_mot/FIX_REPORT.md` 记录，未掩盖。
4. **③ 的已知缺陷**：两人同时在画面时同时确认航迹为 0 帧（检测层连通域不稳），单目标跟踪与预测正常。

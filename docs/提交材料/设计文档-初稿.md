## 摘要（≤800 字）

本作品面向室内安全与康养看护场景，构建一台以 Ti60F225 FPGA 为核心的多模态边缘智能终端。系统以摄像头为视觉主通路：MIPI CSI-2 图像经去马赛克、白平衡与颜色校正后写入 DDR3 三缓冲帧缓存；显示通路独立读取帧缓存形成 1080p60 HDMI 画面，AI 通路在另一时钟域按 96×96 分辨率采样并送轻量神经网络推理，两条通路完全解耦（显示 59.7–60.3 fps、推理约 2.4 fps，来源：`sw/tinyml_live/技术说明-TinyML视觉子系统.md` L17/L29）。FPGA 内同时运行帧差运动检测（160×120，阈值 25、最小面积 60）、红外阵列热点检测（32×24）与温湿度采集，三路证据按 60%/25%/15% 权重在 RTL 中完成 Q8 定点融合与报警门控，报警时驱动 LED、蜂鸣器、HDMI 红框并在 OSD 上显示事件类型与置信度。

在此基础上，作品完成赛题任务 3 的七选二：② RISC-V 软核决策控制——RTL 提供每帧证据与硬实时门控，RISC-V 固件完成滑动窗口、连续确认、迟滞、事件分类与趋势预警，并把决策经新增 APB 字 14/15 回送，形成"硬实时 + 历史统计"的分层决策；⑤ 低功耗场景管理——无人约 15 秒后 RTL 将视觉处理帧率降为 1/4，RISC-V 固件同步暂停神经网络推理并每 500 ms 低频轮询，温度监测持续运行，检出运动或红外热点后立即恢复。固件另实现相机寄存器安全访问层（写白名单、写后读回、失败回滚）、自动曝光控制器与可选的 AI 输入预处理（中心裁剪、亮度归一化、分位拉伸），并支持一键编译多个对比固件。

实现结果：MERGE11 版本五步构建全部通过，`No valid pin(s) found for clock`=0、`No clocks matched`=87，XLR 41,493/60,800（68.25%）、BRAM 192/256、DSP 68/160，18 条 setup 与 19 条 hold 全部为正，最差 setup +0.177 ns、最差 hold +0.007 ns（来源：`out/evidence/v7_merge11_build.md`）。RTL 三个测试平台全部通过；固件 v16 的电脑端 3 个测试共 25 项检查全部通过（来源：`sw/tinyml_live/v16/host/logs/SUMMARY.txt`）。摄像头画面、OSD、AI 判决与历史采集数据已在早期位流上实测（p2d_ci 组合 p=19…34、均值 25.7，来源：`out/evidence/ai_load_20261022_p2dci/uart_capture.txt`）；②/⑤ 与全部改进功能的板上实测数据见【待补：MERGE11 上板验证记录】。

关键词：多模态感知；FPGA；边缘智能；软硬协同决策；低功耗

## 第一部分 作品概述

### 1.1 功能与特性（≤400 字）

系统在一台终端内完成"采集—预处理—推理—融合—报警"闭环，主要功能：

1. **实时视觉**：摄像头 1080p 画面经 HDMI 输出，显示通路与推理通路解耦；OSD 三行叠加温湿度、红外估算体温、运动面积、事件与置信度、传感器与 I2C 诊断信息。
2. **多模态感知**：SHT30 采环境温湿度（1 Hz），MLX90640 采 32×24 红外阵列（2 Hz），与视觉帧差结果做时间对齐（SHT30 允许 120 帧、红外 60 帧的最大时差，来源：`rtl/v7/mmt/v7_ts_align.v` L10-11）。
3. **入侵检测与报警**：非授权时段（RD 夜间 22:00–6:00，可按键切换）+ 视觉运动 + 红外热点三重门控，触发 LED 闪烁、蜂鸣器、HDMI 红框与 OSD 事件显示；报警保持约 1.8 s（`v7_mmt_core.v` L15，HOLD_BITS=28 @148.5 MHz）。
4. **分层决策（②）**：RTL 给出每帧证据，RISC-V 固件做窗口统计与迟滞决策，默认不改变 RTL 行为，可一键旁路。
5. **低功耗管理（⑤）**：无人时视觉处理抽稀、推理暂停、温度监测保持；检出人体自动恢复。
6. **可配置改进**：相机寄存器安全读写、自动曝光、AI 输入裁剪/归一化/拉伸等可选功能，默认关闭以保证行为稳定。

### 1.2 应用领域（≤400 字）

- **室内安防**：非授权时段人员闯入检测，适合机房、仓库、独居老人住所等场景；本地完成全部推理，画面不出户，隐私风险低。
- **智慧康养**：结合红外热点与环境温湿度，可在不接触的前提下观察人体存在与体温趋势；当前实现范围是"入侵检测 + 人体证据"，跌倒识别、姿态分类属于可扩展方向。
- **边缘视觉终端**：双通路架构可移植到工业检测、门禁、零售客流统计等需要"实时显示 + 低成本 AI"的场合。
- **教学与二次开发**：RTL 模块、RISC-V 固件、电脑端测试与构建脚本齐全，可作为 FPGA 软硬协同与 TinyML 部署的实验平台。

本作品的定位是**边缘侧的实时多模态感知终端**：把需要硬实时的运动/温度证据放在 FPGA 逻辑中，把需要历史上下文与可调参数的决策放在 RISC-V 中，兼顾实时性、可解释性与可迭代性。

### 1.3 主要技术特点（≤400 字）

1. **双通路解耦**：显示通路按像素时钟实时读帧缓存，AI 通路按整帧节拍采样，推理慢不拖累画面（显示 59.7–60.3 fps、推理 2.4 fps，来源：技术说明 L29）。
2. **分区帧缓存**：DDR3 划分 3 个 bank 轮转，避免读写撕裂；帧缓冲写通路的握手计数器暴露到 APB，可在线诊断写通路是否工作（`rtl/v7/mmt/` 与 `ti60f225_oob_top.v` APB 字 1–8）。
3. **定点化融合**：融合得分用 `score=(v×154+t×64+e×38)>>8` 的 Q8 权重实现，无除法器（`rtl/v7/mmt/mmt_fusion_vote.v` L19-23、L122）；环境置信度用线性分段近似 2.56。
4. **软硬协同分层决策**：RTL 负责每帧硬实时门控，RISC-V 负责 8 样本滑动窗口、连续 3 帧确认、140/70 迟滞、趋势斜率预警（`sw/tinyml_live/main_live16.cc` 宏 DEC_*）。
5. **带保护的寄存器访问**：相机参数写入前读旧值、写后读回、失败回滚，并限制白名单地址，避免把相机置于半配置状态（`sw/tinyml_live/v16/cam_ctrl_core.h`）。
6. **可观测性**：OSD 诊断字段 + 串口 `MMT_OSD/MMT_DEC/MMT_LP/MMT_AE/MMT_LPCAM` 日志，任何结论都可追溯到原始记录。

### 1.5 主要创新点（≤200 字）

1. **显示/AI 双通路 + 三缓冲帧缓存**：`rtl/frame_buffer_V4/frame_buffer.v` 与 `v7_mmt_core.v` 采样通路分离，实现画面 60 fps 与推理 2.4 fps 并行。

## 第二部分 系统组成及功能说明

### 2.1 整体介绍

系统以 Ti60F225 为核心，FPGA 逻辑承担像素处理、运动检测、传感器采集、融合报警与显示输出，RISC-V 软核承担 AI 推理调度与 ②/⑤ 决策，电脑端承担固件加载、变体构建与算法验证。

```
                 ┌──────────────────────── FPGA（Ti60F225）────────────────────────┐
摄像头 SC431HAI ─►│ MIPI CSI-2 RX → 去马赛克/白平衡 → 帧缓冲写 → DDR3 三缓冲帧缓存 │─► HDMI 1080p60
                 │                     │                                ▲          │
                 │                     └─► 视觉降采样(160×120) → 帧差 ──┤          │
SHT30 ─I2C─┐     │  SHT30/MLX90640 驱动 → 时间对齐 → 融合决策(Q8) → 报警门控 → OSD │
MLX90640 ──┴─────►│  I2C 分时复用        （红外 32×24 热点/体温）      │  文字/热力图/红框 │
                 │                                                       ▼          │
                 │  RISC-V 软核 + TinyML 加速器：采样→推理→②决策  ◄─ APB 字11-15 ─┤
                 │  低功耗管理 ⑤、相机寄存器安全访问（APB 字16-18）               │
                 └─────────────────────────────────────────────────────────────────┘
                                  ▲ UART/加载器（板载 FT4232HL）
                                  └── 电脑：固件加载、变体构建、电脑端测试
```

各模块关系：摄像头像素流是唯一主时间基准；显示通路与 AI 通路共享帧缓存但独立读取；传感器以周期任务运行，帧差结果与传感器数据按"最近时间匹配"对齐后进入融合；融合结果一路驱动本地报警与 OSD，另一路以 APB 只读证据形式提供给 RISC-V；RISC-V 的决策与低功耗状态经 APB 写回，参与最终报警门控与相机配置。

### 2.2 硬件系统介绍

#### 2.2.1 硬件整体

- 主控板：Ti60F225I3-V4 开发板，单根 Type-C 线完成供电、JTAG 下载与串口（板载 FT4232HL，115200 8N1）。
- 输入：SC431HAI 摄像头模组（2568×1448 阵列、RAW、MIPI CSI-2 1/2/4-lane、I2C 地址 0x30），经板上 22-pin FPC 座接入。
- 传感：SHT30 温湿度（I2C 0x44）与 MLX90640 红外阵列（I2C 0x33，32×24、FOV 55°×35°），共用一条 I2C 总线。
- 输出：标准 HDMI Type-A，1080p60；板载 LED×2、按键×2；蜂鸣器模块可外接（GPIOR_13）。
- DDR3：板上 DDR3 颗粒由 FPGA 软核控制器驱动，用作三缓冲帧缓存。

#### 2.2.2 机械设计

本作品**无定制机械结构**。整机为板卡平放于桌面，摄像头模组通过 FPC 插入板上 sensor 座，传感器模块经杜邦线接到 J7 扩展排针，HDMI 线连接显示器，Type-C 线连接电脑/电源。装配与走线照片位置：【待补：整机装配照片】。

#### 2.2.3 电路各模块介绍

| 模块 | 连接/引脚 | 说明 |
|---|---|---|
| 摄像头接入 | MIPI CSI-2 4-lane，FPC 22-pin；摄像头 I2C：SCL=GPIOR_20、SDA=GPIOR_18 | 摄像头 I2C 由开机 ROM 序列完成初始化，运行期可由固件经 APB 字 16/17/18 读写（白名单保护） |

### 2.3 软件系统介绍

#### 2.3.1 软件整体

软件分三层：**RTL**（像素链路、帧缓存、传感器驱动、融合报警、OSD、②⑤接口）、**RISC-V 固件**（AI 采样与推理、② 历史决策、⑤ 低功耗、自动曝光、相机寄存器访问、日志）、**电脑端工具**（固件加载器、变体构建脚本、电脑端算法验证）。三者通过 APB 寄存器、UART 与固件镜像文件交互。

|---|---|---|
| 采样与预处理 | 帧缓存字节 → 96×96 int8 | 行距 1920 B、1 B/像素；3×3 点盒式（每点 2×2 均值）；可选中心裁剪（1080/1620 宽）、亮度归一化（目标 115、增益 0.5–3.0）、1%/99% 分位拉伸 |
| AI 推理 | 96×96 张量 → p、a | 调用 TinyML 加速器，单次 430–470 ms；写 APB 字 9/10 供 RTL 使用 |
| ② 历史决策 | 融合得分/运动/红外 → 报警请求 | 8 样本滑动窗口均值、斜率=|最近4−最早4|/4、连续 3 帧确认、140/70 迟滞、事件分类（入侵/趋势预警）；结果写字 14/15 |
| ⑤ 低功耗 | 字13 bit17 → 暂停推理 | 低功耗时每 500 ms 轮询一次证据；暂停推理并清 AI 寄存器，退出后恢复 |
| 自动曝光 | 输入图均值 → 曝光/增益码 | 目标 [95,125]，每 8 帧评估，死区 3、连续 2 次动作、±12% 步进，先曝光后增益，上下限取自启动读值（默认只增不减） |
| 相机安全访问 | APB 字16/17/18 | 10 ms 超时；写白名单 8 个地址；写后读回，不一致回滚 |
| 日志 | UART | `MMT_OSD/MMT_DEC/MMT_LP/MMT_AE/MMT_LPCAM/MMT_CAM/MMT_PP/MMT_CFG` |

**电脑端工具**：`load_and_run.py`（UART 加载固件到 DDR）、`build_tinyml_firmware.py`（编译 RISC-V 固件）、`build_variants.py`（按宏生成并编译 6 个对比固件）、`v16/host/run_tests.ps1`（预处理/自动曝光/寄存器层三组电脑端测试）。

**关键算法公式**

- 融合：`score = (v×154 + t×64 + e×38) >> 8`，`v,t,e ∈ [0,255]`；环境置信度在 10–35 ℃、20–80 %RH 内为 256，否则按 `256−(d×41)>>4` 线性降低（`mmt_fusion_vote.v` L19-23、L76）。
- 视觉概率：`vision_prob = min(255, area×13/64)`（`v7_mmt_core.v` L82）。
- 帧差背景：`bg += (pix−bg) >> 5`（有符号补偿），掩码条件 `|pix−bg| > threshold`（`v7_frame_diff.v` L31-35）。
- ② 决策：`mean_k = (1/N)Σscore`，`slope = (Σ最近4 − Σ最早4)/4`，`alarm` 由 `mean≥140` 连续 3 次置位、`mean≤70` 复位；趋势预警 `slope≥10` 且 `mean≥60`。
- ⑤ 进入条件：`idle ≥ 900 帧` 且无红外热点；动作：视觉处理 `proc_vs` 每 4 帧取 1 帧（`v7_pwr_ctl.v`）。
- 自动曝光：`g = clamp(round(115×100/mean), 50, 300)`；步进 `±12%`，上下限 `[init, min(4×init,0xFFFF)]`（增益上限 `2×init`）。

## 第四部分 总结

### 4.1 可扩展之处（≤300 字）

1. **算法层**：当前 ② 的历史分析仅基于融合得分与运动/红外摘要；RTL 可增加目标质心/轨迹寄存器，固件即可做多目标跟踪与轨迹预测；跌倒/姿态识别可在现有 96×96 通路上换模型或加二级分类器。
2. **硬件层**：可把 96×96 采样与预处理搬入 RTL 流水线，减轻固件 DDR 读压力；相机 VTS 降帧在确认寄存器行为后可默认启用，进一步降低功耗。
3. **系统层**：增加 Wi-Fi/以太网事件上报、Web 查看、语音播报（赛题任务 3 的其他选项）；把 APB 证据表扩展到更多传感器。
4. **可靠性**：给相机写操作增加周期自检与配置快照恢复，长时间运行更稳。

### 4.2 心得体会（≤1000 字）

这套系统的研发过程，几乎每一步都由"证据—假设—验证"推动，而不是靠直觉堆功能。

**几何采样错误是第一个转折点。** 早期版本把帧缓存按 4 字节像素、960 字行宽来理解，采出来的 96×96 图水平方向重复、下半部分是黑的。我们先用"两帧校验和是否变化"确认帧在更新，再把采样地址打印到串口逐行比对，才发现真实格式是行距 1920 B、1 B/像素的原始 Bayer；按真实几何重写采样后，AI 输入第一次变成完整画面。这件事让我们养成了"先测量格式、再写代码"的习惯，也留下了 `MMT_IMGSTAT/MMT_IMG` 这套可回放的输入快照。

**预处理对 AI 输入的影响比模型本身更大。** 我们用同一帧做受控实验，发现点采样会把人的竖直结构切碎，判决逐帧乱跳（约 40% 帧随机判"有人"）；改成区块平均后连续 34 帧稳定，而且推理还快了一点（430 vs 435 ms）。另一侧是归一化：早期错误地做"减 128"，整幅图亮度偏移一半，分类恒为空；后来按位重解释才恢复。这些实验让我们把"输入分布"（均值 98–166、标准差 66–67、无偏置）写进了技术说明，而不是只盯模型分数。

**时序与资源收敛靠的是可解释的取舍。** 合并工程里跨时钟域路径带来 −0.733 ns 违例，我们先试了 clock-group，发现会把 `vid_clk_dvi2→hdmi_tx_slow_clk` 这类真实同步路径一起排除，随后改为单向 `set_false_path`，违例消失且同步路径回到时序表。资源一侧，MERGE5/6 曾因 gamma 查找表被映射成逻辑而超出容量，换成 BRAM 后 XLR 降到 4.1 万级；此后每版都把 `inst_gamma_correction` 的综合波动单独归因，避免误判成"新逻辑太胖"。

**CDC 是另一个反复出现的问题。** 多比特状态跨域不能按位打拍，我们采用"帧结束翻转单比特标志、软核只在标志变化后读数据"的方案（`alg_frame_tgl`）；② 决策接口则用"每帧快照 + toggle 握手"，并在时序签核中看到新增的 hdmi→core 关系只有 +0.007 ns 余量——虽然为正，仍如实记录、不掩盖。

**电脑端验证显著提升了效率。** 没有板子的时候，我们把预处理算法抽成纯 C 头文件，用合成帧做逐像素回归和裁剪落点验证；把自动曝光控制器抽出来，用带噪声与延迟的相机模型闭环跑收敛与振荡测试；把寄存器访问层用 mock 注入"写丢失/回滚失败"验证保护逻辑。这些测试在主机上几秒跑完，上板前就能排除大部分低级错误。

**调试工具本身就是设计的一部分。** 写通路握手计数、相机上游探针、I2C 地址扫描、OSD 诊断字段、`MMT_*` 日志，都是被问题逼出来的；它们让"画面不动/传感器不应答/报警不触发"这类问题从猜测变成读数。回头看，最省时间的做法不是更快地改代码，而是更早地把内部状态变成可读的数字。

# 如何运行这个工程（从零到板子上跑起来）

> 适用：Ti60F225I3 DemoBoard（Ti60F225）· Efinity **2026.1.132** · 仓库 <https://github.com/MakiseAohara/FPGA_104>
> 本文面向"刚拿到仓库的人"。**按顺序做**，每步都有判据；判据不对就停在那一步排查，不要往下走。
>
> ⚠️ 仓库里**只有我们自研的代码**（`rtl/mmt/`、`sw/`、`sim/`、`constr/`、`tools/`、`mmt.xml`、`mmt.peri.xml`）。
> 厂商 IP 与厂商 demo RTL **不在仓库里**，需要从厂商工程/官方 demo 获取后放到对应路径；
> 我们**对厂商源码做过的改动**列在 README §10，换机器后必须照此重新打上。

## 0. 你需要准备什么

| 类别 | 需要 | 说明 |
|---|---|---|
| 工具 | **Efinity 2026.1**（装在 `D:\Efinity\2026.1`）| 综合/布局布线/生成位流/烧录 |
| 工具 | **RISC-V 工具链** `xpack-riscv-none-elf-gcc`（`D:\riscv\xpack-riscv-none-elf-gcc-15.2.0-1`）| 编译固件 |
| 工具 | **iverilog**（`D:\iverilog\Library\bin`）| 跑仿真 |
| 硬件 | 板子 + USB 线 + HDMI 屏 + 摄像头（SC431HAI，接 **J4**，屏接 **J5**）| |
| 驱动 | **FTDI 驱动必须版本统一**（`ftdibus`/`ftdiport` 同为 2.12.36.4）| ⚠️ 版本不一致会 **BSOD `0x000000FC`**，见 §5 |

## 1. 编译固件（**两步，第二步最容易漏**）

```powershell
cd D:\FPGA\mmt\sw
powershell -File .\build_sw.ps1          # 编译 → build\mmt_fw.bin / .elf / .map
powershell -File .\hex2soc.ps1 -Install  # ★ 把固件装进 SoC 的片内 RAM 初始化（4 个 symbol 文件）
```

**为什么第二步不能漏**：固件不是从 flash 读的，而是**综合时通过 `$readmemb` 烧进 SoC 的片内 RAM**。
不跑 `hex2soc.ps1 -Install`，**位流里带的还是上一版固件**（这个坑我们踩过）。

**判据**：`build_sw.ps1` 打印 text/bin 大小且 exit 0；`hex2soc.ps1` 打印 `round-trip verify : OK`
并显示 `installed into : ...\ip\sapphire_soc`。

## 2. 生成位流

```powershell
cd "D:\FPGA\易灵思\工作区\06_Efinity验证"
powershell -File .\run_full_flow.ps1      # 综合 → 引脚 → 清理 → 布局布线（约 10~15 分钟）
```

出来后**必须**再生成烧录文件（`run_full_flow.ps1` 只到 `work_pnr\mmt.lbf`）：

```powershell
$efi = "D:/Efinity/2026.1"
$env:EFINITY_HOME=$efi; $env:EFINITY_USER_DIR="C:/Users/<你>/.efinity"
$env:EFINITY_USER_DIR_INI="$env:LOCALAPPDATA\efinity\user_dir.ini"
$env:EFXPT_HOME="$efi/pt"; $env:EFXPGM_HOME="$efi/pgm"; $env:EFXDBG_HOME="$efi/debugger"; $env:EFXIPM_HOME="$efi/ipm"
$env:PYTHONHOME="$efi/python311"; $env:PATH="$efi/python311/bin;$efi/bin;$efi/scripts;"+$env:PATH
& "$efi/bin/efx_pgm.exe" --project-xml "D:\FPGA\mmt\mmt.xml" `
  --source "D:\FPGA\mmt\work_pnr\mmt.lbf" --dest "D:\FPGA\mmt\out\mmt.hex" `
  --family Titanium --device Ti60F225 --mode active --width 1
```

**判据**：`out\mmt.hex` 与 `out\mmt.bit` 都生成（约 2.9 MB），且 **`.bit` 的时间戳晚于所有源码改动**。

**本次构建的参考数字**（用于对照"有没有跑歪"）：

| 项 | 值 |
|---|---|
| XLRs | ~44,950 / 60,800（约 74%）|
| Memory Blocks | 235 / 256（91.8%，接近上限）|
| DSP Blocks | 24 / 160 |
| 未分配引脚 | **0**（`none -- every pin is constrained`）|
| 时序 | 408 条 slack，**最小 +0.02 ns，负 slack 0** |
| 写通路守卫 | `check_wr_path.ps1` 4 项 PASS |

> ⚠️ **厂商 `frame_buffer` 的写 FSM 会被 Efinity 2026.1 静默折成常量**（`optimized to 0`、写 FIFO 的 13 块 BRAM 消失）。
> 我们靠给 4 个寄存器加 `(* preserve, syn_keep=1 *)` 绕过（见 README §10）。**每次编译后跑工作区里的 `06_Efinity验证\check_wr_path.ps1` 确认没被折**（该脚本在我们内部工作目录，不在仓库里）。

## 3. 跑仿真（可选，但强烈建议在改 RTL 前跑）

```powershell
$env:PATH = "D:\iverilog\Library\bin;D:\iverilog\Library\mingw-w64\bin;" + $env:PATH
cd D:\FPGA\mmt\sim\frame_wr;      powershell -File .\run_frame_wr.ps1      # 帧缓冲写通路功能
cd D:\FPGA\mmt\sim\frame_wr;      powershell -File .\run_frame_addr.ps1    # 写地址范围（防越界）
cd D:\FPGA\mmt\sim\test_pattern;  powershell -File .\run_test_pattern.ps1  # 测试图案 → 写/读
cd D:\FPGA\mmt\sim\debayer;       powershell -File .\run_debayer.ps1       # Bayer 相位 / 显示透传
cd D:\FPGA\mmt\sim\axi_ic;        powershell -File .\run_axi_ic.ps1        # AXI 互联仲裁与 ID
# 寄存器/探针单元测试（直接编）
iverilog -g2012 -o %TEMP%\t.vvp rtl\mmt\common\mmt_sync2.v rtl\mmt\mmt_cam_probe.v `
         rtl\mmt\soc\mmt_soc_regs.v sw\test\tb_mmt_cam_probe.v ; vvp %TEMP%\t.vvp
```

**注意**：iverilog 对**越界常量索引**是宽松的（例如对 12 位信号取 `[15:0]` 它不报错，**Efinity 会报 `VERI-1216`**）
⇒ **仿真通过 ≠ 能综合**，改完 RTL 一定要跑一次真编译。

## 4. 烧到板子上

### 4.1 前置条件（四条缺一不可）

1. **FTDI 驱动版本统一**（见 §5）
2. `$env:EFX_HIFTDI_ENABLE = "1"` —— 否则 Efinity 只认 pyftdi(libusb)，报 `No backend available` / `No Board Profile Selected`
3. **`efx_dbg\jcf.py` 补丁** —— 否则 D2XX 后端下任何操作都在 TAP 检测处抛
   `TypeError: JtagEngine.configure() takes 2 positional arguments but 3 were given`
   （补丁内容见 README §5.2.3）
4. 指定板级 profile：`-b "Generic Board Profile Using FT4232H"`

### 4.2 烧录（JTAG → 片内 SRAM，掉电即失）

```powershell
$efi = "D:\Efinity\2026.1"
# …环境变量同 §2…
$env:EFX_HIFTDI_ENABLE = "1"
& "$efi\bin\python3.bat" "$efi\pgm\bin\efx_pgm\ftdi_program.py" `
  "D:\FPGA\mmt\out\mmt.bit" -m jtag -b "Generic Board Profile Using FT4232H"
```

**成功判据**：
```
Connecting to JTAG_TAP: efx_ti
jtag programming started!
Device ID read from JTAG: 0x10660A79          ← Ti60F225
... finished with JTAG programming
```

> ⚠️ **必须是 `.bit`**（传 `.hex` 会报 `Incompatible file extension`）。整个流程约 20 秒，**别中途拔线**。
> **flash 持久化烧录目前未打通**（`-m active` / `-m jtag_bridge` 在 D2XX 后端都失败），所以每次上电都要 JTAG 烧一次。

## 5. 驱动出问题？先看这里（我们的血泪记录）

**症状：一访问 FTDI 就 BSOD `0x000000FC`（ATTEMPTED_EXECUTE_OF_NOEXECUTE_MEMORY）**
原因：Windows 给 FT4232H 的**总线**和**串口**通道装了**不同年代**的驱动（例：`ftdibus` 2024 版 vs `ftdiport` 2017 版）。

```powershell
pnputil /delete-driver oem114.inf /uninstall      # 删掉旧包（编号按你机器实际）
pnputil /delete-driver oem118.inf /uninstall
pnputil /delete-driver oem119.inf /uninstall
pnputil /add-driver D:\FTDI\ftdibus.inf  /install  # FTDI 官网 CDM-v2.12.36.4
pnputil /add-driver D:\FTDI\ftdiport.inf /install
```
**判据**：设备管理器里 `USB Serial Converter A/B/C/D` 与 `USB Serial Port` 的驱动版本**都是 2.12.36.4**。
（修好后我们连续烧录十几次，再无蓝屏。）

## 6. 看串口（不带屏幕也能知道设计活没活）

- **端口 `COM19`，115200 8N1**（实测 COM17/18/20 无数据）
- 正常会持续打印（每行含义见 §7）：

```
T=0.0C RH=0.0% IR=0.0C score=0.0
ALM=0 AUTH=0 EVT=0 ST=0x00000000 thr=154 hr=0 auth22-6
[WR] AW=0(d=0) W=0(d=0) st=0x00 FRM=367(d=11) amax=0x00000000(d=0x00000000) asmp=0 az=NOIMG [FS] raw=0x00000000 ... [VW] vis=0x00
[CAM] SCL=..(d=..) CK=..(d=..) PCLK=..(d=..) DE=..(d=..) HS=..(d=..) VS=..(d=..) st=0x.... wc=..(d=..) link=0x........
```

**烧完第一件事**：确认 `[CAM]` 行里能看到 **`PROBE_ID = 0x4D4D5450`**、且 **`nk != SCL`**、**`rh != CK`**
（三条同时成立才说明"新位流 + 新固件"都生效；否则任何字段都别信）。

## 7. 寄存器映射（SoC 侧，基址 `0xF8100000`）

| 地址 | 属性 | 含义 |
|---|---|---|
| `0x00` | R | `MMT_ID`（`0x4D4D5401`）= "位流活着" |
| `0x24` | R | 运动标志/帧翻转 |
| `0x28` | R | 融合输出（**注意**：实测被截断，`[31:24]` 只有 1 位；完整视觉字节看 `0x78`）|
| `0x2C` | R | 报警状态（bit0 报警、bit1 授权窗口；**读一次即清**）|
| `0x6C`/`0x70` | R | 帧缓冲写地址/写数据**握手累计数** |
| `0x74` | R | 写通路电平/粘滞位 |
| `0x78` | R | 完整视觉字节 `[31:24]` |
| `0x7C` | R | 视频帧翻转次数（**显示读通路**在跑的标志，**不是摄像头帧**）|
| `0x80..0xBC` | R | **摄像头上游探针**（I2C SCL/ACK/NACK、MIPI 字节/像素时钟、`de/hs/vs`、CSI 状态、在位流魔数）|
| `0xC8` | **W/R** | **测试图案**：`[0]`=使能（0=摄像头，1=图案）、`[2:1]`=模式（0 彩条 1 红 2 绿 3 蓝）|
| `0xCC`/`0xD0`/`0xD4` | R | 每帧行数 / 每行 `de` 拍数 / 帧计数 |
| `0xD8`/`0xDC` | R | 帧缓冲**最大写地址** / 采样数与越界粘滞位 |
| `0xE0+` | — | 预留（TinyML 遥测）|

## 8. 板子上的操作顺序（建议照做）

1. 烧位流 → 看串口有没有 §6 的四行 + `PROBE_ID`
2. **不插摄像头**，先做 **M0 自证**：写 `0xF81000C8 = 1`（或 2/3 试纯色）
   - **预期**：HDMI 出 8 色彩条 + 移动方块（**红是红、蓝是蓝**）；`[WR] AW/W` 开始增长；`[AMAX] az=OK`
   - 失败：没画面但 `AW/W` 在涨 ⇒ 查读通路/HDMI；`AW/W` 不涨 ⇒ 读回 `0xC8` 确认写入、看 `0xD4` 帧计数
3. **插摄像头前的硬件检查** ⚠️：**J2/J3 跳线 = 1.2V**（MIPI bank 电压，选错会烧 IO）；FPC 插到底并压紧；**断电插拔**
4. 写 `0xF81000C8 = 0` 切回摄像头，按顺序读 `[CAM]`：
   `PROBE_ID` → 复位/PLL 状态 → **SCL 总数与 ACK 数** → **HS_ENA** → `word_count/datatype/vc` → `de/vs`

## 9. 判读避坑（**这几条能把人坑很久**）

| 现象 | 真相 |
|---|---|
| `PCLK` 一直在涨 | **正常且无意义**：它是 PLL 输出，与摄像头无关。要看 **`CK/PCLK` 比值** |
| `SCL(d=0)` | **正常**：配置序列发完就不动了。要看**总数** |
| `wc(d=0)` | **正常**：它数的是 `word_count` **值变化次数**，不是包数 |
| `FRM` 在涨 | **不代表摄像头帧**：它来自显示读通路（读 DDR 旧数据）|
| `fifo_rd_empty` | **不能当证据**（字节时钟域的 2FF 快照）|
| `amax=0` | **不等于"没越界"**：没出图时它就是 0。必须联合 `asmp`/`asck` 看 |
| `d=` 增量 | **无固定时间基准**（软件空循环+串口打印），只能比"零/非零"与数量级 |

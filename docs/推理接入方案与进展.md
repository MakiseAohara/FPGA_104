## 0. 一页结论

1. **做了什么**
   - 厂商驱动的**最小可用集**查清并给了 `文件:行`（§2）；关键发现：**算子在预编译库
     `common\tinyml_lib.a` 里**（C++，非源码）。
   - 我们的固件驱动 **`sw\mmt_tinyml.h` + `sw\mmt_tinyml.c`**（新增）：
     **张量布局**（全落 R7、128B 对齐）+ **地址自检 fail-closed** + **D-cache 刷新** +
     **只读探测加速器**（默认关）+ 一行 `[AI]` 遥测。
   - **自定义指令编码实测核对通过**（`sw\test\run_ci_encode_test.ps1`，**16 PASS / 0 FAIL**）：
     我们宏编出来的读 UUID 指令 = `0x00a5150b`，**与厂商库 `tinyml_accel_get_uuid()`
     的指令逐字节相同** ✓
   - `sw\build_sw.ps1` exit 0；`mmt_fw.bin` **6752 字节**（RAM 9493 B + 1K 栈 ≪ 32KB）。

2. **没做什么（**明确**）**：**没有真的发过任何"参数写 + 触发"命令**，也**没有算过一次卷积**。
   原因是**参数寄存器的语义无法确认**（§4.4）：`func3=0..7` 与 20 多个 conv 参数/张量指针的
   对应关系只存在于加密 IP / 预编译库里，**猜错就会让加速器按错误地址访存**（而加速器/互联/DDR3
   **都没有越界保护**）。所以本轮的默认路径里，这一类指令**一条都不发**。

3. **怎么用（安全档，默认）**：上板只看一行
   ```
   [AI] layout=OK err=0x00000000 weights@0x03000000+300568 input@0x03049680+9216 output@0x0304BA80+2 arena@0x0304BB00+1048576 probe=off
   ```
   `layout=OK` ⇒ 张量全在 R7 内且对齐正确；`probe=off` ⇒ **没发任何自定义指令**（不可能卡住）。

4. **还差什么（要真跑推理，按顺序）**：① 参数寄存器语义（拿厂商 TinyML 用户手册的寄存器表，
   或链 `tinyml_lib.a`）；② `init_accel()` 的配置写入；③ 完成信号（PLIC 中断或轮询状态）；
   ④ 权重搬进 R7；⑤ 打开开关前先在板上确认加速器已接线。详见 §8。

## 3. 自定义指令协议（**实测推导**）

### 3.1 字段映射（证据链）

```
RISC-V R 型：  [31:25]funct7 | [24:20]rs2 | [19:15]rs1 | [14:12]funct3 | [11:7]rd | [6:0]opcode
SoC 侧：        ci_function_id[9:0]  ⇐   func3(3) + funct7(7)      （mmt_top.v:418 是 10 位）
                ci_inputs_0[31:0]    ⇐   rs1 的**值**
                ci_inputs_1[31:0]    ⇐   rs2 的**值**
                ci_outputs_0[31:0]   ⇒   rd
                cmd_valid/cmd_ready/rsp_valid/rsp_ready = 握手
```
（`opcode_R(opcode, func3, func7, rs1, rs2)` 的参数顺序见 `riscv.h:350-359` 的宏体；
`function_id` 的拼接顺序 **{func7,func3} 还是 {func3,func7}【无法确认】** —— 见 §4.4。
好消息是：**只要发同一条指令，就不受这个顺序影响**。）

### 3.2 从厂商库里"抠"出来的指令（**实测**，反汇编 `tinyml_lib.a`）

| 厂商函数 | 指令 | 解码 | 含义 |
|---|---|---|---|
| `tinyml_accel_get_uuid()` | `.insn 4, 0x00a5150b` | op=0x0B f3=**1** f7=**0** rd=a0 rs1=a0(=0) rs2=a0(=0) | **读配置 idx 0 = UUID** |
| `tinyml_accel_get_accel_count()` | `.insn 4, 0x00e7928b` | op=0x0B f3=**1** f7=**0** rd=t0 rs1=a5(**=1**) rs2=a4(=0) | **读配置 idx 1 = 加速器个数** |
| `conv_drv` 里成族的指令 | 例 `.insn 0x0505870b` / `0x046a0a0b` … | f3=0..7、f7=2 与 3 | **参数写 bank**（19~2 条），但有 ~20 个参数 ⇒ 应是"bank(f7) + 索引(f3)"，**语义未确认** |
| cache 相关 | f7=12/13、f3=0..7 | — | cache 配置/维护（**语义未确认**） |

⇒ 结论：**func3=1 / func7=0 = "读配置"，rs1 = 配置索引**（这是本轮唯一敢用的族）。

### 3.3 加速器配置读出的索引表（**推断**，来自 `sys.h:42-53` 的函数名顺序）

| rs1 | 函数名 | 我们固件里 |
|---|---|---|
| 0 | `tinyml_accel_get_uuid()` | `MMT_CI_CFG_READ(0)` |
| 1 | `tinyml_accel_get_accel_count()` | `MMT_CI_CFG_READ(1)` |
| 2.. | `get_axi_dw` / `get_cache_en` / `get_cache_depth` / `get_conv_depthw_mode` / … | 未用（需要时按同名顺序试） |

⚠️ 这张表的**顺序是推断**（依据是 `sys.h` 里函数声明的顺序），**每个索引的含义需要上板核对**。

### 3.4 我们的实现（**实测：编出来的指令与厂商逐字节相同**）

### 4.1 文件与接口

| 文件 | 内容 |
|---|---|
| `sw\mmt_tinyml.h` | 张量区常量、指令宏、张量描述结构、API 声明（含**安全约定**） |
| `sw\mmt_tinyml.c` | `mmt_tinyml_layout_init()` / `mmt_tinyml_check()` / `mmt_tinyml_check_str()` / `mmt_tinyml_probe()` / `mmt_tinyml_selftest()` / `mmt_tinyml_flush_dcache()` |

| `sw\test\ci_encode_test.c` + `run_ci_encode_test.ps1` | ★ 命令编码自测（不烧板） |

### 4.2 ★ 工具链差异（**实测的坑**）

厂商 `riscv.h:350-359` 的写法是
`asm(".word ((0x0B) | (regnum_%0 << 7) | (regnum_%1 << 15) | …)")`。
**[实测] 我们这支 xpack GCC 15.2 的 GAS 编不过**：
```
Error: invalid operands (*UND* and *ABS* sections) for `<<'
```
改用 GAS 的 `.insn r` 形式并把寄存器交给 `%0/%1/%2` 代换（实测可用，且与厂商同字段）：
```c
asm volatile(".insn r 0x0B, 1, 0, %0, %1, %2" : "=r"(v) : "r"(rs1), "r"(rs2));
```
（`.insn r` 的 rd/rs1/rs2 位置也接受**寄存器名**，固定寄存器版见 `ci_encode_test.c` 的 `CI_FIXED`。）

### 4.3 ★ 张量布局表（R7）

规则：从 `0x03000000` 起，逐个 `align_up(,128)`；尺寸来自模型/demo（§2.1）。
**这张表就是固件运行时会打印的内容**（`[AI] ...`），文档与串口必须一致。

| # | 张量 | 地址 | 大小(B) | 对齐 | 依据 |
|---|---|---|---|---|---|
| 0 | `weights`（模型常量） | **`0x03000000`** | 300,568 (`0x49618`) | 128 | `sw\ddr\weights\mobilenetv1_person_detect_model_data.bin` 实测大小 |
| 1 | `input` | **`0x03049680`** | 9,216 (`0x2400`) | 128 | 96×96×1 int8（`model_settings.h:24-28`） |
| 2 | `output` | **`0x0304BA80`** | 2 | 128 | 2 类（`model_settings.h:30-32`） |
| 3 | `arena`（中间激活） | **`0x0304BB00`** | 1,048,576（暂定） | 128 | 剩余空间充足；实测需求见 §8 |
| — | **本版张量区总占用** | `0x03000000 – 0x0314BB00` | ≈1.29 MB | — | `0x0314BB00 < 0x04000000` ✓（R7 还剩 ~14.8MB） |

（`weights` 的尾部 `0x03049618` 到 `0x03049680` 之间 104 B 是对齐填充，无害。）

### 4.4 ★ 地址自检（fail-closed）

`mmt_tinyml_check()` 返回**错误位掩码**（0 = 通过）：

| 位 | 常量 | 判什么 |
|---|---|---|
| 0 | `E_BASE_LOW` | `base < 0x03000000` |
| 1 | `E_END_HIGH` | `base+size > 0x04000000`（越出 R7 上界） |
| 2 | `E_ALIGN` | 未满足 8B 硬下限 / 自身 align |
| 3 | `E_ZERO_SIZE` | 尺寸为 0 |
| 4 | `E_OVERLAP` | 两张量相交 |
| 5 | `E_VIDEO` | 与 R5 视频帧缓存 `[0x02000000,0x02BDDE00)` 相交 |
| 6 | `E_MODEL_SIZE` | 权重尺寸 ≠ 300,568（防"以为装了其实没装"） |
| 7 | `E_WRAP` | `base+size` 32 位回绕 |

**约定**：任何"发命令"的路径都必须先 `if (mmt_tinyml_check() != 0) return ERR;`（**拒绝执行**）。
这条是本任务的重点：加速器/互联/DDR3 都没有越界保护，越界会静默写坏视频/TinyML 别的区
（今天的帧步长 bug 就是这么坏的 1.8MB）。

### 4.5 D-cache 一致性

`mmt_tinyml_flush_dcache()` = `.word(0x0000500F)` + `fence rw, rw`。
【实测（task-7）】本 SoC 的 DDR 通路是 **write-through（无 dirty 位）**，所以刷一条即可；
**调用时机**：写输入张量后、发命令前（厂商文档要求）。

### 4.6 开关（默认全部"安全档"）

| 宏 | 默认 | 含义 |
|---|---|---|
| `MMT_TINYML_PROBE_EN` | **0** | 1 = 上板**发自定义指令**读 UUID/个数（**可能阻塞**，见 §8 第 5 条） |
| `MMT_TINYML_ISSUE_EN` | **0** | 1 = 允许发"参数写+触发"（**语义未确认，默认禁止**） |

⇒ 默认固件**一条自定义指令都不发**，不可能卡住板子 ✓（符合 Lead 的"任何时刻可编可跑"要求）。

## 7. 上板步骤与判据

1. **重编位流**（Lead）；固件已在位流里（当前 6752 字节版）。
2. 上电看串口，**第一眼**：
   - 既有遥测行照旧（`T=/ALM=/[WR]/[AMAX]/[CAM]/[FS]/[VW]`）✓
   - 新增一行：`[AI] layout=OK err=0x00000000 weights@0x03000000+300568 input@0x03049680+9216 output@0x0304BA80+2 arena@0x0304BB00+1048576 probe=off`
   - **判据**：`layout=OK` 且 `err=0x00000000` ⇒ 张量地址安全；
     若 `err≠0`，`check_str()` 会直接打出 `ERR:out-of-R7` / `ERR:align` 等**原因**
     ⇒ **先修地址表，别去发命令**。
3. **（可选，谨慎）确认真机接线**：把 `sw\mmt_tinyml.c` 的 `MMT_TINYML_PROBE_EN` 改成 `1`，
   重编。串口会出现 `uuid=0x........ accel=N`。
   - `uuid ≠ 0` ⇒ **自定义指令通道 + 加速器都在**（这是最有价值的一步）✓
   - **如果串口从此不再刷新**（连遥测也停）⇒ **自定义指令阻塞** ⇒ 说明
     `mmt_soc_subsystem.v:323-328` 那句"端接成永远就绪、无响应"的注释是**现状**
     （加速器没真正接上）⇒ 立刻改回 `0` 重编，并把这件事记进 §8。
4. **（现在还不能做）** 发卷积命令：需要 §8 的 ①–④。

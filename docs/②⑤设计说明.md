## 1. ② RISC-V 软核决策控制

### 1.1 任务书原文

> RISC-V 软核决策控制：在 FPGA 内运行 RISC-V 软核，负责复杂决策逻辑（如多目标跟踪、历史轨迹分析、预测）和协议处理

### 1.2 整体架构（文字框图）

```
                  ┌──────────────────────────── 视频时钟域 (hdmi_tx_slow_clk) ───────────────────────────┐
 MIPI 摄像头 ───► │ 降采样 160x120 → 帧差(面积/motion) ─┐                                             │
                  │ MLX90640 → 红外热点/最高体温 ────────┤→ mmt_fusion_vote → RTL 报警(rtl_alarm) ──┐   │

                  │ 证据打包 → obs_evt/obs_env/obs_st ───────────────┐                             ▼   │
                  └──────────────────────────────────────────────────┼────────── v7_alarm_sel ──────────┐

```

### 1.3 RTL 与 RISC-V 的分工

| 层 | 承担的工作 | 理由 |
|---|---|---|
| RTL（视频域，每帧） | 帧差面积/运动标志、红外热点/最高体温、环境温湿度、60/25/15 加权融合得分、运动+红外硬件门控、报警保持、LED/蜂鸣器/OSD 输出 | 硬实时、与像素流同步、不受软件调度抖动影响 |
| RISC-V 固件（APB 域，主循环） | 读 RTL 证据做历史统计：滑动窗口平滑、连续帧确认、迟滞、事件类型分类、上升趋势预警；输出决策到字14；控制字15 使能/旁路 | 历史窗口/预测属于"软"逻辑，需要可调参数、可观测、可与 AI（TinyML）结果协同；放软件里迭代成本低 |
| 旁路保证 | 复位默认 `fw_decision_enable=0` ⇒ `alarm_final = rtl_alarm`，与 MERGE10 行为完全一致；仿真测试 b/c 项验证 | 新增通路不改变既有行为，便于定位问题 |

### 1.4 历史轨迹 / 趋势 / 决策算法（固件）

参数集中在 `main_live15.cc` 头部宏：

| 宏 | 值 | 含义 |
|---|---|---|
| `DEC_WIN` | 8 | 滑动窗口长度（样本 = 一次主循环，正常模式约 0.43 s/样本） |
| `DEC_CONSEC` | 3 | 窗口均值连续 ≥ `DEC_TH_ON` 的样本数达到 3 才确认报警 |
| `DEC_TH_ON` | 140 | 报警置位阈值（RTL 融合得分 0..511） |
| `DEC_TH_OFF` | 70 | 报警解除阈值（迟滞，防抖） |
| `DEC_TREND_TH` | 10 | 上升斜率阈值（得分/样本） |
| `DEC_TREND_MIN` | 60 | 触发趋势预警所需的最低窗口均值 |
| `DEC_WARMUP` | 2 | 采集 2 个样本后才把 `fw_decision_enable` 置 1 |
| `DEC_SLOPE_HALF` | 4 | 斜率 = 最近 4 样本均值 − 最早 4 样本均值 |

**公式**（`dec_update()`）：

```
滑动窗口均值：   mean  = (1/N) * Σ_{i=0..N-1} score[n-i]          N = dec_filled ≤ 8
上升斜率：       slope = (1/4) * (Σ recent4 - Σ oldest4)           score/样本
趋势预警：       trend = (slope >= 10) && (mean >= 60)
连续确认：       consec = (mean >= 140) ? consec+1 : 0
报警置位：       !alarm && consec >= 3        → alarm = 1
报警解除（迟滞）： alarm && mean <= 70         → alarm = 0, consec = 0
事件分类：       evt = 1  (alarm && motion && ir_hot)        # 入侵确认
                      2  (trend)                           # 上升趋势预警
                      0  (其它)
置信度：         conf = clamp(mean * 100 / 511, 0, 100)
```

**决策输出**：`字14 = {evt[7:0], conf[7:0], 0, alarm_req}`；`字15.bit0 = fw_decision_enable`，
`字15.bit1 = 本周期是否推理`（观测用）。使能后 RTL 侧：
`alarm_final = rtl_alarm & fw_alarm_req`；未使能时 `alarm_final = rtl_alarm`。

**说明（如实）**：
- 任务书举例的"多目标跟踪/历史轨迹分析/预测"中，本实现做的是**融合得分的历史窗口统计与
  上升斜率趋势预测**，不是多目标轨迹跟踪；v7 RTL 只提供帧差面积/运动/红外/环境摘要，
  不提供目标质心/轨迹，因此未做语义级目标轨迹。
- 固件决策位于"与门"一侧：它只能**否决/保持** RTL 报警，不能独立新增报警（任务书要求
  最终报警 = 固件决策 & 现有门控）。因此不会引入新的漏报路径，但 RTL 报警会被附加
  一次"连续确认"延迟（最多约 `3 × 0.43 s ≈ 1.3 s`），用于滤除单帧瞬态。

### 1.5 软硬件接口（新增 APB 字 11–15）

基址 `0xF8100000`，字地址 = 偏移/4。字 11–15 由 `rtl/v7/mmt/v7_apb_ext.v` 实现，
字 0–10、16–18 保持 MERGE10 行为不变。

| 字 | 偏移 | 方向 | 位域 | 含义 |
|---|---|---|---|---|
| 11 | 0x2C | 只读 | `[0]` motion `[1]` ir_hot `[2]` ir_valid `[3]` sht_seen `[15:4]` body_temp_x10[11:0] `[31:16]` frame_diff_area | 运动/红外摘要 |
| 12 | 0x30 | 只读 | `[15:0]` ambient_x10（int16） `[31:16]` rh_x10 | 环境温湿度 |
| 13 | 0x34 | 只读 | `[8:0]` score `[16:9]` conf `[17]` low_pwr `[18]` alarm_final `[19]` fw_decision_enable `[20]` fw_ai_infer_en `[23:21]` 0 `[31:24]` video_frame_cnt[7:0] | RTL 融合/低功耗/报警状态；帧计数用于帧率测量 |
| 14 | 0x38 | 只写 | `[0]` alarm_req `[15:8]` confidence `[23:16]` event_type | 固件决策结果 |
| 15 | 0x3C | 只写 | `[0]` fw_decision_enable `[1]` fw_ai_infer_en（仅观测） | 固件控制 |

**跨时钟域**：
- 证据 字11/12/13：视频域在 `vs` 上升沿把 `obs_evt/obs_env/obs_st` 锁存快照并翻转 toggle；
  core 域检测 toggle 边沿后整字锁存（数据在 toggle 前已稳定一整帧，属握手式传输）。
- 控制/决策位（字14 bit0、字15 bit0）：core 域 → 视频域两级触发器同步。
- 该设计避免对多比特总线逐位打拍，数据总线只在"快照 + toggle"节拍上跨域。

### 1.6 实时性考虑

| 环节 | 时延 | 说明 |
|---|---|---|
| RTL 融合/门控 | 每帧（60 Hz，≈16.7 ms） | 与视频同步，无软件抖动 |
| 固件读证据 | 主循环内即时读（<1 µs/次） | APB 读，无缓存一致性问题 |
| 固件决策周期 | 正常模式 ≈ 0.43 s/样本；低功耗 0.5 s/样本 | 推理（TinyML）本身约 0.43 s/次，是主循环节拍 |
| 连续确认延迟 | ≤ `DEC_CONSEC × 0.43 s ≈ 1.3 s` | 开启固件门控后新增的最坏确认时延 |
| 解除延迟 | 窗口均值 ≤ 70 后 1 个样本 | 迟滞保证不抖动 |

## 2. ⑤ 低功耗场景管理

### 2.1 任务书原文

> 低功耗场景管理：无人时进入低功耗模式（降低摄像头帧率、关闭神经网络推理、保留温度监测）；检测到人体后自动恢复正常模式

### 2.2 状态机（文字）

```
        ┌────────── 复位 ──────────┐
        ▼                          │
   ┌─────────┐   无人连续 900 帧      ┌──────────┐
   │ ACTIVE  │ ────────────────────► │  LOW_PWR │   (RTL v7_pwr_ctl, PWR_IDLE_FRAMES=900 ≈ 15 s@60Hz)
   │ 全速处理 │ ◄──────────────────── │  低功耗   │
   └─────────┘   运动 或 红外热点      └──────────┘
        ▲              (同一帧立即恢复)        │
        │                                       │
        └──────── 固件：low_pwr=0 → 0.5 s 内恢复推理 + 重写 reg9/10 ◄─┘
```

- **进入条件**：`!fd_motion && !ir_hot` 连续 900 个视频帧（`v7_pwr_ctl.v`，约 15 s@60 Hz）。
- **退出条件**：任一处理帧检出运动或红外热点 ⇒ `low_pwr` 当帧清零（RTL）；固件在 ≤500 ms
  的下一次轮询看到 `low_pwr=0` 后立即恢复推理。
- 状态字段：RTL → 字13 bit17；固件日志 `MMT_LP ... lowpwr=... paused=...`。

### 2.3 三项动作的实现

| 任务书动作 | 实现 | 寄存器/位置 | 状态 |
|---|---|---|---|
| 降低摄像头帧率 | 计划写 VTS 寄存器 `0x320e/0x320f` 把帧长 ×4；**但开机 ROM 表 `rtl/cam_i2c_ctrl/i2c/i2c_master_reg_rom.v` 中无这两个寄存器（逐行核对 0 命中）**，按"找不到则退回只做推理暂停"的约定**未实现降帧**。固件仍通过 APB 字 16/17/18（MERGE10 的相机 SCCB 读写通路）**读一次** VTS 当前值写日志（`MMT_CAM_VTS` / `MMT_LP vts=`） | 字 16/17/18；`main_live15.cc: cam_read_vts()` | ❌ 未实现（有明确原因与回退） |
| 关闭神经网络推理 | `low_pwr=1` 时固件暂停推理循环：不采样帧缓冲、不 `Invoke()`；每 500 ms 只读一次字 11/12/13 并更新 ② 决策；同时写 `reg10=0`、`reg9=0`（`ai_alive=0`），RTL 视觉输入退回运动检测；`low_pwr=0` 立即恢复 | 固件主循环 `#if LOWPOWER_ON` 分支；`LP_POLL_MS=500` | ✅ 已实现（仿真/编译级验证；板上效果待验证） |
| 保留温度监测 | 不动 RTL 传感器子系统：SHT30 周期 1000 ms、MLX90640 周期 500 ms（`v7_mmt_core.v` 参数 `SHT_PERIOD_MS/IR_PERIOD_MS`）；固件在 `MMT_LP` 行输出 `sht=`/`rh=`/`body=` 与 `sht_upd`/`ir_upd` 更新计数，用日志证明低功耗期间仍在更新 | `v7_mmt_core.v:90-95`；`main_live15.cc` 传感器更新计数 | ✅ 已实现（RTL 未改；日志证明待上板核对） |

**为什么 AI 推理暂停期间要清 reg9/reg10**：MERGE11 顶层 `AI_MODE=1`，RTL 的 `vision_prob` 来自
固件写入的 AI 判决/得分；推理暂停后若保持旧值，RTL 会一直用最后一次 AI 结果做融合。清 0 后
`ai_alive=0`，RTL 自动退回 `ai_person/运动检测`（`v7_mmt_core.v` AI_MODE 分支），语义上等价于
"关闭神经网络推理，仅保留运动/温度监测"，恢复后再写回。

### 2.4 恢复时延的设计考虑

- RTL 侧恢复是**同帧**的：`v7_pwr_ctl` 在检出 `human` 的 `vs` 沿立即清 `low_pwr`，视觉处理
  从下一帧恢复全速。
- 固件侧轮询间隔取 **500 ms**：兼顾"及时恢复"与"低功耗时真的少跑"；最坏恢复延迟
  = 500 ms + 一次主循环（读证据 + 更新决策，<1 ms）。
- 为什么不是 100 ms：500 ms 已满足演示与温度采样节拍（SHT30 1 Hz），同时把低功耗期间
  的固件活动量压到 2 次/秒。

### 2.5 可展示的量化指标（不依赖功率计）

由固件日志 `MMT_LP` 每轮输出：

| 指标 | 来源 | 说明 |
|---|---|---|
| 相机帧率 `camfps` | 字13 `[31:24]` 视频帧计数差值 ÷ 秒 | 8 位计数（256 帧回绕），采样周期 ≤1 s，安全 |
| 推理次数/秒 `inf_hz` | 固件计数 | 低功耗暂停时为 0，恢复后回到 ≈2.4 |
| DDR 读事务/秒 `ddr_ar_s` | 字2 `soc_ar_cnt` 差值 ÷ 秒 | SoC 主口 AXI AR 握手数（TinyML 读帧缓冲） |
| 加速器 AR/秒 `tml_ar_s` | 字4 `t_ar_cnt` 差值 ÷ 秒 | TinyML 加速器读带宽代理 |
| 传感器更新计数 `sht_upd/ir_upd` | 字12/字11 数值变化计数 | 证明低功耗期间温度监测仍在更新 |
| 相机帧长 `vts` | 字16/17/18 读 `0x320e/0x320f` | 本实现未改（回退），仅记录 |

**如实说明**：以上是系统活动量指标（帧率、推理次数、总线事务），**不是电流/功率测量**；
本项目没有功率计，任务书 ⑤ 原文也未要求给出功耗数字。

- 构建：MERGE11 五步流程通过、时序全正（见构建报告）；固件经项目脚本编译（见固件报告）。

### 4.2 已仿真验证（Icarus Verilog 11.0）

- `sim/tb_apb_ext.v`：字 11/12/13 读回与内部证据一致（含下一帧才更新）；字 14/15 写入后
  视频域控制位生效；字 13 的 fw_en/ai_en 回读；报警选择 8 种组合真值表；复位默认旁路。
- `sim/tb_i2c_apb.v` / `sim/tb_apb_regs.v`（MERGE10 原测试台）：回归通过（I2C 通路、旧字 0–10/16–18）。

### 4.3 尚未上板验证（明确列出）

- `low_pwr` 进入/退出时序在真实摄像头帧率下是否符合 15 s 预期；
- 推理暂停后 RTL 视觉输入退回运动检测的实际融合得分变化；
- 字 11/12/13 的真实证据数值（帧差面积量纲、体温/环境读数）；
- ② 决策在真实场景下的分离度（挥手/站立/离开）；
- 相机 VTS 读回值（本实现只读不写；ROM 无此寄存器 ⇒ 未降帧）；
- 长期运行稳定性（CDC 握手、日志 # 量、TinyML 推理与 APB 访问并发）。

### 4.4 已知限制（不夸大）

1. 未降低摄像头输出帧率（原因：ROM 表无 `0x320e/0x320f`，按任务约定回退）。
2. "历史轨迹分析"限于**融合得分时间序列**（窗口/斜率），不是多目标轨迹跟踪。
3. 固件决策只能否决 RTL 报警，不能独立新增报警（由"最终报警 = 固件 & 现有门控"的约定决定）。
4. 固件决策会引入最长约 1.3 s 的附加确认延迟（滤除瞬态换来的代价）。
5. 低功耗的"省电"没有功率计数据；只能用帧率/推理次数/DDR 事务量作为代理指标。

### 4.5 构建与固件结果（本次实测）

**MERGE11 位流（v7_flow.ps1 五步）**：

| 步 | 结果 |

| [1] efx_map | 退出码 0 |
| [2] efx_pnr#1 | 退出码 0 |
| [3] efx_run -f interface | PASS（483 行接口） |
| [4] filter_interface | wrote 483 lines |
| [5] efx_pnr#2 --sync_file | 退出码 0 |

## 2. 烧录

### 2.1 两种模式
- **JTAG**：烧到片内 SRAM，**掉电就没了**。← **第一次用这个**，快、反复试不写坏 flash。
- **SPI Active**：烧到板上 flash，掉电保留，上电自动加载。← 稳定后/演示时用。

### 2.2 烧位流（先只烧这一步）

1. 插 Type-C，确认电脑识别出串口（设备管理器里多一个 COM 口）。
2. 打开 **Efinity Programmer**（开始菜单里单独有这个程序）。
3. 器件选 **Ti60F225**。
4. 模式选 **JTAG**。
5. 文件选：`D:\FPGA\mmt\out\mmt.hex`
6. 点 **Start**，等完成。

### 2.3 把"程序 + AI 模型"也烧进 flash（第 2 步，可以晚点做）

固件和模型放在 flash 的 **0x380000**，由片内一小段搬运程序负责搬进 DDR 运行。

**走厂商的分两次烧（推荐，最简单）：**

| 顺序 | 文件 | 起始地址 |
|---|---|---|
| 1 | `D:\FPGA\mmt\out\mmt.hex` | **0x00000000** |
| 2 | `D:\FPGA\mmt\sw\ddr\build\ddr_image.bin` | **0x00380000** |

两次都用 **SPI Active** 模式（如果你要先在 SRAM 里验证，第 1 步用 JTAG，第 2 步的数据反正只在 flash 里有意义）。

> ⚠️ 合并成"一个文件烧一次"的路（`sw\ddr\build\flash_combined.hex`）**本轮没做出来**：Programmer 自带的合并工具 `multi_image_merger.py` 读我们这份位流时报格式错（位流头里有 9 行是 **2 字节挤在一行**，就是路径里 `易灵思` 那几个字节被转义了；我做了规范化后格式错消失，但它又卡在 `invalid device information`）。
> **所以用上面的分两次烧就行**，这条路是厂商 readme 的原始做法，不依赖合并工具。

**烧完可以自检**（不用板子，纯解码检查重叠/越界）：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\FPGA\mmt\sw\ddr\verify_flash_layout.ps1"
```
实测：**PASS 24 / FAIL 0 / WARN 2**（两个 WARN 都是信息性的）。

## 4. 已知风险 / 预期会踩的坑

1. **摄像头出图是本轮最大未知数。**
   我们刚把"写通路被综合器误删"这个问题绕过（用 `(* preserve *)`），**波形/仿真层面没有再回归一次**，所以：
   - 如果屏幕**一直显示不动的画面**（内存残留）→ 说明写通路还是没生效，**不是**你接线的问题，把这个现象告诉我；
   - 如果屏幕**跟着摄像头变化**（哪怕颜色不对、有撕裂纹）→ 说明写通路通了，接下来才是调图像格式/时序的事。
   **两种情况都请拍照/录一小段发我**，这比文字描述有用得多。
2. **摄像头 FPC 插座有两个**（一个屏、一个摄像头），插错不会烧，但肯定不出图。
3. **引脚是我们自己选的**：UART（R4/R14）、蜂鸣器（A12）、传感器 I2C（C5/A4）在板上**没有现成网络**，要按 `mmt.peri.xml` 的脚位自己飞线/用 QSE 转接子卡。SPI flash 那 4 根（M1/L1/N1/P1）是板子固定的配置脚，**不用动**。
4. **别热插拔摄像头**：先断电（拔 Type-C）再插拔 FPC。
5. **如果 HDMI 全黑但 LED 在闪**：说明逻辑跑起来了、只是输出没出来。可能原因：显示器不接受这个时序 / OSD 没初始化 / 视频复位（这条刚修，属于"还没上板验证"的部分）。记下现象即可。

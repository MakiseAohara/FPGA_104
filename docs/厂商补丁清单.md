## 三、三处改动的细节（取自 diff）

### 1. `frame_buffer.v` — 帧步长修复

```verilog
// [我们] 新增
.BURST_LEN      (BURST_LEN        ),
// ★ 2026-10-13 修复（task-21 仿真实证）：原来漏转发这三个参数 ⇒ ddr_buffer 用自身默认
//   1920×1080 算 FRAME_LEN（0x7E9200），而本工程约定是 960 版 0x3F4A00 ⇒ 三个 bank 基址
//   错成 0x02000000/0x027E9200/0x02FD2400 ⇒ bank2 写入 [0x02FD2400,0x031CC800) 会把
//   TinyML 张量区（0x03000000 起）前 1.80 MB 覆盖掉。
.FB_NUM           ( FB_NUM           ),
.MAX_VID_WIDTH    ( MAX_VID_WIDTH    ),
.MAX_VID_HIGHT    ( MAX_VID_HIGHT    )

// [demo] 只有
.BURST_LEN      (BURST_LEN        )
```

### 2. `ddr_wr_buffer.v` — preserve 属性 + 写 ID

```verilog
// [我们]
(* preserve, syn_keep = 1 *) output  reg 	awvalid = 'd0,  // ★ 2026-10-12：必须保留！
(* preserve, syn_keep = 1 *) output  reg		wvalid,         // ★ 必须保留！
(* preserve, syn_keep = 1 *) reg [1:0] state = 2'd0;        // ★ 必须保留！
(* preserve, syn_keep = 1 *) reg wr_req = 0;                // ★ 必须保留！
assign awid = 6'h0D;  // AXI 写 ID：低 4 位 = 0xD，非 0，与 TinyML(0) 互斥

// [demo]
output  reg 								awvalid = 'd0,
output  reg									wvalid,
reg [1:0] state = 2'd0;
reg wr_req = 0;
assign awid = 8'd0;
```

### 3. `ddr_rd_buffer.v` — 读 ID（此前从未记录在案）

```verilog
// [我们]
assign arid = 6'h0C;  // AXI 读 ID：低 4 位 = 0xC，非 0，与 TinyML(0) 互斥；本模块不使用 rid，ID 为纯 tag

// [demo]
assign arid = 6'h00;
```

**这处改动在 `docs\代码学习地图.md §7.3` 与交接提示词里都没有出现**，是从哈希比对里发现的。
相关背景见 `docs\AXI主口ID互斥修复.md`。

## 四、为什么这份清单重要

1. **`cam_i2c_ctrl` 全部相同** ⇒ 摄像头 I2C 配置表**不是**"摄像头不出图"的原因（我们用的和能出图的 demo 是同一份代码）。
2. **`debayer` / `dvi_tx` / `ddr3_controller` 全部相同** ⇒ 显示链路与 DDR 控制器也排除。
3. **3 处改动全部集中在 `frame_buffer/`**，且都是我们主动加的（修复 + 属性 + ID）。
   ⇒ 若上板时写通路/DDR 行为异常，嫌疑范围被压缩到这 3 个文件。
4. **AXI ID 改动是风险点**：`awid=0xD` / `arid=0xC` 是为了和 TinyML 的 ID 0 区分，
   而 AXI 互联是加密 IP，ID 路由行为只能靠仿真（`sim\axi_ic\`，用的是行为模型，非真实 IP）。

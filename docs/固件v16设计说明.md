# 固件 v16 设计说明（自动曝光 / 相机降帧 / AI 输入预处理 / 相机安全访问）

> 适用位流：**MERGE11**（本固件不依赖任何新 RTL 寄存器；只使用 MERGE10 起已有的 APB 字 16/17/18 与 MERGE11 的字 11–15）
> 源码：`sw/tinyml_live/main_live16.cc`；共用核心头：`sw/tinyml_live/v16/*.h`
> 状态：**电脑端测试全部通过；尚未上板验证**（哪些未验证见 §9）

---

## 0. 范围与基线

- 基线：`main_live15.cc`（MERGE11 固件：② RISC-V 决策 + ⑤ 低功耗）。
- 本版本新增四组功能，全部由宏开关控制，**默认全关**：
  | 宏 | 默认 | 功能 |
  |---|---|---|
  | `CROP_MODE` | 0 | AI 输入裁剪方式（0 整幅 / 1 中间正方形 / 2 中间 1.5 倍宽） |
  | `NORM_ON` | 0 | 亮度归一化（目标均值 115） |
  | `STRETCH_ON` | 0 | 1%/99% 分位拉伸 |
  | `AUTOEXP_ON` | 0 | 自动曝光控制器 |
  | `LP_CAMFPS_ON` | 0 | 低功耗期间相机降帧（写 VTS） |
  | `LP_VTS_MULT` | 3 | 降帧倍数（限 2..4） |

## 1. 默认行为与 main_live15 的一致性（验收依据）

全部宏为默认值时：

1. **采样数学完全一致**：`preprocess_core.h` 的 `pp_run()` 在 CROP=0/NORM=0/STRETCH=0 时逐像素复刻
   `main_live15.cc` 的 `sample_frame_box()`（同一几何公式：`sx=(ox*3+i)*cw/288` 在 `cw=1920` 时等价于
   `ox*20 + i*20/3`；`sy=(oy*3+j)*ch/288` 等价于 `(oy*45+j*15)/4`；同样的偶数对齐与边界钳位；同样
   `acc/9`；同样 `(int8_t)v` 位重解释）。
   **电脑端测试已证明逐像素一致**：随机帧下 9216 个输出像素 `diff_pixels=0`，返回的 uint8 和也相同
   （`sum_new=1170952 == sum_ref=1170952`，见 `host/logs/test_preprocess.log`）。
2. **②/⑤ 逻辑原样保留**：滑动窗口/迟滞/事件分类、低功耗推理暂停、`MMT_DEC`/`MMT_LP` 日志字段与 v15 相同。
3. **不读写新寄存器**：`AUTOEXP_ON=0 && LP_CAMFPS_ON=0` 时，不做 `MMT_CAM` 的 8 个寄存器启动读取，
   不写任何相机寄存器；启动只保留与 v15 相同的 `MMT_CAM_VTS` 只读行（格式与 v15 一致，含 `fallback=1`）。
4. 唯一**新增的可观察差异**是任务书要求的 `MMT_CFG` 行（打印编译期宏配置）——这是"每个固件日志头部
   必须打印所用宏配置"的硬性要求，不影响功能行为。

> 结论：默认配置下，功能行为与 `main_live15.cc` 一致；差异仅在版本字符串、`MMT_CFG` 行与代码体积（base 472,594 B）。

## 2. 功能 1：相机寄存器安全访问层

### 2.1 接口

```c
static int cam_raw_read (unsigned short reg, unsigned char *out);   // 超时 10 ms
static int cam_raw_write(unsigned short reg, unsigned char val);    // 超时 10 ms
// 安全封装（cam_ctrl_core.h）
static int cam_checked_write(cam_io_t *io, unsigned short reg, unsigned char val, unsigned char *old_out);
```

流程：等待 ready（`字17.bit2`=1 且 `字17.bit0`=0）→ 清残留 done → 写命令（`字16`：bit31=start，
bit30=rw，[23:8]=寄存器地址，[7:0]=写数据）→ 轮询 done（`字17.bit1`，10 ms 超时）→ 读 `字18`。

### 2.2 写白名单

`0x320e`、`0x320f`（VTS）、`0x3e00`、`0x3e01`、`0x3e02`、`0x3e03`（曝光/模式）、`0x3e08`、`0x3e09`（增益）。
其它地址返回 `CAM_E_NOT_ALLOWED`，**不产生任何写**。

### 2.3 读回校验与回滚

每次写：读旧值 → 写新值 → 读回确认。
- 一致 → 返回 `CAM_OK`；
- 不一致 → 写回旧值并再确认：回滚成功返回 `CAM_E_VERIFY`，回滚也失败返回 `CAM_E_ROLLBACK`。
固件收到错误会打印 `MMT_AE_ERR` / `MMT_LPCAM ... FAILED` 并关闭对应功能。

### 2.4 启动读初始值

仅当 `AUTOEXP_ON || LP_CAMFPS_ON` 时执行（保证默认行为与 v15 一致）。读 8 个寄存器并打印：

```
MMT_CAM 320e=.. 320f=.. 3e00=.. 3e01=.. 3e02=.. 3e03=.. 3e08=.. 3e09=.. exp=0x.... gain=0x....
```

后续 AE/降帧的上下限一律来自这些**实际读到的值**，不凭手册直接写。

## 3. 功能 2：自动曝光（AUTOEXP_ON）

### 3.1 控制律

- 目标：96×96 输入图均值（`mean_sensor`，即**原始取样均值**，不受 NORM/STRETCH 影响）稳定在
  `[AE_TARGET_LO, AE_TARGET_HI] = [95, 125]`。
- 每 `AE_EVAL_FRAMES=8` 帧评估一次。
- 越界判定：先看死区 `AE_DEADBAND=3`（`[lo-3, hi+3]` 内不动），超出死区后需**连续 2 次**评估
  （`AE_CONFIRM=2`）才动作；单次调节幅度 ±12%（`AE_STEP_PCT=12`）。
- 动作顺序：**先曝光、后增益**；变亮时曝光到上限再用增益，变暗时曝光到下限再用增益。
- 动作后等待：任务书要求"等待 3 帧再评估"；因评估周期 8 帧 ≥3 帧，默认不再额外跳过评估
  （`AE_WAIT_EVALS=0`；若把 `AE_EVAL_FRAMES` 改到 <3，请把 `AE_WAIT_EVALS` 设为 3）。
- 饱和：曝光与增益都到对应上限/下限后不再动作，日志打印 `act=-1/-2`。
- 低功耗期间（`low_pwr=1`）**冻结**（不评估、不写寄存器）；退出后计数清零重新评估。

### 3.2 上下限

- 曝光码：`exp = (0x3e01<<8) | 0x3e02`；增益码：`gain = (0x3e08<<8) | 0x3e09`。
- 上限：曝光 `min(初始值×4, 0xFFFF)`；增益 `初始值×2`（不超过 ×2）。
- 下限：任务书写"下限=初始值"（**默认只能变亮、不能变暗**）。电脑端测试还要求"偏亮场景也能收敛"，
  两者冲突，因此提供 `AE_DIM_ENABLE`（默认 0）：置 1 时下限 = 初始值/4，允许下调。
  **默认固件保持任务书语义**；主机测试的偏亮场景用 `AE_DIM_ENABLE=1` 验证双向能力。
- `AE_SET_MANUAL`（默认 0）：置 1 时写 `0x3e03 = 初始值 | 0x01`（候选手动模式位）。
  该位定义**未上板确认**，默认不写；上板时先看 `MMT_CAM` 的 0x3e03 读数再决定。

### 3.3 主机模型验证（已通过）

相机模型：`mean = scene × (exp/exp0) × (gain/gain0) + 噪声(±2)`，测量有 1 次评估延迟。

| 场景 | 结果 |
|---|---|
| 偏暗：初始均值 45 | 第 **17** 次评估进入目标，最终均值 96；进入后 0 次动作 |
| 偏亮：初始均值 200（`AE_DIM_ENABLE=1`） | 第 **11** 次评估进入目标，最终均值 119；进入后 0 次动作 |
| 已在目标范围（均值 110） | 15 次评估 **0 次动作**（死区+迟滞） |
| 极暗场景（均值 5） | 曝光/增益都到上限后报饱和，始终不越界 |
| 20 场景 × 80 次评估随机检查 | exp/gain **从未越界** |

日志：`sw/tinyml_live/v16/host/logs/test_autoexp.log`。

### 3.4 未验证 / 风险

- 真实相机"曝光码→亮度"线性度、增益粗/细寄存器的码值含义、生效延迟**均未上板标定**；
- 0x3e03 手动模式位未确认（默认不写）；
- 若曝光/增益寄存器实际不是 16 位线性码，AE 可能动作方向正确但步长失真，需按 `MMT_AE` 日志调参。

## 4. 功能 3：低功耗相机降帧（LP_CAMFPS_ON）

### 4.1 保护逻辑（先决条件）

1. 启动时读 VTS（`{0x320e[6:0],0x320f}`）；
2. **只有 VTS ∈ [0x0400, 0x0a00]** 才启用；否则打印
   `MMT_LPCAM init vts=0x.... DISABLED (valid range [0x0400,0x0a00])` 并永久关闭；
3. 读寄存器失败 → 直接禁用，不写；
4. 写序列：先高字节 `0x320e`、后低字节 `0x320f`，每字节都走 `cam_checked_write`（白名单+回滚）；
5. 写完重读 VTS 校验；失败 → 恢复初始值并**永久关闭**；
6. 倍数 `LP_VTS_MULT` 钳位到 2..4；新 VTS 不超过芯片最大帧长 `0x7ff0`。

### 4.2 进入/退出

- 进入 `low_pwr`：`VTS_new = VTS_init × mult`（写 + 读回校验）→ 打印
  `MMT_LPCAM enter vts=0x....->0x.... mult=...`；
- 退出：恢复 `VTS_init` → 打印 `MMT_LPCAM exit vts restored=0x....`；
- 周期日志：`MMT_LPCAM state=... vts=... mult=... camfps=...`。
  其中 `camfps` 用字13 `[31:24]` 视频帧计数在 1 s 窗口内的差值计算（8 位回绕安全）。

### 4.3 主机（mock 寄存器层）验证（已通过）

- VTS=0x05dc 正常：进入 ×3 → 0x1194（高字节先写），退出恢复 0x05dc；
- VTS 越界（0x0300）：init 返回禁用、进入被拒、**0 次写**；
- 写入读回不一致：恢复初始值 + 永久禁用；
- 回滚失败：返回 `CAM_E_ROLLBACK`；
- 倍数 9→4、1→2 钳位正确。
日志：`sw/tinyml_live/v16/host/logs/test_camctrl.log`。

### 4.4 未验证 / 风险

- 真实 SC431HAI 是否接受运行中改 VTS、画面/CSI 是否出现撕裂或丢行**未验证**；
- 降帧只影响相机输出（VTS），**不影响** RTL 帧差/推理逻辑的时钟；
- 若上板发现画面异常：立即用 `LP_CAMFPS_ON=0` 重编（VTS 不会被写）。

## 5. 功能 4：AI 输入预处理选项

### 5.1 几何

帧缓冲固定：行距 **1920 B**、1 B/像素、1920×1080（与已修复的 v14 几何一致）。
通用取样公式（`CROP_MODE` 决定 `x0,cw`；`y0=0, ch=1080`）：

```
sx = (ox*3 + i) * cw / 288 + x0     i∈{0,1,2}
sy = (oy*3 + j) * ch / 288 + y0     j∈{0,1,2}
sx &= ~1 ; sy &= ~1                （2x2 Bayer 对齐）
sx 限幅到 x0+cw-2 ; sy 限幅到 y0+ch-2
v  = mean( 2x2 quad at (sx,sy) ) ; acc += v ; 输出 = acc / 9
```

- `CROP_MODE=0`：`x0=0, cw=1920`（原行为）
- `CROP_MODE=1`：`x0=420, cw=1080`（中间正方形，**去掉左右各 420 列**，解决 16:9→1:1 的横向压扁）
- `CROP_MODE=2`：`x0=150, cw=1620`（中间 1.5 倍宽）

### 5.2 归一化（NORM_ON）

- 先算原始 96×96 的均值 `mean_in`；增益 `g = round(115×100 / mean_in)`，限幅 `[50, 300]`（0.5..3.0）；
- 每个像素 `v = v*g/100`，clamp 0..255；
- 日志 `MMT_PP ... mean_sensor=... mean_in=... gain_x100=... mean_out=...`
  （`mean_sensor` 是**未归一化**的原始均值，AE 用它）。

### 5.3 拉伸（STRETCH_ON）

- 对 96×96 的 0..255 值做 256 桶直方图，取 1%（千分比 10）与 99%（千分比 990）分位 `lo/hi`；
- `v = (v-lo)*255/(hi-lo)`，clamp 0..255；画面极平（`hi<=lo`）时**不拉伸**（避免放大噪声/除零）；
- 处理顺序：取样 → STRETCH → NORM → int8。

### 5.4 主机合成帧验证（已通过）

| 测试 | 结果 |
|---|---|
| 回归：CROP=0 全默认 vs main_live15 | `diff_pixels=0`，uint8 和相同 |
| crop1 取样范围（亮块 x=600..899,y=300..599） | 输出亮区 x=[16,41] y=[27,52]，与理论 `x≈16..42,y≈27..53` 一致 |
| crop2 取样范围 | 输出亮区 x=[27,43]，与理论 `x≈26..45` 一致 |
| 裁剪区外亮块（x=50..300） | crop1 输出全 0（正确忽略） |
| NORM 偏暗（均值 50） | 输出均值 **115**，gain_x100=230 |
| NORM 极暗（均值 20） | gain 限幅 **300**，输出均值 60（到上限） |
| NORM 极亮（均值 240） | gain 限幅 **50**，输出均值 120 |
| STRETCH 梯度 20..235 | 输出 min=2 / max=255，lo=20 / hi=233 |

日志：`sw/tinyml_live/v16/host/logs/test_preprocess.log`。

### 5.5 预期（未上板验证）

- crop1/crop2 应减少"人占画面比例被压扁"造成的输入畸变，可能改善 p 的分离度；
- NORM 把 `b0m` 拉向 115，可缓解夜间/曝光漂移，但会放大暗部噪声；
- STRETCH 对低对比场景可能更有效，但对噪声/坏点敏感；
- 三者的真实收益必须用 `docs/上板步骤-v16.md` 的对比实验测，不能凭设计假设下结论。

## 8. 决策记录（自主决定，如实列出）

1. **AE 下限冲突**：任务书要求"下限=初始值"，电脑端测试又要求偏亮场景能收敛。实现按任务书默认
   （`AE_DIM_ENABLE=0` 只能变亮），并额外提供 `AE_DIM_ENABLE=1`（下限=初始值/4）用于偏亮场景测试；
   主机测试用后者验证双向调节，默认固件不启用下调。
2. **AE "等待 3 帧"**：评估周期 8 帧 ≥3 帧，因此默认 `AE_WAIT_EVALS=0`（不再额外跳评估）；
   若把评估周期调小，应改回 3。
3. **启动读相机寄存器**：只在 `AUTOEXP_ON || LP_CAMFPS_ON` 时执行，保证 base 配置行为与 v15 一致
   （VTS 只读行仍与 v15 完全一致保留）。
4. **曝光/增益码值**：按 `{0x3e01,0x3e02}`、`{0x3e08,0x3e09}` 合成 16 位码值做线性近似；
   真实位定义/线性度未上板确认，设计说明与上板步骤均已标注。
5. **0x3e03 手动模式**：不猜位定义，`AE_SET_MANUAL=0` 默认不写；提供候选值开关，需上板确认。
6. **相机降帧失败策略**：任何读回不一致/写失败都恢复初始值并**永久关闭**该功能，避免把相机置于
   半配置状态；`base`/其他变体默认不启用，因此风险默认关闭。
7. **变体生成方式**：`build_variants.py` 对源码里的 `#define <MACRO> <默认值>` 行做受控替换并校验
   "恰好出现 1 次"，保证六个镜像来自同一份 main_live16.cc，避免手工复制走样。
8. **不覆盖旧固件**：新变体以 `tinyml_pdti8_v16_*.bin` 命名放入 `v16/fw/`，不覆盖队友已验证的
   `tinyml_pdti8.bin`。

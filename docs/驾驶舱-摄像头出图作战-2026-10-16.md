## 0. 一句话

**摄像头链路已经通了 4 段（CSI 收 → 视频进帧缓冲入口 → 视频读 → HDMI），唯一死的是「帧缓冲写 DDR3」。**
而死因不是 RTL 写错，是 **Efinity 2026.1 把写 FSM 的"条件装载"寄存器折成常量**（`.D(1'b0)`）。
修法已知（`infer-clk-enable=0`），唯一障碍是**装不下：60833 > 60800，差 33 个 XLR**。
**本方案的唯一新动作：把 TinyML 加速器暂时摘下来，腾出 15,647 XLR。**

| 2 | MIPI CSI 收包 | ✅ 通 | `DE=277542377 HS=1302067 VS=1205 pd=305172` 全在涨；`ck`/`d0..d3` 的 HS_ENA 全起 |

**根因（你 10-16 的提交已给出）**：

| 实验 | 结果 |
|---|---|
| 同一份厂商工程：2025.2.288 综合 | 写通路完好（FIFO 13 块、CE 齐全） |

> ⚠️ 还有一条必须记住的坑：`mmt.xml:163` 当时**注释写着 3→0，但 value 实际仍是 3**。
> 也就是说 **10-15 的 v2 位流里根本没有这个修复**。这不是"修了没用"，是"压根没修"。

## 2. ★ 唯一新杠杆：TinyML 占掉全设计 34.8% 的 XLR，而它现在不产出任何功能

`out/mmt.hier_util.rpt`【实测】：

| 模块 | XLR | BRAM | DSP | 当前是否产出功能 |
|---|---|---|---|---|
| `u_soc` | 10,540 | 71 | 4 | ✅ 全部遥测/决策/OSD 都靠它 |
| `u_ddr3_top` | 6,031 | 39 | 0 | ✅ 帧缓冲必须 |
| `inst_efx_csi2_rx` | 2,901 | 36 | 0 | ✅ 摄像头入口 |
| **`u_tinyml_accel`** | **15,647** | **33** | **12** | ❌ **推理链路没通** |
| `checker0`（帧缓冲） | 2,464 | 22 | 0 | ✅ |
| 其余 | ~7,400 | 55 | 8 | ✅ |

**TinyML = 15,647 XLR（34.8%）+ 33 BRAM + 12 DSP，而 `MMT_TINYML_ISSUE_EN` 恒为 0（fail-closed），推理从未跑通过一次。**

⇒ 摘掉它：

1. **XLR**：15,647 ≫ 33 ⇒ `infer-clk-enable=0` 从"差 33 装不下"变成"绰绰有余"；
2. **BRAM**：写通路修好后写 FIFO 要回来 **+13 块**。你现在 235/256（91.8%），只剩 21 块；
   摘掉 TinyML 后最坏情形（写 FIFO 回 13 + CSI RX 回 32）≈ **235 − 33 + 45 = 247/256**，**仍然装得下**；
3. **时序**：XLR 从 100%+ 降到 ~60–75%，原来"最小 slack +0.021 ns（hold）"的下限会宽松很多。

**这不是"砍功能换进度"，是"删掉一个当前零 yield 的模块"。** 而且它是**可逆的**：一个宏开关。

### 2.1 技术要点：为什么摘 TinyML 不需要重生成 AXI 互联

`axi_interconnect` 是 **S_PORTS=3**（frame_buffer / SoC / TinyML）。本方案**不动互联**，只把 s2 口钉成"永远不发请求的主口"：

```
tinyml_accelerator_channels u_tinyml_accel  →  由 `ifdef MMT_TINYML_ENABLE 包住，默认不综合
tml_*  (s2 的 AXI 主口信号)                  →  默认全部 assign 0（valid=0 / ready=0）
u_soc 的 .ci_* (自定义指令口)                 →  默认全部接常量（cmd_ready=0，fail-closed）
```

**收益**：零 IP 重生成、零 `.peri.xml` 改动、零引脚改动、零固件改动。
**代价**：互联仍占着 s2 口的仲裁逻辑（几百 XLR 级），可忽略。

## 3. 执行：三步，一次构建

### 步骤 1 — 应用补丁（2 分钟，离线）

```bat
cd /d D:\FPGA\mmt
:: 备份当前状态（保留进度，随时可回）

```

补丁只改 **2 个文件、7 个 hunk**：

| 文件 | 改什么 |
|---|---|
| `rtl/mmt/mmt_top.v` | 加 `MMT_TINYML_ENABLE` 宏（默认未定义）；TinyML 例化整块 + `tml_*` 钉 0 + `u_soc` 的 `ci_*` 钉 0 三处加 `ifdef`/`else`/`endif` |
| `mmt.xml` | `infer-clk-enable` **3 → 0**（这次是真的改，不是只改注释）+ 写明与宏必须同进同退 |

> 补丁是**双文件、可 `git apply`** 的（已用独立回放器逐字节验证：7 hunks 全部落在正确上下文，回放结果 == 预期结果）。
> 另做了**两种宏配置的结构自检**（无仿真器可用）：宏嵌套平衡、括号/begin-end/module 配对、
> `u_soc` 170 个端口连接无重复、`ci_*` 九个端口在两个分支里**端口集完全一致**（只换驱动源）、
> `tml_*` 在关断态下 24 个驱动齐全 / 开启态只剩 2 个 lock 位补零。

### 步骤 2 — 构建（约 15 分钟）

```bat
cd /d D:\FPGA\mmt
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_mmt.ps1
```

`build_mmt.ps1` 的现有三层防线正好适配本次（**不要绕过它**）：
① 构建前清 `work_pnr\*.lbf` 与 `out\mmt.bit`（杜绝陈旧位流）；
② `efx_map` → `check_expected` 门禁 → `efx_pnr`，任一步失败即 abort；
③ 校验 bit 时间戳晚于 PnR 结束并写 sha256。

> ⚠️ `infer-clk-enable=0` 后综合时间可能变长（逻辑变多），但总体量反而**下降**（TinyML 走了）。
> 如果 PnR 报 `Block capacity checks have failed`，直接看下面的 §5 失败分支。

### 步骤 3 — 构建后判定（1 分钟，**先判再上板**）

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File patches\verify_ice0_cut.ps1
```

读 `out\mmt.place.rpt` / `mmt.map.rpt` / `efx_pnr.log`，四条判据：

| # | 判据 | 通过含义 |
|---|---|---|
| ① | `XLRs` ≤ 60800，`Memory Blocks` ≤ 256 | 装得下 |
| ② | `efx_pnr.log` 里 `u_tinyml_accel` 出现 **0** 次 | 宏真的生效了（不是"以为生效"） |
| ③ | **`fb_awvalid` / `fb_wvalid` / `fb_wlast` 不再出现 `optimized to 0/1`** | ★ 写通路没被折 —— 本轮成败关键 |
| ④ | `state[0/1]`、`sync_r0/1/2` 未被折叠；`u_wr_fifo` 读端口未 `disabled` | 写 FSM + 写 FIFO 都回来了 |

**退出码 0 才上板。** 退出码 1 说明"编译过了但写通路还是死的" —— 这种位流烧上去只会再看到一次雪花，白占板子。

## 4. 上板判据（顺序不要跳）

| 步 | 看什么 | 期望 | 不符时的含义 |
|---|---|---|---|
| 1 | `pid=0x4D4D5450`、`nk≠SCL`、`rh≠CK` | 成立 | 位流/固件没生效，停 |
| 2 | **`dbg=` 最高字节** | 本版路标常量 | 读到旧路标 ⇒ 烧错位流 |
| 3 | **`[WR] AW=… W=…`** | **`d>0` 持续增长**（第一次！） | 仍为 0 ⇒ 写通路还是被折，回 §5 |
| 4 | `[AMAX] amax` | 落在 `[0x02000000, 0x02BDDE00)` | `OVER1920/SUSPECT` ⇒ 帧步长 |
| 5 | **HDMI 画面** | **雪花变成真实画面** | 有 AW/W 但仍是雪花 ⇒ 读通路/HDMI（另一条线，不要回改写通路） |

第 3 步是**分水岭**：`AW` 从"开机到现在一次都没涨"变成"在涨"，就说明这 33 个 XLR 的缺口被填上了。
第 5 步出图后，才轮到白平衡/Bayer 相位（🟡 可延后）。

> 若 AW 涨了但画面颜色不对：先查 `docs/去马赛克Bayer相位分析.md`，**别动写通路**。

## 5. 失败分支（每种都给了下一步，不要即兴发挥）

| 现象 | 判断 | 下一步 |
|---|---|---|
| `verify_ice0_cut.ps1` 报 **XLR 超限** | 摘 TinyML 还不够，或宏没生效 | 先看 ② 是否 0；若确实为 0 仍超限 ⇒ 说明 ice=0 的膨胀比预估大，走 §5.1 |
| ② 报 `u_tinyml_accel` 仍存在 | 宏没生效 | 检查是否误把 `// `define ...` 取消注释；检查 `mmt.xml` 是否在综合参数里另加了 `MMT_TINYML_ENABLE` |
| ③ 仍报 `fb_awvalid optimized to 0` | **ice=0 也没救回来** | 这否掉了"根因=ice"这条强假设 ⇒ 走 §5.2（换版本），不要再去调 preserve |
| XLR/BRAM 都过、但 `[WR] AW` 还是 0 | 容量不是障碍，是别的 | 读 `dbg` 的 `state`/`sync_r2_cnt`：`sync_r2_cnt=0` ⇒ 启动链没到；`state≠0` 但 `awready=0` ⇒ 互联 s0 死锁 |

### 5.1 BRAM 二次腾挪（只在"XLR 过了但 BRAM 爆"或 PnR 容量失败时做）

`tools` 侧已有实测标定（`docs/BRAM资源优化方案.md`）：

| 动作 | 省 | 类型 | 说明 |
|---|---|---|---|
| **R1** `RD_FIFO_DEPTH 1024→512` | −6 | 纯 RTL | **✅ 已落地**（`mmt_top.v:749` 已经是 512） |
| **R2** SoC `OCRSize 32768→16384` | −16 | 重生成 SoC IP | 需 `regen_soc.py` + 固件重编（32KB→16KB，**注意固件体积**：当前 6752 B + 栈，16 KB 仍够但要复核） |
| **R5** SoC `ICache/DCache 4096→2048` | −4 | 重生成 SoC IP | 同 R2 |

> R2/R5 会重生成 SoC IP，属于"有风险的一次性动作"。
> **先看本轮 `verify` 的 ① 结果**：若 BRAM ≤ 256 就不要做，省下的风险留给摄像头出图后。

### 5.2 若 ice=0 仍救不回写通路 ⇒ 换 Efinity 2025.2（零代码改动）

这是你 10-16 提交里自己给出的**最高概率**路径：同一份厂商工程在 2025.2.288 上综合是对的。
做法与风险：

1. 另装 2025.2，**不要覆盖** 2026.1（保留现在能出 HDMI 的环境）；
2. **先在副本上验证 IP 兼容性**：本工程用了 TinyML 5.15 / SoC 3.4.0 / CSI 5.6 / 互联 5.6。
   2025.2 打不开某个 IP 时会报版本错 —— 那就先只做"最小复现件"（`D:\FPGA\易灵思\工作区\08_Efinix复现件\`）证明写通路在该版本正常，作为报障材料；
3. 厂商基线就在 2025.2，**这条路的成功概率最高**，代价是环境切换时间。

> 判断顺序建议：**本轮 ice=0+剪 TinyML 一次构建 → 若 OK 就直接出图，别再折腾版本；若否再上 2025.2。**
> 因为换版本是"未知时长"，而这一轮是"确定性 15 分钟"。

### 7.1 TinyML 怎么"体面地"加回来

现在摘掉的是**当前零 yield 的配置**。加回来推荐两条路，**都比现在省**：

| 方案 | 做法 | 资源账 |
|---|---|---|
| **A. 瘦身 TinyML** | `TINYML_CACHE ENABLE→DISABLE`（−22 BRAM）、`IN_PARALLEL 8→4`（−4 BRAM，+6 DSP） | BRAM 33→7 左右；XLR 仍是大头（15.6k） |
| **B. 软件侧推理** | 用 SoC（RISC-V）跑一个**小到能塞进 32KB 片内 RAM 的模型**（如 2 层卷积 + 1 层全连接的手势/人体分类），输入用已有的 160×120 帧差 + 降采样 | 0 XLR 增量；需要量化 + 定点推理代码 |

> 赛题对"网络 ≤5 层卷积 + 2 层全连接、参数 100K 以内"是**【技术要点提示】的建议**，不是硬红线（见 `docs/赛题完成度看板.md` 的注）。
> 所以 **B 方案在评分上是站得住的**，而且它把"RISC-V + AI 推理"这条叙事做成了"软硬协同"。A 方案更适合要展示硬件加速的场面。

### 7.2 一个必须提前想清楚的风险

`AXI 互联` 现在仍按 **3 主口**配置，s2 常年空闲。出图之后若要加任务3 第三项（如以太网 RGMII），
**不要再往这个互联上加第 4 个主口** —— 先算 BRAM（当前最紧），并优先考虑"复用 s2"或"以太网走独立小互联"。

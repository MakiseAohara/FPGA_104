## 4. ⑤ 低功耗场景管理 —— 原文定义与最小实现

**原文定义**（`_易灵思.txt:268-269`）：

> **低功耗场景管理**：无人时进入低功耗模式（**降低摄像头帧率、关闭神经网络推理、保留温度监测**）；检测到人体后自动恢复正常模式。

拆开看，三项里**两项现在天然满足**：
- "关闭神经网络推理" —— TinyML 本来就是 `DISABLE`（`ip\tinyml\tinyml_core0_define.v`）
- "保留温度监测" —— 传感器轮询本来就在跑

**真正缺的只有"模式切换"本身**：

| 要做的事 | 落点 | 工作量 |
|---|---|---|
| 一个"有人/无人"状态机（输入 = 运动标志和/或融合得分） | 固件 `main.c` 主循环 | 小 |
| 无人态：降传感器轮询率、关帧差使能、LED 慢闪 | 固件写 `MMT_CTRL` / 传感器周期 | 小 |
| 有人态：恢复全速 | 同上 | 小 |
| 状态可观测（串口打印 + OSD 一行字） | `main.c` 遥测 | 小 |

**结论**：⑤ 是**固件级改动**，不需要动 RTL，验证成本低。这是投入产出比最高的一项。

## 7. 上板纪律（踩过的坑，逐条都是真事）

1. **烧录用 `tools\flash_mmt.ps1`** —— 文档里那段裸命令在干净 shell 里**跑不起来**
   （缺 `PYTHONHOME` → `No module named 'encodings'`；再缺 `EFXPGM_HOME` → `KeyError`）。
2. **必须先开 `serial_daemon.ps1` 再上电** —— 上次"上过板但没截串口日志"，结论无法复现。
3. **FTDI 驱动 `ftdibus`/`ftdiport` 必须同版本 2.12.36.4**，否则蓝屏 `0x000000FC`（踩过两次）。
4. **插摄像头前确认 J2/J3 跳线 = 1.2 V**，断电插拔。
5. **每次构建后跑 `check_wr_path.ps1`**（写通路折叠是静默故障）。
6. 只由一个人跑 Efinity（占满机器）；改完 RTL 必须重跑构建+bitgen，否则烧的是旧位流。

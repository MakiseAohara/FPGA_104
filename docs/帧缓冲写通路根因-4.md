## 0. 结论摘要

### 0.1 收敛判定：**已可判定为"工具侧（Efinity 2026.1.132）不可解释的误优化"，但还差最后一个可解释的嫌疑需要 1 次实验排除**

**判定为误优化的证据（全部是 Lead 实测 + 我的 RTL 逐拍推导）：**

1. **Y1**（把 `fb_awvalid` 与 `soc_ddr_awvalid` 在互联拼接里对调）⇒ `fb_awvalid` **仍被折**、`soc_ddr_awvalid` 不折 ⇒ **折叠跟着信号走，不在互联端口上**（否掉 task-14 的 S1）。
2. **Y2**（把 `fb_awvalid/fb_wvalid/fb_wlast` 引到 `led[1]` 给它可观测消费者）⇒ **仍被折** ⇒ **不是"不可观测"**（否掉 task-13 的"甲"假设）。
3. **Z1**（`checker0.i_clk` 从 `i_mipi_rx_pclk` 换成 `core_clk`）⇒ 仍被折 ⇒ 不是写侧时钟域问题。
4. **Z2**（给 `state`/`wr_req` 加 `(* preserve, syn_keep=1 *)`）⇒ **逻辑保住了**（`ddr_wr_buffer_inst` XLR **77→189**、`state` 不再出现在折叠报告），**但 `fb_awvalid` 仍被证成常量 0、mem 仍 0** ⇒ **工具在"逻辑被保住"的前提下，依然'证明'了 `awvalid ≡ 0`**。
5. **X1**（`.wr_start(1'b1)`）⇒ `state` 仍 `optimized to 0`。而按 RTL（`ddr_wr_buffer.v:119-125` + `:402-442`）逐拍推导，`wr_start≡1` 时 `start_sync` 走 `00→01→11→11…`，`pos_sync` **必然出现 1 拍**、`sync_r2` 随之出现 1 拍 ⇒ **`state` 必然是常量 `2'b01`**（推导表见 §1.3）。**报告说 0 ⇒ 与 RTL 语义矛盾。**

**⇒ 结论（推断，强度：高）**：在 RTL 语义下**已不存在任何能证明 `state ≡ 0` / `awvalid ≡ 0` 的条件**（`rst_n` 已在 10/12 修好、`wr_start` 在 X1 里被钉成 1、输出在 Y2 里被观测、逻辑在 Z2 里被 preserve），工具仍然折叠它 ⇒ **误优化**。

### 0.2 但还剩下**唯一一个"可解释"的嫌疑**，必须用 §2 的结构实验排除

`ddr_wr_buffer.v:408` 的这一支：

```verilog
:402  always @( posedge axi_clk or negedge rst_n )
:404      if( !rst_n )            begin awvalid<=0; wvalid<=0; state<='d0; end
:408      else if( sync_r0 )      begin awvalid<=0; wvalid<=0; state<='d0; end   // ← 优先级高于 case
:412      else begin
:413          case(state )
:414          2'd0 : if( sync_r2) state <= 2'd1;
```

**`sync_r0` 那一支对 `state` 的复位优先级高于 `case`。** 如果工具把 `start_sync`（`:119-123` 的 `{start_sync[0], wr_start}` 移位寄存器）的**稳态值**当成它的初值：

- `wr_start` 是**电平**（例如 X1 的恒 1）时，`start_sync` 的稳态是 `2'b11` ⇒ 工具认为 `pos_sync ≡ 0` ⇒ `sync_r0 ≡ 0`、`sync_r2 ≡ 0` ⇒ **`state ≡ 0`** ✔ 解释了 X1；
- 反之若工具把 `start_sync` 判成恒 `2'b01` ⇒ `pos_sync ≡ 1` ⇒ **`sync_r0 ≡ 1` ⇒ `state` 被无条件按在 0** ✔ **同样解释 X1，并且同时解释 Z2**（preserve 保住了 FF，但 `sync_r0` 恒 1 ⇒ `state` 恒 0 ⇒ `awvalid` 恒 0）。

**⇒ 这是唯一还能"用 RTL 解释"X1+Z2 的机制。** 它是**结构问题**（边沿脉冲式启动链），因此 §2 的实验正好就是"改结构"。

### 0.3 唯一实验（详见 §2）：把 FSM 的启动从"边沿脉冲"改写成"电平"，并让 `sync_r0` 不再无条件复位

改 `rtl\frame_buffer\ddr_wr_buffer.v` **3 处**（同一处结构性改动）：
- `:408` 屏蔽 `sync_r0` 对 FSM 的复位支；
- `:415` `if( sync_r2)` → `if( sync_r2 | wr_start )`（电平化）；
- （可选强化）`:419` 去掉 `if( wr_req )` 门控，让 `awvalid` 一定能拉起来，使 `fb_awvalid` 这个观测量真正可判。

**判读**：`fb_awvalid`/`state` 不再被折 ⇒ **根因就是边沿脉冲式启动链，且这次改动本身就是修法**；仍被折 ⇒ **工具误优化确证**，转 §3 的绕过方案。

### 0.4 绕过方案排序（若 §2 证实是工具问题，详见 §3）

① preserve 输出端口（Z2 的延伸，代价 XLR +200 以内）→ ② 把 FIFO 读侧做成"工具无法证明无用"的形式 → ③ **换回 Efinity 2025.2 跑这一块**（厂商基线同版本，最可能一次解决）→ ④ 向 Efinix 报 issue（最小复现已具备）→ ⑤ 结构性规避（照厂商让 frame_buffer 直连 DDR3，放弃三主口互联；代价最大）。

### 0.5 BRAM 预算（详见 §4）：**仍建议现在就上 task-5 的 R1+R2+R5（−26）**

- Z2 实测 `ddr_wr_buffer_inst` **XLR 77→189、mem 仍 0** ⇒ **preserve 不改变 BRAM**，所以"修好后写 FIFO 回来 = +13"**依然成立**；
- 但 **CSI RX 的 32 块**（现 4 vs 厂商 36）是否跟着回来**仍未确认**（最新那一轮 `Memory Blocks` = **218**，比 baseline 222 还少 4，说明**还没回来**）；
- 因此最坏仍是 **+13 +32 = +45 ⇒ 267 > 256（装不下）**；**现在就上 −26 的削减，196 → 209 / 241 两种结局都装得下**。

### 1.2 `vid_rst_n` 这条修复：既重要又**不足以**解释现在的折叠（**实测 + 推断**）

Lead 在 `mmt_top.v:1135-1145` 写明：删掉 DSI TX ⇒ `panel_config` 的 AXI 无从设备 ⇒ `o_confdone` 永不置位 ⇒ 原 `else if( w_confdone )` 使 `dly_cnt` 不计数 ⇒ **`vid_rst_n` 曾恒 0** ⇒ 整条视频链被永久按在复位态。现改为（`:1146-1154`）：

```verilog
always @( posedge vid_clk_dvi2 or negedge w_arstn ) begin
  if( !w_arstn ) dly_cnt <= 'd0;
  else           dly_cnt <= dly_cnt[26] ? dly_cnt : (dly_cnt + 1'b1);
end
assign vid_rst_n = dly_cnt[26];
```

⇒ 现在 `vid_rst_n` 由 `vid_clk_dvi2` 上的自由计数器产生，**是活寄存器**（不再恒 0）。

**这条修复是对的方向**（它确实是一条真缺陷：不修的话上板视频链永远不出复位），**但实测折叠仍在** ⇒ **`vid_rst_n ≡ 0` 不是（唯一）原因**。需要 Lead 在干净一轮上确认 `vid_rst_n` 现在真的活了（判据见 §1.4）。

> 备注（**无法确认**）：`vid_rst_n` 修复后的那一轮 `Memory Blocks` 从 222 变成 **218**（`out\mmt.place.rpt:339`；`map.rpt` 头 = `Oct 12 18:38:26`）。方向是**减少** 4 块，不是增加——与"写通路复活"相反。是哪 4 块、为什么少，需要 Lead 在干净一轮上用 `res.csv` 逐项对比（我不在报告可读窗口内）。

### 1.3 X1 与 RTL 语义的矛盾（逐拍推导，**可核对**）

相关 RTL（**已逐行核对当前文件**）：

```verilog
rtl\frame_buffer\ddr_wr_buffer.v
:119  always @( posedge axi_clk or negedge rst_n )
:121      if( !rst_n )  start_sync <= 'd0;
:122      else          start_sync <= {start_sync[0], wr_start};
:125  assign pos_sync = start_sync[1:0] == 2'b01;
:127-140  sync_r0 <= pos_sync; sync_r1 <= sync_r0; sync_r2 <= sync_r1; sync_r3 <= sync_r2;
:408  else if( sync_r0 ) begin awvalid<=0; wvalid<=0; state<='d0; end
:414  2'd0 : if( sync_r2) state <= 2'd1;
```

`wr_start ≡ 1'b1`（X1）时的状态序列：

| 拍 | `start_sync` | `pos_sync` | `sync_r0` | `sync_r2` | `state` |
|---|---|---|---|---|---|
| 复位 | 00 | 0 | 0 | 0 | 0 |
| E1 | 01 | **1** | 0 | 0 | 0 |
| E2 | 11 | 0 | **1** | 0 | **0**（被 `:408` 拉回） |
| E3 | 11 | 0 | 0 | 0 | 0 |
| E4 | 11 | 0 | 0 | **1** | **1** |
| ≥E5 | 11 | 0 | 0 | 0 | **1（永久停在 1）** |

⇒ **`state` 必然是常量 `2'b01`**，工具应当报 `state[1] optimized to 0`、**`state[0] optimized to 1`**。X1 实测两份都是 0 ⇒ **与 RTL 矛盾**。
⇒ **只有两种可能**：**(a)** 工具对"复位释放后的单次瞬态"做了不健全的稳态推理（§0.2 的机制）；**(b)** 工具误优化。
**两者都是工具侧问题，且 (a) 可以用 §2 的结构改动直接规避**（把边沿脉冲改成电平 ⇒ 不再依赖瞬态）。

## 2. 唯一实验：把 FSM 启动从"边沿脉冲"重写为"电平"（**改结构**）

> 这是本轮**唯一**建议 Lead 跑的实验。它不是"钉输入"：它改的是 **FSM 的启动机制与优先级结构**，并且**如果成功，这个改动本身就是修法**（电平式启动比"每帧一个单拍脉冲"鲁棒得多，也不依赖 `start_sync` 的复位瞬态）。

### 2.1 改哪 3 行（`rtl\frame_buffer\ddr_wr_buffer.v`）

```verilog
// ── (1) :408  屏蔽 sync_r0 对 FSM 的"无条件复位"支（它是 state 的最高优先级复位）
//     原：  end else if( sync_r0 ) begin
//     改：  end else if( 1'b0 ) begin          // 诊断：只屏蔽这一支，复位(!rst_n)那一支保留

// ── (2) :415  把 state 0 的入口从"边沿脉冲 sync_r2"改成"电平 wr_start"
//     原：              if( sync_r2)
//     改：              if( sync_r2 | wr_start)

// ── (3)〔可选强化，只为让 fb_awvalid 这个观测量可判〕:419  去掉 wr_req 门控
//     原：  2'd1 : begin if( wr_req ) begin state <= 2'd2; awvalid <= 1'b1; end  wvalid <= 1'b0; end
//     改：  2'd1 : begin state <= 2'd2; awvalid <= 1'b1; wvalid <= 1'b0; end
```

**改动 (2) 的语义**：只要 `wr_start` 还是高电平，`state` 就可以离开 0；不再依赖"复位释放后恰好出现的那一拍脉冲"。
**改动 (1) 的语义**：`sync_r0` 原来会在 `pos_sync` 后一拍把整个 FSM（含 `awvalid/wvalid`）清零；屏蔽它后，"边沿检测链"的瞬态不再能把 FSM 按回 0。
**改动 (3) 的语义**：让 `awvalid` 在 RTL 里**一定**会被拉起来（不再依赖 FIFO 里有没有数据），这样 `fb_awvalid` 从"可能恒 0"变成"RTL 语义上必然有 1" ⇒ **判据变成强判据**。若只想保持功能语义接近真实修法，可以先只做 (1)+(2)，把 (3) 留作第二阶段。

### 2.2 预期（逐项给出"看哪里、怎么变"）

| 观测量 | 位置 | 若"根因=边沿脉冲式启动" | 若"确实无解（工具误优化）" |
|---|---|---|---|
| `ddr_wr_buffer_inst/state[0]` | trimming 报告（baseline 那轮在 `:3564`/`:3636` 附近，以最新一轮为准） | **不再 `optimized to 0`**（很可能变 `optimized to 1`，因为 `wr_req` 仍可能恒 0） | **仍 `optimized to 0`** |
| `'fb_awvalid'` | trimming 报告（baseline 轮 `:3561`） | **不再被折**（尤其是做了 (3) 之后） | **仍被折** |
| `+ddr_wr_buffer_inst:ddr_wr_buffer(...)` 的 RAMs 列 | `out\mmt.res.csv`（baseline 轮 `:129`，值 `0(0)`） | **0 → 13**，并出现 `+u_wr_fifo:DC_FIFO(FIFO_DEPTH=1024)` 行 | 仍 0 |
| `+checker0:frame_buffer(...)` 的 RAMs 列 | `out\mmt.res.csv`（baseline 轮 `:118`，值 15） | **15 → 28** | 仍 15 |

### 2.3 它证明什么 / 不证明什么 / 要不要还原

- ✅ **证明**：折叠是否由"边沿脉冲式启动链（含 `sync_r0` 的整体复位支）"驱动。若 (1)+(2) 就让它复活，那就**同时是修法**。
- ❌ **不证明**：`wr_start`（`frame_start & frame_stable`）在真实运行下会不会真的周期性为高——那是视频输入侧的事，与本实验正交（本实验已证明折叠对视频输入不敏感）。
- ❌ **不证明**：`axi_interconnect` 侧是否有别的问题（Y1 已把端口维度的嫌疑排掉）。
- **要不要还原**：
  - 若**复活** ⇒ **(1)+(2) 请保留**（这是结构性修复；建议把 `if( sync_r2 | wr_start )` 写成注释说明"电平式启动，避免依赖复位瞬态"），(3) 若做了要**还原**（它会让 `awvalid` 无条件拉起，功能不对）；
  - 若**仍全折** ⇒ **全部还原**，按 §3 走绕过方案。

### 2.4 为什么选它（而不是别的结构改动）

| 候选结构改动 | 为什么不选 |
|---|---|
| 给 `sync_r0`/`sync_r2` 加 preserve（Lead 建议的方向之一） | Z2 已经证明 preserve 能保住逻辑但**保不住**"证明"——输出仍被证 0。preserve 只是把逻辑留下，不改变工具的证明 |
| 顶层把 `wr_start` 做成"每 vsync 一次脉冲"（恢复厂商语义） | 这仍然是**喂输入**（本次已证明折叠对输入不敏感），且要同时打通 `frame_info_det.frame_cnt`，改动面大、结论不干净 |
| `checker0` 写通道直连 DDR3（绕开互联） | 需要改约 40 根线（DDR3 只有 1 个 AXI 从口，s1/s2 还要用互联）⇒ 不是最小改动，且会同时改变 s1/s2 |
| **改 FSM 启动结构（本文选择）** | ✅ 1 个文件、3 行；直接命中"唯一还能解释 X1+Z2 的机制"；成功即修法；失败即**把"工具误优化"钉死** |

## 3. 工程化绕过方案（若 §2 证实为工具误优化）

按"代价从低到高"排序。**代价估计基于 Z2 的实测标定**（`state`/`wr_req` 加 preserve ⇒ XLR 77→189，即单模块 +112 XLR；BRAM 不变）。

| 顺序 | 方案 | 具体做法 | 预期代价 | 预期效果 |
|---|---|---|---|---|
| **①** | **把写通道的关键输出与 FIFO 读侧一起 preserve** | 在 `ddr_wr_buffer.v` 给 `awvalid`/`wvalid`/`wlast`/`wdata`/`awaddr`/`awlen`/`wr_req`/`state` 加 `(* preserve, syn_keep=1 *)`；在 `DC_FIFO.v` 或实例处给 `FifoRdData`/`RdEn` 同类属性（`DC_FIFO.v` 是厂商原件，建议只在 `ddr_wr_buffer.v` 的**实例端口层**处理，避免改厂商文件） | XLR +200~400（Z2 单模块 +112，全链 ×2~3）；BRAM 不变或 +13 | 依赖工具的 `preserve` 是否也作用于"常量传播"。**Z2 显示单独 preserve 寄存器不够**，必须同时覆盖输出端口，成功概率中等 |
| **②** | **把 FIFO 读侧做成"工具无法证明无用"的形式** | 例如 `assign wdata = wr_fifo_rddata` 之前插一级 `(* preserve *)` 寄存器；或给 `wr_fifo_rdusedw` 加一路"必然被用到"的观测（如把它的 LSB 异或进一个调试输出） | XLR +130 左右（一级 128 位寄存器）+ 少量 | 破坏"FIFO 无用"的证明链。成功概率中等偏低（工具可能仍从上游证下去） |
| **③** | **换 Efinity 版本跑这一块** | 用 **2025.2.288.3.8**（= 厂商基线同版本）重跑 `efx_map`；或至少把该模块单独做 OOC 综合对比 | 环境切换成本；工程本身 0 改动 | **成功概率最高**（厂商 2025.2 的 build 里同一 FIFO 13 块、CE 齐全）。风险：2025.2 是否支持本工程的其它 IP（TinyML 5.15 / SoC 3.4.0 / CSI 5.6）需先验证 |
| **④** | **向 Efinix 报 issue** | 最小复现已具备：`ddr_wr_buffer.v` + `axi_interconnect` + 三主口 + 一个 `1'b1` 的 `wr_start`（X1 的复现件）即可让对方看到"`state` 应恒 1 却被优化成 0" | 时间成本 | 根治；也可能拿到官方 workaround（如某个 `-opt` 开关） |
| **⑤** | **结构性规避（照厂商拓扑）** | 让 `frame_buffer` 的 AXI **直连** DDR3 控制器（放弃三主口互联），或把写通道改成不经 FIFO 的直通 skid buffer | 架构改动 + BRAM/时序全部重估 | 最稳但代价最大；且会牺牲 SoC/TinyML 走 DDR 的能力 |

**建议路径**：§2 实验 → 若否 ⇒ 先做 ①（一次跑流程就能知道 preserve 是否管用）⇒ 若否 ⇒ 走 ③（换版本）并同时 ④ 报 issue。**⑤ 留作最后手段。**

## 4. BRAM 预算复核与建议

### 4.1 复核"修好后涨 13 还是 45"（**实测 + 算术**）

- **+13 这一项没有变化**：Z2 实测 `ddr_wr_buffer_inst` 的 **mem 仍 0**（preserve 只把 XLR 从 77 抬到 189），说明"写 FIFO 回来 = +13 块"（128b×1024 ⇒ `ceil(131072/10240)=13`，厂商实测 13，`ti60f225_oob.res.csv:128`）**仍成立**，且**不接受 §3①/② 的 XLR 代价影响**。
- **+45（含 CSI RX 的 32 块）仍未确认**：
  - X3 实测 **222→218** ⇒ 一旦 CSI RX 的输出没人消费，它当场掉 4 块 ⇒ **"CSI RX 的存储随消费者生灭"已被实验证实**；
  - 但 `vid_rst_n` 修好后那一轮仍是 **218**（`out\mmt.place.rpt:339`），比 baseline 222 **还少 4** ⇒ **CSI RX 的 32 块并没有因为复位修好而回来**；
  - ⇒ 最坏情形（写通路修好 + CSI RX 的 32 块一起回来）**仍然要按 267 预留**。
- **现状口径**：以最新一轮为准（我在写本文时读不到完整报告）：`Memory Blocks` = **218/256 = 85.16%**（`map.rpt` 18:38:26 轮）。

### 4.2 建议：**现在就上 task-5 的 R1+R2+R5（−26），不要等 §2 的结果**

| 条目 | 改动 | 省 |
|---|---|---|
| R1 | `rtl\mmt\mmt_top.v:665` `RD_FIFO_DEPTH 1024→512`（读 FIFO 是**活**的那条，收益确定） | **−6** |
| R2 | `ip\sapphire_soc\settings.json:80` `OCRSize 32768→16384` | **−16** |
| R5 | `ip\sapphire_soc\settings.json:70-71` `ICacheSize`/`DCacheSize 4096→2048` | **−4** |
| | **合计** | **−26** ⇒ 基线 196 |

**三种结局都装得下**：196 →（+13）**209 = 81.6%** →（+45）**241 = 94.1%**。
**不削减的话**：只要 CSI RX 的 32 块跟着回来就是 **218+45 = 263 → 102.7%**（或按 222 起算是 **267 → 104.3%**）⇒ **工程直接不收敛**。

**留作后手（不要现在做）**：`TINYML_CACHE ENABLE→DISABLE`（−22）—— 代价是推理时权重全走 DDR、明显变慢。

**执行顺序建议**：先跑 §2（1 个实验、2~3 分钟）；**无论 §2 结果如何，R1+R2+R5 都建议在同一个批次里上**（R1 纯 RTL，R2/R5 要重生成 SoC IP 并涉及固件，宜同批）。这样"写通路修好"这件事就不会再被 BRAM 容量卡住。

# 上板判据：最大写地址 FB_AWADDR_MAX（task-22）

> 目的：给"**帧步长修复（960 vs 1920）到底进没进位流**"一个**硬件判据**。
> 现有 `[WR]` 行只统计握手次数 —— **握手发生了 ≠ 地址对**。
> Claude 审查指出的另一个坑：**"最大地址读到 0" 不等于 "没越界"**（没出图时它就是 0），
> 所以本寄存器**必须配一个采样/有效标志联合读**。
>
> 写权限遵守：只写 `rtl\mmt\soc\mmt_soc_regs.v`、`sw\**`、本文档。
> **没碰** `rtl\mmt\mmt_top.v`、`rtl\frame_buffer\**`、`ip\**`。**没跑 Efinity**（位流由 Lead 重编）。
>
> 约定：**【实测】**= 本轮真跑过仿真/真读过文件并给原始输出；**【推算】**= 由实测算出；
> **【推断】**= 有依据无直接证据；没把握写"**无法确认**"。

---

## 0. 一页结论（先看这个）

1. **两个新只读寄存器**（接在 `0xA4` 之后，既有地址一个没动）：

   | 偏移 | 名称 | 内容 |
   |---|---|---|
   | `0xA8` | `FB_AWADDR_MAX` | `[31:0]` = **历史最大 `fb_awaddr`**（只在 `fb_awvalid & fb_awready` 那一拍取样，单调不减、饱和保持） |
   | `0xAC` | `FB_AW_STAT` | `[15:0]` = 采样次数（**饱和**在 0xFFFF）· `[16]` = 至少采样过一次 · `[17]` = 曾采到非 0 地址 |

2. **串口 `[WR]` 行追加**：
   ```
   [WR] AW=..(d=..) W=..(d=..) st=0x.. amax=0x........(d=0x........) asmp=1234 ast=0x3 az=OK FRM=..(d=..) [FS] .. [VW] ..
   ```
   `az=` 是固件**替你算好的结论**，一眼可辨（阈值与 §1 一致）：
   `NOIMG`（没出图）/ `OK` / `SUSPECT` / `OVER1920` / `LOW`。

3. **★ 判据必须联合读**（这是本任务的核心）：
   - `az=NOIMG`（`asmp=0`）⇒ **根本没出图**，`amax=0` **不能**当成"没越界"；
   - `amax=0` **但 `asmp>0`** ⇒ 确实写过、但地址全是 0 —— 那是**真异常**（地址通路问题），
     和"没出图"是两回事。仿真里专门留了这个用例（见 §4.1 的 T1–T4）。

4. **需要 Lead 加 1 个端口 + 2 处连接**（`fb_awaddr` 目前没引进 SoC；`mmt_top.v` 里那根 wire
   已经存在，只是没往下接）。**逐行在 §2。重编位流后才生效。**

5. **`amax` 的 `d=`（增量）大部分时间是 0，这是正常的**：`amax` 是"历史最大"，
   一旦走完一圈（三个 bank 都用过）就稳定不再增长 ⇒ 之后看 **`asmp` 是否在涨**才是"还在写"的证据。
   只有**开机后的头几帧** `amax` 的 `d` 才会是正的。别把 `d=0` 误读成故障。

## 1. 阈值从哪来（引用 `docs\帧步长修复-DDR分区对齐.md` 的实测数字）

`frame_buffer` 例化 `ddr_buffer` 时漏转发 `FB_NUM / MAX_VID_WIDTH / MAX_VID_HIGHT`，
于是 `bank_switch.v` 按 1920 版算帧步长：

| 版本 | `FRAME_LEN = W×H×32/8 + 0x200` | 三个 bank 基址 | 帧内最大地址 |
|---|---|---|---|
| **960（本工程约定）** | `960×1080×4 + 0x200` = **`0x3F4A00`** | `0x02000000` / `0x023F4A00` / `0x027E9400` | `0x029E3000` ✅ |
| **1920（bug 版）** | `1920×1080×4 + 0x200` = **`0x7E9200`** | `0x02000000` / `0x027E9200` / **`0x02FD2400`** | ≥ `0x02FD2400` ❌ |

- 约定区间（文档）：**R5 视频帧缓存 = `[0x02000000, 0x02BDDE00)`**（`0x02000000 + 3×0x3F4A00`）。
- bug 版 bank2 = `[0x02FD2400, 0x031CC800)`，与 **R7 张量区 `0x03000000`** 重叠
  1,886,208 字节 ≈ 1.80 MB ⇒ **只要相机出图就会写坏 AI 张量**。

⇒ 所以判据的分界线就是 **`0x02BDDE00`（约定上界）** 与 **`0x02FD2400`（bug 版 bank2 基址）**：

```
amax <  0x02000000                     → LOW      采到的不是帧缓存地址
0x02000000 ≤ amax < 0x02BDDE00         → OK       ✅ 960 版步长（修复生效）
0x02BDDE00 ≤ amax < 0x02FD2400         → SUSPECT  越过约定区间但没到 bug 版 bank2
amax ≥ 0x02FD2400                      → OVER1920 ❌ 仍是 1920 版步长（在写张量区）
```
（阈值写成固件的 `MMT_FB_AWADDR_MAX` 比较，见 `sw\main.c` 的 `az=` 计算。）

## 2. 需要 Lead 加的（1 个端口 + 2 处连接）

> `fb_awaddr` 在 `mmt_top.v:340` 已声明（`wire [AXI_ADDR_WIDTH-1:0]`，宏 = **32**
> 见 `rtl\ddr3_controller\ddr3_parameter.vh:22`），并且已经接到互联 s0 口与 `checker0`，
> 只是**没有引进 `mmt_soc_subsystem`**。

**步骤 1：`rtl\mmt\soc\mmt_soc_subsystem.v`**

(a) 端口表：在 `input wire fb_wready,`（当前 `:209` 一带，**task-16 加的那 4 行**）之后插入：

```verilog
    // ---- ★ task-22：写通道地址（给"最大写地址"判据用）----
    input  wire [31:0] fb_awaddr,
```

(b) `mmt_soc_regs u_soc_regs (...)` 例化：在 `.fb_wready (fb_wready)`（当前 `:495` 一带，
    **节尾要补逗号**）之后插入：

```verilog
        .fb_wready       (fb_wready),          // ← 这一行末尾补逗号
        // ---- ★ task-22：写通道地址 ----
        .fb_awaddr       (fb_awaddr),
```

**步骤 2：`rtl\mmt\mmt_top.v`**

在 `mmt_soc_subsystem u_soc (...)` 例化里、`.fb_wready  (fb_wready),`（当前 `:1629` 一带）之后插入：

```verilog
    .fb_awaddr  (fb_awaddr),
```

> 锚点以**端口名**为准（行号会漂移）：找 `.fb_awready` / `.fb_wready` 那两处。
> 时钟域：`fb_awaddr` 与 `fb_awvalid/awready` 都在 **core_clk** 域（互联 `.clk(core_clk)`，
> `mmt_top.v:779`；`checker0 .axi_clk(core_clk)`，`:698`），寄存器块也在 core_clk ⇒ **不需要 CDC**。
> **不要回退** task-16/19/22 之外的既有改动（R/B 修复、参数转发等）。

## 3. 判据表

| # | 串口现象 | 结论 | 下一步 |
|---|---|---|---|
| 1 | `az=NOIMG`（`asmp=0` `ast=0x0`） | **没出图**。此时 `amax=0` **完全不能**说明"没越界" | 先查 task-19 的 `[CAM]` 行（`SCL/CK/PCLK/DE` 哪个不动） |
| 2 | `asmp>0`、`amax=0`、`ast=0x1`（seen=1、nz=0） | **写过、但地址全是 0** —— 真异常（不是"没出图"） | 查 `fb_awaddr` 是否被引进 SoC（§2 补丁）、互联 s0 口的地址位、帧缓存基址是否被改成 0 |
| 3 | `az=OK`、`amax ∈ [0x02000000, 0x02BDDE00)`，且 `amax` 的 `d>0`（开机头几帧） | **960 版步长生效** ✅（地址正在往上推进） | 正常 |
| 4 | `az=OK`、`amax` 稳定不动（`d=0`）但 **`asmp` 在涨** | **正常**：历史最大已经饱和（三个 bank 都走过一圈），系统仍在写 | 正常。要判断"是否覆盖到 bank2"，看 `amax` 是否 ≥ `0x027E9400`（960 版 bank2 基址） |
| 5 | `az=SUSPECT`（`amax ∈ [0x02BDDE00, 0x02FD2400)`） | 越过约定区间，但**没到** 1920 版 bank2 基址 | 对着 §1 的表逐位比对：是不是别的 stride 值 / 只修了一半 |
| 6 | `az=OVER1920`（`amax ≥ 0x02FD2400`） | ❌ **仍是 1920 版帧步长** ⇒ bank2 正在写 `[0x02FD2400,0x031CC800)` = **张量区前 1.8MB** | 确认 `frame_buffer.v` 的 3 行参数转发是否在位流里（重编+重烧，见 `docs\帧步长修复-DDR分区对齐.md`） |
| 7 | `az=LOW`（`amax < 0x02000000`） | 采到的不是帧缓存地址 | 查是不是别的主口地址 / 帧缓存基址被改 |
| 8 | **只写了 1 帧的中间态**（`asmp` 很小，例如 1–3，`amax ≈ 0x02000000 + 一帧内偏移`） | 还没轮到 bank1/bank2（bank 是轮转的） | **再看几秒**：`asmp` 涨到几十以后 `amax` 应该到 `0x027E94xx`~`0x029E3000` 之间；若一直停在 `0x0200xxxx` ⇒ bank 轮转没工作 |

**两个附加的交叉校验**（都不需要额外硬件）：

- `asmp` 应恒等于 `min(FB_AW_CNT(0x6C), 0xFFFF)`（两者都数 AW 握手）——**不等就是有 bug**。
- `ast` bit0（seen）应与 `0x74` 的 bit4（`fb_aw_seen`）一致。

## 4. 验证记录（**实测**；不含 Efinity）

### 4.1 仿真：`sw\test\tb_mmt_soc_regs.v` → **45 PASS / 0 FAIL**

```powershell
$env:Path = "D:\iverilog\Library\bin;D:\iverilog\Library\mingw-w64\bin;" + $env:Path
iverilog -g2012 -o tb.vvp D:\FPGA\mmt\rtl\mmt\soc\mmt_soc_regs.v `
    D:\FPGA\mmt\sw\test\tb_mmt_soc_regs.v
vvp tb.vvp
```

task-22 新增的用例（T1–T18，原始输出节选）：

```
  PASS  0xA8 AMAX == 0 at reset = 0x00000000
  PASS  0xAC samples == 0 at reset = 0x00000000
  PASS  0xAC seen(bit16) == 0 => NO IMAGE = 0x00000000
  PASS  T1 AMAX still 0 (addr was always 0) = 0x00000000
  PASS  T2 samples == 21 (we DID write) = 0x00000015        ← ★ amax=0 但确实写过
  PASS  T3 seen=1 while AMAX=0  <-- key distinction = 0x00000001
  PASS  T4 nz=0 (never a nonzero addr) = 0x00000000
  PASS  T5 AMAX == 0x02000000 = 0x02000000
  PASS  T8 AMAX holds on smaller addr = 0x02000000          ← 单调不减
  PASS  T10 AMAX == 0x023F4A00 (960 bank1) = 0x023f4a00
  PASS  T11 AMAX == 0x02FD2400 (1920 bank2!) = 0x02fd2400    ← 坏位流会暴露成这个值
  PASS  T12 AMAX unchanged by addr=0 = 0x02fd2400            ← 地址 0 不污染最大值
  PASS  T13 samples == 26 = 0x0000001a                       ← 采样照常累加
  PASS  T15 AMAX ignores valid-without-ready = 0x02fd2400     ← 未握手不采样
  PASS  T17 0x6C AW_CNT grew by exactly 5 = 0x0000001a        ← 与握手计数一致
  PASS  T18 0x74 aw_seen(bit4) == 1 = 0x00000001
=== RESULT: PASS 45 / FAIL 0 ===
```

覆盖了任务要求的全部四点：**复位为 0 / 单调不减 / 只保留历史最大 / 既有寄存器不受影响**，
另加：地址 0 不污染最大值、未握手不采样、与 `0x6C` 握手计数一致。

> 本轮还顺带跑了 task-19 的探针 TB（`sw\test\tb_mmt_cam_probe.v`）：新端口加进去后
> **仍是 39 PASS / 0 FAIL**，说明这次改动没有破坏探针。

### 8. `[CAM]` 判读纪律（这些坑全踩过）

- `PCLK` **一直在涨且毫无意义**（它是 PLL 输出），只能当参照尺；要看摄像头有没有动请用 `CK/PCLK` 比值
- `SCL(d=0)`、`wc(d=0)` 是**正常现象**（配置已发完 / 只有包头）；要看 **SCL 总数**和 **ACK 数**
- `FRM` 是**显示读**通路，不是摄像头
- `fifo_rd_empty` 不能当证据；`d=` 没有固定时间基准；`amax=0` ≠ 没有溢出
- 分界线：**SCL 有总数但 ACK=0** 或 **HS_ENA 恒 0** ⇒ 硬件侧（排线 / 供电 / 复位脚 / 跳线）；**HS_ENA 拉起但 de/vs 不动** ⇒ IP 内部或工具版本（我们与厂商摄像头 demo 唯一的实质差异是 **Efinity 2026.1.132 vs demo 的 2024.1.163**，而 2026.1 已知会误折写通路）

## 3. Lead 必须在 RTL 侧配合的 3 件事（**硬前提**，peri 侧无法替代）

### 3.1 `led` 必须缩成 `led[1:0]`

- 现状：`rtl\mmt\mmt_top.v:176` `output [3:0] led`；驱动在 `:1812`。
- 本轮已在 peri 里删掉 `led[2]`/`led[3]` 并把 `bus msb` 改成 1。
- ⇒ 如果 RTL 仍是 `[3:0]`，下一次流程会多出 **2 个未分配引脚**（`led[2]`、`led[3]`）。请把 `:176` 改成 `output [1:0] led`，并确认 `:1812` 的赋值按 2 位截断（`alarm_led[1:0]`）。
- 备选（若想保留 4 个灯）：板卡还有 LED2=`GPIOL_P_12`(G3)、LED3=`GPIOL_P_02_CSI`(N2)，但它们在 **1.8V bank**，与 `led[0]/led[1]` 的 3.3V 不在同一电平，同一个 `led` 总线里混电平有风险 —— 本次**没有**采用。

### 3.2 SPI 的两根双向脚必须改成厂商写法（**否则 SPI 通路是错的**）

- 现状（本轮 Lead 新加的）：`mmt_top.v:198-199` 把 `system_spi_0_io_data_0/1` 声明成 **inout 端口**，并在 `:1444-1450` 用连续赋值手工做三态：
  `assign system_spi_0_io_data_0 = ..._writeEnable ? ..._write : 1'bz;` / `assign ..._read = system_spi_0_io_data_0;`
- 厂商参考设计**不是**这么写的：`edge_vision_soc.v:176-185` 直接暴露 8 个单向端口，**没有** inout 端口、**没有**手工三态：
  ```
  output wire system_spi_0_io_sclk_write,
  output wire system_spi_0_io_data_0_writeEnable,
  input  wire system_spi_0_io_data_0_read,
  output wire system_spi_0_io_data_0_write,
  output wire system_spi_0_io_data_1_writeEnable,
  input  wire system_spi_0_io_data_1_read,
  output wire system_spi_0_io_data_1_write,
  output wire system_spi_0_io_ss,
  ```
  三态由 peri 的 pad（`input/output/output_enable_config`）实现。
- 为什么必须改：peri 的 pad 是按**信号名**绑定的（见 §2.1 的实证），所以
  1. pad 会正常建在 M1/L1 上，OUT 来自 `..._write`、OE 来自 `..._writeEnable`、IN 送到 `..._read`；
  2. 但 RTL 里那两个 inout 端口 `system_spi_0_io_data_0/1` 不会被任何 pad 绑定 ⇒ 下一次流程会变成**新的 2 个未分配引脚**，而且它们是 MOSI/MISO 的第二个 pad（随机落在一根空闲脚上）⇒ **flash 实际读不到数据**。
- 改法（建议直接照抄厂商）：删掉 `:198-199` 两个 inout 端口、删掉 `:1437-1450` 的 6 条 assign，改成上面那 8 个单向端口（`_read` 是 input，由 pad 驱动；`_write/_writeEnable` 是 output）。peri 侧不用再动。
- 风险提示：如果不改，除了 2 个未分配引脚，还可能报 "multiple drivers / constantly driven from multiple places" 类错误 —— 这是本轮最需要 Lead 拍板的一条。

## 4. `pll_inst4_RSTN`：它是什么，为什么不能分配引脚，怎么消除

**它是什么**：`mmt_top.v:78` 声明了 `output wire pll_inst4_RSTN`、`:79` 声明了 `input wire pll_inst4_LOCKED`，但**全文件（1817 行）再没有第二处引用**（grep `pll_inst4` 只有这两行）。这是从板卡包原始顶层 `rtl\ti60f225_oob_top.v:54-55` 抄过来的"模板残留"：`pll_inst4` 是 peri 里的 PLL_BR0（`mmt.peri.xml:360`，`reset_name=""`、`locked_name=""`），它的 `CLKOUT1` = `CLK_5M` 是**真在用的**（相机 I2C 等），但它的 RSTN/LOCKED 从来没接线。

**证据**：

- `out\efx_map.log:1178`：`WARNING : The primary output port 'pll_inst4_RSTN' wire 'pll_inst4_RSTN' is not driven. [EFX-0256]`
- `out\efx_map.log:2212`：`mmt_top.v(79): Input/inout port pll_inst4_LOCKED is unconnected ... [VDB-8003]`
- `out\efx_pnr.log:54`：`WARNING : IO cell "pll_inst4_RSTN" has no assigned placement; it will be placed randomly`
- `out\mmt.place.rpt:110`：`| pll_inst4_RSTN | Output |`（在 `Unassigned Core Pins` 表里）

**结论**：它是**一个没被驱动的模板端口**，不是板上任何真实信号。

- ❌ **不能**给它随便找个空闲脚分配：没有任何证据表明板上哪根脚是它的，分配错脚上板才炸，代价比不分配大。
- ❌ **不建议**在 peri 里给 `pll_inst4` 补 `reset_name="pll_inst4_RSTN"`（像其它三个 PLL 那样）：那会让 PLL_BR0 的 RSTN **接到一根没人驱动的线上**，`CLK_5M` 可能永远不出复位 —— 拿功能去换一条报告，不划算。
- ✅ **正解（RTL，Lead）**：删掉 `mmt_top.v:78-79` 这两行端口声明。`pll_inst4` 的 `CLK_5M` 输出在 peri 里已经声明（`mmt.peri.xml:369`），删端口不影响它。
  （次要备选：在 RTL 里 `assign pll_inst4_RSTN = i_arstn;` 并同时把 peri 里 `pll_inst4` 的 `reset_name` 设成 `pll_inst4_RSTN` —— 这样它会被当成 PLL 接口信号而不是用户 IO。两条改动**必须成对**，漏一条就出问题，所以不推荐。）

## 5. `i_sensor_scl`：综合期被优化掉，peri 补不回来

**现象**：上一次构建的 `Unassigned Core Pins` 表里有 `i_sensor_sda`，却**没有** `i_sensor_scl`（`out\mmt.place.rpt:102-110`）；`efx_pnr.log:46-53` 的 "IO cell has no assigned placement" 列表同样缺 `i_sensor_scl`。

**根因（实测，不是推断）**：

- `out\efx_map.log:2213`：`mmt_top.v(181): Input/inout port i_sensor_scl is unconnected. Place and route may remove this unconnected port. [VDB-8003]`
- 链路：`mmt_top.v:1629` `.scl_i(i_sensor_scl)` → `mmt_sensor_subsystem.v:99` `.scl_i(scl_i)` → `mmt_i2c_master.v:80` 声明了 `input wire scl_i`，但**全模块再没有用到它**（`:121-376` 只用到 `scl_o`/`scl_oe`/`sda_i`）。
- ⇒ Efinity 判定 `i_sensor_scl` 无负载、把它从设计里摘掉。

**后果**：本轮我在 peri 里照常写了 `io_sensor_scl` 块（`mmt.peri.xml:292-296`，`input_config` 指向 `i_sensor_scl`），但

- `o_sensor_scl` / `o_sensor_scl_oe` 是真实存在的输出 ⇒ pad 会建、`GPIOL_11`(C5) 会被分配；
- `i_sensor_scl` 在设计里不存在 ⇒ 预期它会出现在 `out\mmt.place.rpt` 的 **`Missing Interface Pins`** 表里（**非 required，不会让 PnR 失败** —— 参考 `out\mmt.interface.csv:291` 的 `i_arstn` 就是普通 `input`，而 required 的只有 JTAG/MIPI 硬块，见 `filter_interface.ps1:11-15` 记录的 `Required pin ... is not found` 失败形态）；
- 极端情况：如果 Interface Designer 认为该 pad 三段信号不全而整块丢弃，则 `i_sensor_scl` 会留 1 条未分配引脚。

**怎么办（二选一，Lead 决定，都不影响本轮 peri）**：

1. **推荐**：在 `mmt_i2c_master.v` 里让 `scl_i` 真正有用 —— 例如在 SCL 释放为高时采样它做**时钟拉伸（clock stretching）**检测，或寄到一个状态位供软核读。这样端口有负载、不会被优化、pin 正常分配。（MLX90640/SHT30 正常不拉伸时钟，所以不加也能通信，只是少了从机拉伸保护。）
2. 或者在 RTL 里删掉 `i_sensor_scl` 端口，同时删掉 `mmt.peri.xml:293` 那行 `input_config`（`o_sensor_scl`/`o_sensor_scl_oe` 两块照旧，pad 变纯输出）。

### 11.2 串口实测（COM10 @115200）

```
[VID] lines=1080 pixels=480 frames=3267(d=50) testpat=1     ← 视频在进（内部测试图案）
[CAM] ... DE=696779357(d=10571079) HS=3320953(d=50384) VS=3075(d=46) ... pid=0x4D4D5450 rh=0x00000FFF
[WR]  AW=0(d=0) W=0(d=0) st=0x00 amax=0 ast=0x00 az=NOIMG FRM=1531(d=23)
      dbg=0xA97FFE1F  fsm=0x9003FFF0
[FS]  raw=0x00000000 vis_bit=0x00 t=0x00 e=0x00 sc9=0x00000000
```

**纠一个读法错误（重要）**：`[FS] raw` 读的是寄存器 **0x28 = FUSION_SCORE**（`[31:24]=conf_vision`、`[23:16]=conf_temp`、`[15:8]=conf_env`、`[7:0]=score`，见 `rtl/mmt/soc/mmt_soc_regs.v:373`），**不是帧同步**。它全 0 只说明"当前没有推理输出"，与 `frame_start` 无关，不能当作写通路判据。

### 11.3 真正的判据：`dbg` 粘滞位

| 位 | 含义 | 实测（`dbg=0xA97FFE1F`） |
|---|---|---|
| bit0 | `wr_fifo_wren` 曾经写过 | **1 ✅** |
| bit1 | `frame_start` 曾经置起 | **1 ✅** |
| bit2 | `frame_stable` 曾经置起 | **1 ✅** |
| bit3 | `wr_start`（=frame_start&frame_stable） | **1 ✅** |
| bit4 | `wr_fifo_wrfull` 曾经满 | **1 ✅** |
| bit5 | `sb_pos_sync`（`pos_sync` 曾经有效） | **0 ❌** |
| bit6 | `sb_st1`（写 FSM 进过 state 1） | **0 ❌** |

`fsm=0x9003FFF0`：高位在 `0x9→0xA→0xC→0xF` 之间跳动 ⇒ `axi_clk` 域的 `free_cnt` 在跑（**时钟/复位正常**）；低 4 位 `0xF` ⇒ `pos_sync_cnt` **已饱和到 15**。

**⇒ 上游全通，写 FIFO 都写进去了，只死在 `wr_start` 之后的一级。**

### 11.4 死点与自相矛盾

```verilog
// rtl/frame_buffer/ddr_wr_buffer.v
start_sync <= {start_sync[0], wr_start};      // :123
assign pos_sync = start_sync[1:0] == 2'b01;   // :126  ← 从未成立
sync_r0 <= pos_sync;                          // :136  写 FSM 的起点
```

矛盾：`pos_sync_cnt`（`if(pos_sync && cnt!=15) cnt++`）已经数到饱和 15，而 `sb_pos_sync`（`if(pos_sync) sb<=1`）却是 0。两者**同源同复位**，物理上不可能同时成立 —— 与工程里已写下的注释一致（`ddr_wr_buffer.v:491`「pos_sync_cnt=15 与 sb_pos_sync=0 在 RTL 上互相矛盾 ⇒ 疑似综合/读数问题」）。

结论：**这不是"没启动"，而是 `pos_sync` 之后的时序/读数在某处不自洽**。下一步应直接观测 `start_sync[1:0]` 与 `awready` 两个信号（各加 2 个粘滞位即可，一轮约 5 分钟），而不是继续在综合选项上试。

### 11.5 ★★ 决定性解码：FSM 活着，卡在 `awready`

按 `sw/main.c:1002` 的位表解码 `dbg=0xA97FFE1F`（0xE0 通道，注释称"可信，以此为准"）：

| 位 | 含义 | 实测 | 判读 |
|---|---|---|---|
| [31:24] | 路标常量 | `0xA9` | 位流是新编的 |
| [22:20] | free_cnt[25:23] | 7 | `axi_clk` 在跑 |
| [19:16] | pos_sync 计数 | **15（饱和）** | 帧起始脉冲持续到来 |
| [15:13] | wr_fifo rdusedw[10:8] | 7 | 写 FIFO 接近满（≈1024），数据在等 |
| [12] | wr_req | **1** | 有写请求 |
| [11:10] | **state** | **3** | **写 FSM 在 state 3 正常运转** |
| [9] | **awvalid** | **1** | **AW 请求已发出** |
| [8] | **awready** | **0** | **从端永不应答 ⇒ 死锁在这一级** |
| [7]/[6]/[5] | sb_st3/sb_rden/sb_pos_sync | 0/0/0 | 粘滞寄存器自身被优化，与 live `state=3` 矛盾 ⇒ **不可作判据** |
| [4:0] | wrfull/wrstart/fstable/fstart/wren | 31 全 1 | 上游全通 |

**结论改写**：`ddr_wr_buffer` 的写 FSM 在 ice=0 下**是正常工作的**（state=3、awvalid=1、FIFO 装满待发）。
`AW=0` 的真正原因是 **AXI 互联 s0 口 / DDR3 控制器从端从不返回 `awready`** —— 与折叠无关，是另一个独立故障。

> 注意 §11.4 的推理因此作废：`sb_pos_sync=0` 并不代表 `pos_sync` 没发生，而是那个粘滞寄存器本身坏了（live 计数器 15 才是真相）。

### 11.6 下一步（针对 `awready`）

1. 查 DDR3 控制器是否退出校准：`cal_done` / `ddr3_top` 的 AXI 从端 `awready` 是否恒 0（可加一个粘滞位，或看 LED0 慢闪）；
2. 查 `axi_interconnect` 的 s0 口是否被使能、`s0_axi_aresetn` 与 `axi_clk` 是否同域；
3. 若 `cal_done=0` ⇒ 问题在 DDR3 初始化（`mmt.peri.xml` 的 DDR 参数/引脚），与视频通路无关；
4. 若 `cal_done=1` 而 `awready` 仍 0 ⇒ 互联 s0 的 `awready` 连线或复位掉线。

### 11.7 观察方法上的两条教训

- **只信 live 值，不信粘滞位**：本轮 `sb_*` 与 live 计数器矛盾，只看粘滞位会误判"FSM 从未启动"。
- **读寄存器前先看位表注释**：`0x28` 是 FUSION_SCORE（视觉置信度）不是帧同步；`0xE0` 才是写通路粘滞位。

### 11.8 原始建议（已被 11.5 取代，留作记录）


1. 在 `ddr_wr_buffer.v` 加两个粘滞位：`sb_start_sync = |start_sync`、`sb_awready = |awready`，重编重烧（约 5 分钟）；
2. 若 `start_sync` 从不置 1 ⇒ `wr_start` 到 `start_sync` 之间有跨域/极性/复位问题；
3. 若 `start_sync` 置 1 但 `pos_sync` 不成立 ⇒ 是 2 拍移位被优化，需 `(* preserve *)` 或改成 `start_sync[0] & ~start_sync[1]` 的显式边沿；
4. 若 `awready` 从不置 1 ⇒ 回到 AXI 互联 s0 口死锁（与 frame_buffer 无关）。

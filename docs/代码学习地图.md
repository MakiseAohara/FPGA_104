## 1. 一句话 + 全景框图

**一句话**：摄像头（MIPI CSI-2）→ DDR3 三缓冲 → HDMI 显示，同时把降采样灰度图送进硬件帧差法，
与 I2C 传感器数据一起做 60/25/15 加权融合 → LED/蜂鸣器/HDMI 红框报警；Sapphire RISC-V 软核通过一个 APB 寄存器块读写这一切，
并预留 TinyML 加速器（经"自定义指令"控制、经 AXI 读写 DDR）。顶层是 `rtl/mmt/mmt_top.v`（`mmt.xml:9`）。

## 2. 三条数据通路

### 2.1 视频通路（最重要，先吃透）

**走向**（每步都能在 `mmt_top.v` 找到）

1. **CSI RX**：`csi_rx_controller inst_efx_csi2_rx`（`mmt_top.v:559`）。输入 MIPI HS/LP 差分（端口 `:82-132`）；
   字节时钟 `clk_byte_HS = i_cam_ck_CLKOUT`（`:564`），像素时钟 `clk_pixel = i_mipi_rx_pclk`（`:566`），
   输出 `w_mipi_rx_data[63:0]` + `de/hs/vs`（`:617-631`）。
   - 【实测】`i_mipi_rx_pclk` 是**板上 PLL 产生的时钟**（`mmt.peri.xml:381,391` USER_PLL 的 out_divider=56；SDC 周期 20 ns，`constr/ti60f225_oob.sdc:21`），
     不是摄像头送来的像素时钟——所以"PCLK 计数一直在涨"没有诊断意义（见 §5.4）。
   - 取像素：`{data[39:32], data[29:22], data[19:12], data[9:2]}` = 4 个 8bit RAW 像素/拍（`:702-704`）。
2. **（可选）测试图案**：`tp_en=1` 时 `mmt_test_pattern` 取代 CSI 的 `vs/hs/de/vin`（`:699-719`），用于**没有摄像头也能自证 DDR 写→读→显示**；
   由寄存器 `0xC8` 控制（§5.3）。
3. **整帧写入 DDR3**：`frame_buffer #(...) checker0`（`:721-799`）。关键参数（`:722-731`）：
   `I_VID_WIDTH=32`、`O_VID_WIDTH=16`、`START_ADDR=32'h02000000`、`FB_NUM=3`、`BURST_LEN=127`、`MAX_VID_WIDTH=960`、`MAX_VID_HIGHT=1080`、
   `WR_FIFO_DEPTH=1024`、`RD_FIFO_DEPTH=512`。AXI 口接互联 s0（`:821-870`），时钟 `axi_clk=core_clk`（`:736`）。
4. **读出**：同一个 `frame_buffer` 的读侧按 HDMI 时序（`H_*/V_*` 端口 `:750-757`）以 `o_clk=vid_clk_dvi2`（70 MHz）吐出 16bit 数据 `{ch0_g,ch0_b}`（`:744-748`）。
   内部结构见 `frame_buffer.v:154-342`（`vid_rx_align_v1` → `ddr_buffer` → `par2ser_parse` → `data_tx`）——**这是外部依赖**。
5. **去马赛克**：`debayer_top_2to1 debayer_top`（`:1096-1112`），输入仍是 RAW（`raw_datax4_i({ch0_b,ch0_g})`），输出 **2 像素/拍 RGB**（`rgb_datax2` 48bit，`:1093`）。
6. **像素展开**：`always @(posedge hdmi_tx_slow_clk)`（`:1120-1131`）用 `vid_cnt` 交替取 `rgb_datax2` 的高/低 24bit，把"70 MHz×2 像素"摊成"140 MHz×1 像素"，得到 `hdmi_tx_{r,g,b}data/vs/hs/de`。
   两个时钟来自同一个 PLL（`mmt.peri.xml:389-390`，out_divider 40 与 20，比例 1:2）。
7. **OSD**：`mmt_osd_overlay u_osd`（`:1423-1452`）叠加热力图/文字/红框，晚 4 拍输出 `osd_*`。
8. **HDMI 编码**：`dvi_encoder dvi_encoder_m0`（`:1311-1335`，**加密**），输出 TMDS 10bit（`:1336-1339` 取反后接 `tmds_tx_*_TX_DATA`）。
   端口对应 `mmt.peri.xml:424-468` 的 LVDS TX。
9. **降采样旁路**：`mmt_video_downscale` 从 `hdmi_tx_*`（debayer 之后、OSD 之前）抽 160×120 灰度（`:1368-1388`），喂算法子系统（见 §2.2）。

**为什么整帧必须过 DDR3**

- **跨域/速率解耦**【实测】：写侧像素域（50 MHz，4 像素/拍）、读侧显示域（70 MHz，输出 HDMI 严格时序）、AXI 域（100 MHz）互不同步
  （`frame_buffer.v:20-28` 三个时钟端口；`mmt_top.v:736-744`）。摄像头帧率与 HDMI 刷新率无需相等，靠帧缓冲吸收。
- **容量**【推断】：一帧 1920×1080 RAW8 约 2.07 MB（1920×1080×1 B）；片上总共 256 块 BRAM（`README.md` §〇 器件容量），而 BRAM 还要给 TinyML/帧差/OSD。
  代码侧证据：`mmt_video_downscale.v:6-9` 明说 1080p 全分辨率背景 RAM "2 MB，不可能放进 BRAM"。
- **多主口共享**：SoC、TinyML 也要读写同一片 DDR3，所以中间有 3 主 1 从互联（`mmt_top.v:315-337`）。
- **三缓冲**【推断】：写/读各占一个 bank，第三个"干净/脏"轮换，避免读到写了一半的帧——逻辑见 `bank_switch.v:97-157`（`dirt_bank/clean_bank`）。

**帧步长 / bank 机制（960 版）**

- 公式【实测】：`FRAME_LEN = MAX_VID_WIDTH × MAX_VID_HIGHT × VID_DATA_WIDTH / 8 + 0x200`（`bank_switch.v:32`），
  其中 `VID_DATA_WIDTH` 实参是 `I_VID_WIDTH`（`ddr_buffer.v:225`）= 32（`mmt_top.v:722`）。
- 960 版：`960×1080×32/8 + 0x200 = 0x3F4800 + 0x200 = 0x3F4A00`。三个 bank 基址 = `0x02000000 / 0x023F4A00 / 0x027E9400`（`mmt_soc_regs.v:291`），
  区上界 = `0x02000000 + 3×0x3F4A00 = 0x02BDDE00`（`mmt_tinyml.h:53`、`main.c:477`）。
- **历史 bug（已修）**：`frame_buffer.v` 曾漏把 `FB_NUM/MAX_VID_WIDTH/MAX_VID_HIGHT` 转发给 `ddr_buffer`，
  于是用默认 1920 算出 `FRAME_LEN=0x7E9200`，bank 基址变成 `0x02000000/0x027E9200/0x02FD2400`，bank2 会写进 TinyML 张量区
  （`frame_buffer.v:189-193`；坏版本基址同见 `mmt_soc_regs.v:290`）。修后真实帧最大写地址 `0x029E37FF`（`frame_buffer.v:193`）。
- 【推断】`0x029E37FF` 恰好等于第三个 bank 基址 `0x027E9400` + 一帧 RAW8 实际字节数 `0x1FA400` − 1：即 stride 是实际数据量的 2 倍（预留余量）。
- 运行时判据：`0xD8/0xDC` 最大写地址寄存器 + 固件的 `az=` 判读（`main.c:492-497`，见 §5.4）。

### 2.2 传感器与算法通路

```
 SHT30(0x44)  ┐                                      hdmi_tx_* ─▶ downscale(160x120 灰度) ─▶ frame_diff ─┐
 MLX90640(0x33)┴▶ i2c_hub ▶ i2c_master ▶ SCL/SDA                                                          │ motion/area/sumx/sumy
        │  (sensor_subsystem)                                                                              ▼
        └▶ 寄存器 0x04..0x14 / 0x4C ──▶ 固件(main.c) ──▶ 写回 0x40 视觉 / 0x44 体温 / 0x54 环境 ──▶ fusion_vote ─▶ alarm
```

- 传感器：`mmt_sensor_subsystem u_sensors`（`mmt_top.v:1724-1754`），`CLK_HZ=100M, SCL_HZ=100k, SHT30 1000 ms, IR 500 ms`（`:1725-1728`）。
  Hub 客户端编号：0=SHT30、1=MLX90640、2=预留（`mmt_sensor_subsystem.v:17-20`），I2C 地址 0x44/0x33（`:31-32`）。
  **传感器尚未采购**，所以这一路只在仿真验证（§6）。
- 帧差：`mmt_frame_diff`（`mmt_algo_subsystem.v:81-104` 例化）。背景帧存 BRAM（`mmt_frame_diff.v:105-116`），差分/阈值（`:87-89`），
  背景更新 `bg += (cur-bg) >> 5`（`:91-94`），一帧结束时锁存 `sum_area/sum_x/sum_y/motion`（`:196-205`）。**质心除法留给软核**（`:12-14`）。
- 融合：`mmt_fusion_vote`，**`score = (v*154 + t*64 + e*38) >> 8`**（`mmt_fusion_vote.v:19` 注释，实现 `:117-122`）。
  温度置信度：画面最高温落在 30.0–38.0 ℃ 为满分，超出线性衰减（`:78-98`）；环境置信度：温度 10–35 ℃ 且湿度 20–80% 为满分，否则 0.5，无数据 0（`:103-112`）。
  报警 = `score >= score_thresh` **且**在"非授权时段"（`:138-148`，窗口判定 `:128-133`，支持跨零点）。
  `mmt_fusion_vote.v:145` 里信号名叫 `in_auth_window`，语义是"处于需要报警的时段"（默认 22:00–06:00，`mmt_soc_regs.v:439-440`）。
- 视觉输入 `vision_prob`：**当前是占位**——固件用帧差面积折算（`main.c:353-354`），不是 AI（见 §2.3）。
- 红外体温 `body_max_c_x10`：**逐点温度换算还是占位**（`main.c:175-186` 的 TODO），Melexis 官方库只在 PC/指令级模拟器上验证过（`sw/lib/mlx90640/`、`sw/test/t_mlx.c`、`tools/rv32sim.py`）。
- 输出：`alg_alarm` 在视频域，同时（a）直连 OSD 画红框（`mmt_top.v:1451`），（b）经 `mmt_sync2` 进系统域（`:1863-1876`）给报警控制与寄存器。
- 报警：`mmt_alarm_ctrl u_alarm`（`:1897-1913`），`event_type` 固定 `3'd1`（入侵）；LED 合并规则 `:1921-1922`
  （报警时两灯同闪；平时 `cnt[25]` 心跳）。顶层 `led` 只有 2 位（`:174`），尽管 `mmt_alarm_ctrl.v:43` 声明 4 位。
- 跨时钟域规则（统一用 `rtl/mmt/common/mmt_sync2.v`，两级触发器，**只适合准静态量**，`mmt_sync2.v:6-14`）：
  - 配置：系统域 → 视频域（`mmt_top.v:1759-1789`）；
  - `bg_clear` 用"翻转电平 + 同步 + 边沿检测"，避免单拍脉冲丢失（`:1791-1804`，寄存器侧 `mmt_soc_regs.v:460`）；
  - 结果：视频域 → 系统域（`:1858-1876`），并多一个 **帧翻转标志** `alg_frame_tgl`（`:1883-1890`）：软核只在它翻转后才信任多比特结果（`main.c:321-333`）。

### 2.3 AI 通路（TinyML）

```
 固件 (sw/mmt_tinyml.c)
   │  RISC-V CUSTOM-0 指令 (opcode 0x0B)        mmt_tinyml.h:58,69-76
   ▼
 Sapphire SoC  cpu0_customInstruction_*          mmt_soc_subsystem.v:330-337
   ▼ ci_cmd_valid / ci_function_id[9:0] / ci_inputs_0/1 / ci_rsp_*   mmt_top.v:416-425
 tinyml_accelerator_channels u_tinyml_accel      mmt_top.v:929-981   (加密核, 看不到内部)
   │ AXI4 主口 128bit (tml_*)                    mmt_top.v:427-464
   ▼ 互联 s2
 axi_interconnect ─▶ ddr3_top ─▶ DDR3  R7 张量区 0x03000000–0x03FFFFFF
```

- **R7 张量区** `0x03000000–0x03FFFFFF`（`mmt_tinyml.h:46-47`），张量按 **128 B 对齐**（硬下限 8 B，`mmt_tinyml.h:48-49`）。
  布局表：权重(300,568 B) / 输入(96×96×1) / 输出(2 B) / arena(1 MB 预算)（`mmt_tinyml.c:22-28`，常量 `mmt_tinyml.h:110-114`）。
- **fail-closed 自检** `mmt_tinyml_check()`（`mmt_tinyml.c:60-93`）：越界/重叠/对齐不足/压到视频区（`0x02000000–0x02BDDE00`）都置错误位；
  `main()` 开机调用 `mmt_tinyml_selftest()`（`main.c:254`）并打印 `[AI] ...` 行（`mmt_tinyml.c:166-189`）。
- **当前固件默认不发命令**【实测】：`MMT_TINYML_PROBE_EN` 与 `MMT_TINYML_ISSUE_EN` 默认都是 0（`mmt_tinyml.c:12-17`），
  `[AI]` 行末尾会是 `probe=off`（`:187`）。原因：自定义指令是**阻塞**的，若加速器没真正应答 CPU 会卡死（`mmt_tinyml.h:31-34`）。
- 指令编码：用 GAS 的 `.insn r 0x0B, func3, func7, rd, rs1, rs2`（`mmt_tinyml.h:69-76`）；`func3=1,func7=0` 为"读加速器配置"（`:80`）。
  `function_id` 内部拼接顺序、参数写/触发语义：**【无法确认】**（加密核，`mmt_tinyml.h:17-20,82-85`）。
- D-cache 一致性：写张量后调用 `mmt_tinyml_flush_dcache()`（`mmt_tinyml.c:113-120`，`.word 0x500F` 是 SoC 自定义缓存维护指令）。
- 中断 `tml_cmd_int` **未接**到 SoC（`mmt_top.v:425` 注释；`mmt_soc_subsystem.v:433` `userInterruptA(1'b0)`）。
  SoC 配置（完整工程 `ip/sapphire_soc/settings.json` 第 75/80/20/61 行）：`DDR=1`、`OCRSize=32768`、`LDSize=16380`、`CustomInstruction=1`。

### 5.2 构建与"装进位流"（**最容易漏的一步**）

```powershell
cd sw
powershell -File .\build_sw.ps1          # 1) 编译：RV32IM、-Os、无 FPU（build_sw.ps1:37-41）
powershell -File .\hex2soc.ps1 -Install  # 2) ★ 装进 SoC 片内 RAM 初始化
# 3) 重跑 Efinity 全流程（综合+布局布线+生成位流），新固件才会进 .bit
```

- **机制**【实测】：固件不是运行时从 flash 载入，而是**综合时**由 SoC 网表用 `$readmemb` 读 4 个文本文件
  `EfxSapphireSoc.v_toplevel_system_ramA_logic_ram_symbol{0..3}.bin` 当作片内 RAM 初值（格式说明 `hex2soc.ps1:10-29`）。
  地址 `4*i+N` 的字节放 `symbolN` 的第 `i` 行，每行 8 个 `0/1` 字符、LF 换行（`hex2soc.ps1:98-114`）。
- `hex2soc.ps1` 自动探测 RAM 大小（读 symbol0 行数×4，`:55-59`；当前 32 KB → 8192 行），生成后**回读逐字节校验**（`:116-135`），不通过非零退出。
- `-Install` 会覆盖**两处**副本：`ip/sapphire_soc/` 与 `ip/sapphire_soc/source/hardware/netlist/`（`:146-157`）。
  只换一处会出现"固件明明重编了但板子跑旧版"。
- **不跑这一步，位流里带的还是上一版固件**；只跑 `build_sw.ps1` 对位流没有任何影响。
- 因为 `ip/` 不在仓库里，你需要先有完整工程的 `ip/sapphire_soc`，`IpDir` 默认值硬编码为 `D:\FPGA\mmt\ip\sapphire_soc`（`hex2soc.ps1:34`）。

**启动流程**：复位向量 `0xF9000000`（`hex2soc.ps1:28`、`mmt_regs.h` 头注释证据）→ `_start`（`startup.S:21`）→ `main()`：
1. 读 `MMT_ID` 必须为 `0x4D4D5401`，否则打印 FATAL 并死循环（`main.c:221-224`）；
2. 写默认配置：帧差阈值 25、最小面积 60、融合阈值 154、授权 22→6 点、当前小时 0（`main.c:231-244`）。**板子没有 RTC，`hour` 恒为 0，等于恒处于报警时段**（`:236-238`）；
3. `mmt_tinyml_selftest()`（`:254`），随后写 3 行 OSD 欢迎语；
4. 主循环（`:280-584`）：SHT30 → MLX90640 → 帧差（用帧翻转门控）→ 视觉占位概率 → 读融合/报警 → 刷 OSD 文字 → 打印遥测 → 空循环节流（`:583`）。

| `0xC0/0xC4` | R | 不映射 | 读 0（探针窗口越界保护，`:53,66-67`） |
| **`0xC8`** | **W/R** | **测试图案** | bit0=使能（0=摄像头，1=图案）；`[2:1]` 模式 0 彩条+方块/1 红/2 绿/3 蓝（`:407,510-518`） |
| `0xCC/0xD0/0xD4` | R | 视频测量 | 每帧行数 / 每行 de 拍数 / 帧计数（`:410,413,416`） |
| **`0xD8/0xDC`** | R | **最大写地址** | `0xD8` 历史最大 `fb_awaddr`（只在 AW 握手拍取样，`:309-314,400`）；`0xDC`=`{nz,seen,采样次数[15:0]}`（`:403`）。**必须联合读** |
| `0xE0+` | — | 预留 | 当前未译码，读回 0（走 `default` 分支 `:421`） |

补充：`0xA8/0xAC` 历史上曾被最大写地址占用，后移到 `0xD8/0xDC`（`:61-67`）；`mmt_regs.h:95-100,124-130` 记录了同一修正。

### 5.4 串口遥测行（115200 8N1，每轮循环打印 4 行 + 开机 1 行 `[AI]`）

| 行 | 来源 | 字段含义与读法 |
|---|---|---|
| `T=… RH=… IR=… score=…` | `main.c:432-436` | 环境温度/湿度/红外最高温/得分（千分位）；报警时行尾 `ALARM!` |
| `ALM= AUTH= EVT= ST= thr= hr= auth` | `:445-453` | `ALM`=0x2C bit0；`AUTH`=bit1；`EVT`=事件类型；`ST`=0x2C 原值；`thr/hr/auth` 是固件**自己记的**写入值（`0x38/0x3C` 是只写） |
| `[WR] AW= W= st=` | `:465-470` | 写地址/写数据握手累计与"本轮增量 d"；`st` 低 6 位同 `0x74` |
| （`[WR]` 行续）`amax= asmp= ast= az=` | `:487-497` | 最大写地址与采样数、粘滞位；`az` 结论：`NOIMG`（还没出图，**不是**没越界）/ `OK`（落在 `[0x02000000,0x02BDDE00)`）/ `SUSPECT`（越过 960 版区上界）/ `OVER1920`（≥`0x02FD2400`，步长仍是 1920 版）/ `LOW`。⚠️ 固件**没有**单独的 `[AMAX]` 标签，它是附在 `[WR]` 行后面的 |
| （续）`FRM=` | `:501-503` | `0x7C`：视频帧翻转累计及增量 |
| （续）`[FS] raw= vis_bit= t= e= sc9=` | `:506-510` | `0x28` 按**真实**位置解码（因截断，`vis_bit` 只有 1 位） |
| （续）`[VW] vis=` | `:511` | `0x78` 的完整 8 位视觉字节 |
| `[CAM] SCL= CK= PCLK= DE= HS= VS= pd= ack= nk= st= wc= wmx= link= pid= rh=` | `:550-575` | 摄像头上游探针。`SCL/ACK/NACK`=摄像头 I2C 活动与应答；`CK`=字节时钟探针（×1024=周期）；`PCLK`=像素时钟探针（PLL 输出，永远涨，**看 CK/PCLK 比值**）；`DE/HS/VS`=CSI RX 在吐像素的证据；`pd`=像素非全 0；`st`=粘滞位；`wc`=word_count **值变化次数**；`pid` 必须是 `0x4D4D5450`；`rh`=复位/HS_ENA 状态 |
| `[AI] layout=… err=… weights@… input@… output@… arena@… probe=off` | `mmt_tinyml.c:166-189` | 张量布局与自检；`probe=off` 表示没发自定义指令 |

判读避坑：`d=` 增量没有固定时间基准（循环靠空转 `main.c:583`），只能比"零/非零"和数量级；`SCL(d=0)` 是配置发完后的正常态；
`wc(d=0)` 正常；`amax=0` 且 `asmp=0` 是没出图；`FRM` 在涨不代表摄像头有帧。更多见 `docs/如何运行.md` §6、§9。

### 7.2 常见坑（带出处）

1. **厂商 vs 自研**：`mmt_top.v` 本身是"厂商 demo 顶层 + 删 DSI + 自研模块"，所以里面混有大量厂商遗留（`panel_config` `:1197`、`color_bar` 注释、MIPI 屏相关 `LCD_*` 端口 `:209-210`）。
   别把"顶层里有"当成"我们设计的"。判断标准：路径在 `rtl/mmt/` 之下的才是自研。
2. **固件没进位流**：见 §5.2，必须 `hex2soc.ps1 -Install` 再重跑 Efinity。
3. **地址图纪律**（最容易出事故）：
   - 帧缓存区 `0x02000000–0x02BDDE00`，TinyML 张量区 `0x03000000–0x03FFFFFF`，固件自检把两者当成互斥区（`mmt_tinyml.c:76-77`）。
   - 张量 128 B 对齐；任何改帧大小/`MAX_VID_WIDTH`/`FB_NUM` 的动作，都要**同时**重算 `FRAME_LEN`、区上界、`main.c:477-497` 的阈值与 `mmt_tinyml.h:51-53`。
   - 互联/加速器/DDR3 控制器**没有可见的越界保护**，越界会静默别名到低地址（`mmt_tinyml.h:28-31`）。
   - 寄存器窗口：`0x80..0xBC` 属于探针，**不要**在此区间再加显式 `case`（会挡死探针，`mmt_soc_regs.v:61-67,345-349`）。
4. **Efinity 会误折帧缓冲写通路**【实测】：一旦 `vid_rst_n` 被卡在 0 或像素侧 FIFO 被判定无用，综合器会把 `fb_awvalid/fb_wvalid/…` 折成常量、写 FIFO 的 RAM 变 0
   （`mmt_top.v:1173-1183` 的现象描述）。防护手段：对写通路关键寄存器加 `(* preserve, syn_keep = 1 *)`——厂商文件里在
   `frame_buffer/ddr_wr_buffer.v:35,48,316,317`（`awvalid`、`wvalid`、`state`、`wr_req`），自研观测寄存器同样加了（`mmt_soc_regs.v:260-265,300-302,324`、`mmt_cam_probe.v:182-185` 等）。
   **每次综合后要检查写通路没被折叠**（`docs/如何运行.md:73-74` 提到的 `check_wr_path.ps1` 脚本**不在仓库里**）。
5. **iverilog 比 Efinity 宽松**：对越界常量索引（如对 12 位信号取 `[15:0]`）iverilog 不报错，Efinity 报 `VERI-1216`（`docs/如何运行.md:92`）；仿真通过 ≠ 能综合。
6. **RAM 写法**：必须"读写分两个 always、读口无条件寄存读、不用 for 循环赋初值"（`mmt_frame_diff.v:20-25`、`mmt_dpram_2clk.v:9-11`）。
7. **CDC**：`mmt_sync2` 只给准静态量用；多比特结果要靠"帧翻转标志"门控（`mmt_top.v:1878-1890`、`main.c:321-333`）。
8. **寄存器读清语义**：`0x0C/0x10/0x24/0x2C` 读一次就清，同一轮循环里不能重复读（`main.c:375` 的注释与 `mmt_soc_regs.v:239-242`）。
9. **新文件要登记 `mmt.xml`**；peri 里的 MIPI DSI 块不能删（会让 Interface Designer 崩），靠 `filter_interface.ps1` 过滤（其 `:4-30`）。
10. **探针读数的误读**：PCLK 恒涨、`SCL d=0`、`wc d=0`、`FRM` 涨都不是"摄像头好"的证据（§5.4）；
    摄像头 I2C 配置**不判 ACK**（`mmt_cam_probe.v:100-101`），"SCL 在跳"≠"传感器响应了"，要看 `ack/nk`。
11. 顶层里"引脚待定"的注释（`mmt_top.v:178-179,188`）已过时，`mmt.peri.xml:292,297,315,322` 已分配。

## 8. 术语表

| 术语 | 一句话 |
|---|---|
| CSI-2 / MIPI CSI | 摄像头串行接口协议；本工程用 4 条数据 lane + 1 条时钟 lane |
| D-PHY | CSI/DSI 的物理层；LP（低功耗 1.2V 单端）与 HS（高速差分）两种模式切换，`HS_ENA/HS_TERM` 控制其使能 |
| RAW / Bayer / RGGB | 传感器输出每像素只有一种颜色；RGGB 是 2×2 的排列；debayer 把它还原为 RGB |
| DDR3 / bank / row / col | 外部动态内存；其内部 8 个 bank（本工程 `BANK_WIDTH=3`）；**与"帧缓冲 bank"是两回事**——后者是 `bank_switch` 管理的三块帧存区 |
| 帧缓冲 bank / 三缓冲 | 把 DDR 划成 3 块，写/读/空闲轮换，避免撕裂；步长 `FRAME_LEN` |
| BRAM / DSP / XLR | 片上块 RAM（共 256 块，写法不对会退化成触发器）/ 硬件乘加块（160 个）/ Efinix 逻辑单元计数单位（60,800） |
| AXI4 | ARM 总线协议（写地址/写数据/写响应/读地址/读数据 五通道）；本工程 DDR 侧 128 位 |
| APB3 | 简易外设总线；`mmt_soc_regs` 是它的从机，0 等待 |
| Avalon-MM | Intel/Altera 的内存映射总线。**本工程不使用**（用 AXI4 与 APB3），列出仅避免混淆 |
| Sapphire SoC | Efinix 的 RISC-V 软核平台（`efx_soc`）；本工程单核 RV32IM、无 FPU、片内 RAM 32 KB |
| 自定义指令 | RISC-V 预留的 custom-0 等 opcode；SoC 把 `func3/func7/rs1/rs2` 直连到加速器命令口，`rd` 取回加速器响应 |
| 张量 / arena / OSD / TMDS | 网络输入输出数据 / 推理中间缓冲 / 视频上叠加图文 / HDMI 的差分编码 |
| CDC / 帧翻转标志 | 跨时钟域（本工程用 2FF + 每帧翻转一次的单比特，让软核知道多比特结果已稳定） |
| `preserve` / `syn_keep` | Efinity 综合属性，阻止工具把寄存器优化掉 |
| `peri.xml` / SDC | Interface Designer 状态文件（PLL、GPIO、LVDS、JTAG、D-PHY）/ 时序约束文件 |

# 现场演示与验收指南

本页用于评委查看当前交付版本。安装软件、连接硬件和载入程序完成后，可按下表进行约 5–10 分钟演示。首次安装、网络配置与下载时间另计。

**本次仓库整理没有新增上板实测。** 2026-11-04 已保存的下载、网络、浏览器和画面刷新记录可在[证据索引](EVIDENCE.md)中复核；下面的现场操作用于记录本次演示结果，不预先将它们标为通过。功能完成范围见[赛题对照](FEATURES.md)，完整构建与运行方法见[复现说明](REPRODUCE.md)。

## 1. 演示前准备

| 项目 | 准备内容 |
|---|---|
| 开发板与摄像头 | Ti60F225 V4、SC431HAI 摄像头；相机排线按开发板资料连接 |
| 显示与供电 | 开发板正常供电；HDMI **实际插好**，显示器选中对应 HDMI 输入 |
| PC 连接 | USB 下载/串口线、网线；确认本机实际 UART 串口名，115200、8N1。`COM15` 只是此前测试电脑的实例 |
| 传感器 | SHT30 和 MLX90640 共用 I²C，地址分别为 `0x44`、`0x33`。当前工程 `io_sns_scl=GPIOL_11`、`io_sns_sda=GPIOL_09`；以 V4 板手册核对排针位置、共地、3.3V 电平和上拉 |
| 蜂鸣器 | 当前 `sns_buzzer=GPIOR_13`。蜂鸣器报警与 SPI 语音模块播报分别验收，不能互相替代 |
| 软件 | 使用预编译交付文件演示需 Efinity Programmer、Python 3；串口工具需 `pyserial`。重新构建另见[当前完整工程](../../project/current/README.md) |

当前引脚依据为[实际位流的接口约束](../../evidence/network_20261104/project_settings/ti60f225_oob.peri.xml)。[历史接线说明](../上板作战计划-2026-10-15.md)提供 J7 排针及 4.7kΩ 上拉参考，但其旧固件操作和旧功能结论不作为当前验收结果。

### 先分清两个地址

| 入口 | 固定配置 | 用途 |
|---|---|---|
| PC 以太网适配器 | `169.254.47.62`，掩码 `255.255.0.0` | PC 监控服务使用此地址 |
| FPGA 网口 | `169.254.47.63` | RISC-V 固件直接提供板内网页 |
| PC 网页 | [http://169.254.47.62:8090/](http://169.254.47.62:8090/) | 同源画面/轨迹镜像，加上 PC 收集的事件 |
| 板内网页 | [http://169.254.47.63/](http://169.254.47.63/) | 不依赖 PC 网页服务提供页面 |

两个 IP 不能配置成同一个地址。只对连接开发板的以太网适配器配置上述地址，保留原上网适配器设置。这些是实验局域网地址，外地评委直接从 GitHub 点击时不会连接到开发板。启动 PC 服务后，若浏览器不能访问，检查本机监听端口及本地网络防火墙设置。

## 2. 确认交付版本并载入

| 文件 | 当前交付标识 |
|---|---|
| [应用固件](../../firmware/tinyml_pdti8.bin) | 438,506 字节；CRC32 `B42CC161`；完整 SHA256 见[固件身份记录](../../firmware/firmware_identity.json) |
| [网络位流](../../firmware/netfix04_rxq2_seed1.bit) | 2,858,286 字节；SHA256 `865458AB2AF51C366AAA2C22DCFA3312F4AB104E90680185BC90F58BDF0E69F5` |

若板上已运行该配套版本，直接进入第 3 节。重新上电或版本不确定时，由演示人员先关闭占用板卡串口的程序，在 Efinity Programmer 中以 **JTAG 临时加载**上述 `.bit`，随后使用下列命令载入 RAM 应用。所有命令均在仓库根目录运行，端口由本机实际枚举结果填写。

```powershell
py -3 -m pip install pyserial
$serialPort = Read-Host '开发板 UART 串口名，例如 COM15'
py -3 tools/load_firmware.py --port $serialPort --image firmware/tinyml_pdti8.bin --out out/review_boot --capture-seconds 15
```

载入工具会等待 `MMT_LOADER_READY`。成功应同时看到 `UPLOAD 438506 B crc32=B42CC161`、`MMT_LOAD_CRC B42CC161`、`MMT_LOAD_PASS DDR_CRC` 和后续应用输出；串口记录保存在 `out/review_boot/serial.log`。若 loader 未就绪，重新确认 JTAG 加载及板卡状态，不向已运行的应用盲发镜像；块 ACK 失败后不要重复发送当前块来猜测恢复。

当前应用还沿用 `MMT_LIVE_BOOT v29.2` 的历史横幅文字，**以实际镜像哈希、载入 CRC 和功能配置识别版本**。最终记录中有 `MMT_FB_LAYOUT base=0x017e9200 stride=8294912 row=1920 bank=1`；[原始下载记录](../../evidence/preview_fps_20261104/board_fw2-loader.log)可供对照。

本交付采用 JTAG 位流加 UART RAM 应用，未写 SPI Flash，**断电后需按上述顺序重新载入**。安装于此前电脑的 Efinity 实际版本为 2026.1.132；没有 Efinity 2025.1 重新构建的验收记录。

## 3. 打开两端网页

先结束上一节的载入工具，再启动监控；同一个 UART 端口只交给一个程序使用。以下命令前台运行，可用 `Ctrl+C` 结束。它从板内 HTTP 镜像画面/轨迹，并通过串口及 UDP 收集事件。

```powershell
py -3 -X utf8 tools/web_monitor.py --port $serialPort --udp 8080 --http 8090 --public-host 169.254.47.62 --board-url http://169.254.47.63 --udp-pixel-encoding uint8 --preview-aspect 16:9 --out out/review_live
```

分别打开 PC 和板内网页，各保留一个演示页面，并使用 `Ctrl+F5` 刷新缓存。现有 `tools/start_network_monitor.ps1` 是此前电脑的快捷入口，其中串口固定为 `COM15`；换电脑优先使用上面的显式参数命令。

两端使用同一份网页，镜像同一算法输出。因请求时刻不同，两个页面的最新帧号可以不同；需要对照的是同一快照中的画面、时间与轨迹，不能要求两个浏览器始终同步跳帧。

## 4. 5–10 分钟演示顺序

| 顺序 / 建议时间 | 演示操作 | 查看内容及本次记录 |
|---|---|---|
| 1 / 约 1 分钟 | 在镜头前挥手，确认 HDMI 和两个网页都在更新 | HDMI 实时相机画面及 OSD；网页“画面 FPS”和快照编号增长。网页是 96×96 灰度采样，按原视野恢复 16:9，分辨率与 HDMI 分别记录 |
| 2 / 约 1–2 分钟 | 一人入画后横向行走，再离开；必要时调整站位使人体足够大 | 观察“当前捕捉人数”、目标 ID、观测框和历史轨迹；空场数值、确认延迟、漏检和误检均如实记录 |
| 3 / 约 1–2 分钟 | 两人分开行走，再进行一次短暂交会或遮挡 | 当前容量最多 **2 个目标**。观察两条轨迹及各自 ID，记录是否换号、丢失或多计；遮挡续轨单列，不能把累计 ID 数当作当前人数。本轮尚无新版现场多人/遮挡通过记录 |
| 4 / 约 1 分钟 | 点击一个目标框或目标表格行，开关“轨迹”“预测”“关注区” | 查看速度、400ms 预测路径/落点与配置的关注区。预测为估计，不是未来实拍；当前位置模型不提供跌倒或姿态分类 |
| 5 / 约 1 分钟 | 查看温湿度，并将手掌放入红外传感器视野对照变化 | SHT30 环境值、红外相关状态及 HDMI 热图分别记录。红外页标为“估算温度”，未完成逐像素温度标定；45.0℃可能来自限幅，不能按准确体温验收 |
| 6 / 约 1–2 分钟 | 无人且保持场景安静至少 30 秒，再有人进入 | 观察“推理 / 低功耗”由运行转暂停、再恢复；传感采集继续。进入条件含运动/人体判据，噪声可能使等待超过 30 秒。当前相机降帧开关关闭，不以 HDMI 仍有画面判断推理未暂停 |

### 预测、预警与低功耗的验收口径

当前交付日志的关注区为全幅 `[0,0,95,95]`，网页可开关区域显示，不能用鼠标重新划定 ROI。上述演示用于查看配置与预测输出，不保证出现区域边界预警。若要演示内部禁入区，需要另行配置并重新验证；网页出现预测箭头本身也不证明执行了唤醒动作。实际“预测提前唤醒”应有 `MMT_LP_EXIT reason=prewarn` 记录。

当前 `LOWPOWER_ON=1`、进入安静时间为 30 秒；`LP_CAMFPS_ON=0`，只保留暂停推理及持续传感/跟踪。完整的“降低摄像头帧率”要求尚未满足。[串口归档](../../evidence/preview_fps_20261104/board_fw2/serial.log)含重载前的低功耗运行片段，不将其中的暂停/更新计数单独当成最终应用验收证据；现场切换应重新留档，整机功耗也尚未测量。

### 事件与语音的验收口径

PC 页的“最近事件”及 `out/review_live/events.jsonl` 可核查本次收到的事件。板内提供画面和状态接口，当前板内事件历史仍为空，不具备掉电持久化；两端页面相同不代表事件存储能力相同。

蜂鸣器或板上音调输出不等同于题目的 SPI 语音模块播报。本轮没有 SPI 语音模块播报验收证据，不将“检测到跌倒，请确认安全”等语句作为已实现功能展示。

## 5. 无板卡时的审查入口

在仓库根目录运行下列命令，打开 [http://127.0.0.1:8092/](http://127.0.0.1:8092/)，可切换场景、暂停、逐帧查看人数、ID、轨迹和预测，不占用板卡或串口：

```powershell
py -3 tools/mot_replay_server.py --bind 127.0.0.1 --http 8092
```

页面明确标为离线回放。合成场景用于检查算法行为；历史实拍缺少人工人体框和 ID 真值，不能由此得出真人检测准确率或真实 400ms 预测精度。回放播放速度也不是板端画面刷新率。

## 6. 随演示提交的记录

记录实际使用的位流/应用标识、日期、PC/板内入口、各项观察结果及失败现象，并保存必要截图、下载日志和事件文件。历史新画面实测为 PC **2.20 FPS（44 张 / 20.01 秒）**、板内 **2.00 FPS（20 张 / 10.01 秒）**；它是此前特定场景的结果，现场应另记，不能用页面轮询频率替代新画面数。

若出现无信号、无新快照、空场常有人或温湿度全零，先记录该项未通过，再分别核查 HDMI 输入、供电/加载版本、IP/端口、采集及传感接线。白平衡、红外补偿、固定 bank 读锁和位流负 setup 余量等现有限制详见[当前交接说明](../HANDOFF_2026-11-04.md)。

## 1. 数据通路总览

```
MIPI CSI-2 ─► csi_rx ─► debayer ─► 帧缓冲写入 ─► DDR3 @0x01000000
                                                      │
                                          ┌───────────┴───────────┐
                                          │                       │
                                   显示读取通路            CPU 采样通路
                                   (HDMI 60 fps)        (RISC-V, 2.4 fps)
                                                                  │
                                                        96×96 INT8 张量
                                                                  │
                                                      TinyML 加速器（CI 指令）
                                                                  │
                                                          person / not-person
                                                                  │
                                                          APB 寄存器 / UART
```

**关键点**：显示通路与推理通路**完全解耦**。推理慢不影响画面流畅度，
画面实测 59.7–60.3 fps（用视频域 VSYNC 计数器测得），推理 2.4 fps。

## 2. AI 输入通路

### 2.1 帧缓冲格式（实测确定）

| 项 | 值 | 依据 |
|---|---|---|
| 基址 | `0x01000000` | 工程参数 |
| bank 数 | 3，步长 `960×1080×4 + 0x200` 字节 | |
| 活跃 bank | `bank2` | 读校验和变化确定 |
| 每像素 | **4 字节** | `FRAME_LEN/1080 = 3840 = 960×4` |
| 32 位字内容 | **一个 16 位像素复制到高低两半** | 统计显示 `lane0≈lane2`、`lane1≈lane3` |
| 行步长 | 3840 字节 | |
| **亮度通道** | **byte0（bits[7:0]）** | 该通道方差最大 |

### 2.2 降采样参数

| 参数 | 值 | 说明 |
|---|---|---|
| 输出尺寸 | 96 × 96 | 模型输入固定 |
| 源尺寸 | 960 × 1080 | |
| 块大小 | 10 × 11 源像素 | |
| **块内采样** | **5 × 5 = 25 点求均值** | **区块平均，不是点采样** |
| 每帧读取量 | 96×96×25 = **230,400 次** | |

> **为什么必须区块平均**：曾经用最近邻点采样（每 10×11 块只取 1 点），
> 1080 行降到 96 行等于每 11 行才取 1 行，人的竖直结构被切碎，
> 分类结果逐帧乱跳（约 40% 帧随机判"有人"）。
> 改成 5×5 区块平均后立即稳定（连续 34 帧一致判"有人"）。
> **而且更快**：420 ms vs 435 ms —— 判决稳定后不再反复跨越阈值。

## 3. 归一化方式

### 3.1 采用的方式

```c
out[i] = (int8_t)(uint8_t)luma_byte;   /* 纯位重解释，不减 128 */
```

即把 byte 值按二进制原样写入 int8 张量：
- byte `0x00` → int8 `0`
- byte `0x80` → int8 `-128`
- byte `0xFF` → int8 `-1`

**依据**：TinyML 官方静态示例 `sw/tinyml_static_smoke/main.cc:146` 就是
`model_input->data.int8[i] = images[test][i];`（uint8 直接赋给 int8）。
早期曾错误地做 `luma - 128`，导致整幅图亮度偏移一半、分类恒为"空"。

### 3.2 实测输入分布（空场）

| 指标 | 数值 |
|---|---|
| 字节均值 | 98–166（随曝光/光照变化） |
| 标准差 | 66–67 |
| 有符号均值 | ≈ 0（**无偏置**） |
| 低于 `0x80` 的像素 | 34–36% |
| 不同取值个数 | 220–230 |

## 4. 推理性能

| 指标 | 值 |
|---|---|
| 单次推理 | **430–470 ms**（含硬件加速） |
| 每帧 CI 指令数 | **813,352** |
| 推理帧率 | **约 2.4 fps** |
| 采样开销 | 230,400 次 DDR 读，相对推理可忽略 |
| 加速器配置 | LITE，并行 4，cache 512，AXI DW 128 |
| 加速器 UUID | `0x4923687a` |
| 纯软件对照 | 1724 ms → **硬件加速约 4 倍** |

**整机资源**：48,287–51,003 XLR（79%–84%），BRAM 162/256，时序负 slack 0。

### 4.1 为什么是 2.4 fps

`430 ms` 中绝大部分是模型本身的计算量（813,352 条自定义指令）。
**这是模型规模决定的，不是采样或接口开销。**

要显著提速只能：换更小模型 / 减小输入尺寸（96→64→48）/ 降低推理频率。
前两者需要重新训练与量化，后者见 §5。

## 5. 功耗措施（赛题七选二之⑤）

### 5.1 当前状态

- 推理按帧率**连续运行**，约 2.4 fps，无空闲管理
- 需在文档中如实标注为「未启用事件驱动」

### 5.2 建议的事件驱动方案（待与硬件侧对齐）

```
运动检测（帧差面积 / 红外最高温变化）
        │
        ├─ 有运动 ──► 恢复全速推理
        │
        └─ 长时间无变化 ──► 暂停推理 / 降频（如每 10 帧一次）
```

**需要的硬件接口**（由 RTL 侧提供，固件只读）：

| 建议寄存器 | 内容 |
|---|---|
| 运动/空闲状态 | 1 = 有运动，0 = 空闲 |
| 帧差面积 | 量化后的变化面积，供固件做多级判定 |
| 红外最高温 | 用于与阈值比较 |

> 按约定，**固件不自行占用寄存器 11 及以上**，等 RTL 侧给出编号与位定义后再实现。

### 5.3 可量化的收益（估算口径）

- 空闲时暂停推理：推理功耗占比 → 0，只保留采样与比较
- 空闲时降到 1/10 频率：推理平均功耗 → 约 10%
- **代价**：从"进入画面"到"首次判定"的延迟增加一个推理周期（约 0.43 s）

## 6. 与融合层的接口

固件每帧写入两个 APB 寄存器（已对齐）：

| 寄存器 | 地址 | 内容 |
|---|---|---|
| 9 | `0xF8100024` | bit0 = (p > 0)，即"有人" |
| 10 | `0xF8100028` | `0x100 \| (uint8_t)p`，bit8 为有效标记，低 8 位为有符号得分 |

硬件侧：寄存器 9 同步进视频域作为 `ai_person`；寄存器 10 作为
`ai_alive`(bit8) + `ai_score`(低 8 位，有符号)，用阈值 `AI_TH` 比较。
固件未写寄存器 10 时，硬件自动退回只用寄存器 9。

## 7. 曝光对判决的影响（重要，建议写入文档）

模型得分**被整体亮度主导**。同一帧用不同亮度缩放跑推理（受控实验）：

| 输入缩放 | p 值 |
|---|---|
| 100% | −67 … −78 |
| 75% | −91 … −98 |
| 50% | −103 … −104 |

**单调关系**：越暗越倾向"空"。

两次不同曝光下的实测对比：

| 曝光值 | 输入均值 | 饱和率（0xff 占比） | p | 判决 |
|---|---|---|---|---|
| `0x01BBF0` | 166 | **21%** | **+17 … +25** | ❌ 误判"有人" |
| `0x00BAD0` | 98 | **0‰** | **−89 … −100** | ✅ 正确判"空" |

**结论**：之前的"AI 误判 / 得分随光照漂移"，根因是**曝光被调亮到 2.4 倍**
导致 21% 像素削顶，把画面推进了模型的"有人"敏感区。
改回原曝光后饱和归零、误报消失，且 **p100/p75/p50 三个亮度下分数几乎相同**
（差 ≤3），说明判决已退出亮度敏感区。

**因此必须固定曝光（关闭自动曝光）**，否则演示期间光照变化会使判决漂移。

## 8. 已知限制

| # | 限制 | 影响 | 建议 |
|---|---|---|---|
| 1 | 输入是 byte0，非严格 Y | 色度可能混入 | 若后续要提高精度，在硬件侧转真 Y 再写入帧缓冲，固件读取方式不变 |
| 2 | 模型面向全身人像 | 人脸特写检出弱 | 演示时保持全身/半身入镜，距离 1.5–2 m |
| 3 | 2.4 fps | 快速移动可能漏检 | 演示场景为"静止或缓步进入"，可接受 |
| 4 | 曝光敏感 | 光照变化导致漂移 | **固定曝光**，采集与演示期间不变 |
| 5 | 单一阈值 | 无迟滞 | 建议硬件侧加"报警保持"，避免边界抖动 |

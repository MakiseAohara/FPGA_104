# 曝光修复验证：误报消失，判决对亮度不再敏感

时间：2026-10-23 | 板级实测

---

## 1. 改动

`sensor` 长曝光寄存器（SC431HAI，`i2c_master_reg_rom.v`）：

| 寄存器 | 改前 | 改后 |
|---|---|---|
| `0x3e00` | `0x01` | `0x00` |
| `0x3e01` | `0xbb` | `0xba` |
| `0x3e02` | `0xf0` | `0xd0` |
| **曝光值** | **0x01BBF0 = 113,648** | **0x00BAD0 = 47,824（2.38× 更暗）** |

依据：这三个寄存器的行注释里保留着原值 `00 / ba / d0`，
说明当前值是被人为调亮过的。

新位流：`p6_exp.bit`，3,001,872 B，SHA256 `62968FCE4A7D0D989EC0065F862F1FDF6DC3FF2AF70EE1F9E329EE5467F4C71A`

---

## 2. 结果（空场，无人）

| 指标 | 改前 | 改后 |
|---|---|---|
| 输入字节均值 `b0m` | **166** | **98** |
| 饱和率 `sat`（0xff 占比） | **21%** | **0‰** |
| `p100`（原始亮度） | **+17 … +25** ❌ 误判"有人" | **−89 … −100** ✅ 判"空" |
| `p75`（75% 亮度） | — | −93 … −97 |
| `p50`（50% 亮度） | — | −91 … −94 |
| **p100 与 p50 的差** | **约 36**（−68 vs −104） | **约 1**（−93 vs −93） |

### 两个独立的改善

1. **误报消失**：空场从 `p>0`（判有人）变成 `p≈−93`（非常笃定判空）。
2. **亮度敏感度消失**：改前同一帧在 100%/50% 亮度下分数差 36；
   改后三种亮度给出的分数几乎相同（差 ≤3）。

第 2 点尤其重要 —— 说明画面已经退出"亮度敏感区"，
**判决不再随光照漂移**。这正是赛题演示需要的稳定性。

---

## 3. 过程记录（有助于理解）

烧录新位流后，前十几帧仍是旧位流在跑：

```
f=343 b0m=119 sat=32 p100=-72 p75=-62 p50=-104   ← 旧位流（sat 3.2%，p100 与 p50 差 32）
f=0   b0m=98  sat=0  p100=-95 p75=-95 p50=-93    ← 新位流（sat 0，三者一致）
```

`sensor` 配置生效后 `sat` 从 32‰ 归零，分数立刻收敛。

---

## 4. 需要注意

- **画面会明显变暗**（2.38× 曝光减少）。需要目视确认 HDMI 画面仍然清晰可辨，
  不是一片死黑。若太暗，取中间值（例如 `0x3e01 = 0xc0` 左右）折中。
- 本次只验证了**空场不误报**。**"有人时能否检出"必须再测**：
  人站到镜头前，观察 `p100` 是否转正。
- 若新曝光下人不在画面里也偏暗导致检出困难，应在 96×96 缩略图上判断，
  而不是看 HDMI 大画面。

## 6. 结论一句话

**之前的"AI 误判 / 得分随光照漂移"，根因是曝光被调亮到 2.4 倍，
导致 21% 像素削顶、把画面推进了模型的"有人"敏感区。
把曝光改回原值后，饱和归零、误报消失、判决对亮度不再敏感。**

# 10/26 验收清单：入侵 → 报警 端到端

配合自检固件 `main_selftest.cc`（CRC32 `6A1FBC66`，470,354 B）使用。

---

## 一、先跑自检（自动，2 分钟）

```powershell
# 1. 起加载器
<python> load_and_run.py --port COM15 --image tinyml_pdti8.bin ^
    --out .\st --boot-timeout 45 --run-timeout 30
# 2. 另开窗口烧位流，触发复位
```

期望输出（全部 PASS）：

```
MMT_ST DDR      PASS  write+readback ok
MMT_ST ACCEL    PASS  uuid=0x4923687a expected
MMT_ST MODEL    PASS  alloc ok
MMT_ST_IMG      mean=107 sd=72 sat_permil=47 min=-128 max=127
MMT_ST CAM_ALIVE PASS frame changed
MMT_ST CAM_USABLE PASS ok
MMT_ST_INFER    p=-18 a=18 ci=813352 ms=430
MMT_ST INFER    PASS  ok
MMT_ST APB_OUT  PASS  reg9/reg10 written
MMT_SELFTEST_RESULT PASS fail=0
```

**每一项的含义与失败时该查什么**：

| 项 | 判据 | FAIL 时说明 |
|---|---|---|
| DDR | 写图样→扫 2 MB 挤 cache→读回一致 | DDR 通路或地址译码问题 |
| ACCEL | UUID=`0x4923687a` 且 Active=1 | 加速器没进网表 / 融合位流没接上 |
| MODEL | 张量分配成功、9216 B、int8 | arena 太小或模型不匹配 |
| CAM_ALIVE | 两帧校验和不同 | 摄像头没出图 / 读到死 bank |
| CAM_USABLE | sd>5 且饱和率<5% | 画面全平（曝光过低）或过曝（饱和高） |
| INFER | Invoke 成功且 CI>0 | 加速器没被调用 |
| APB_OUT | reg9/reg10 可写 | APB 通路问题 |

> `sat_permil` 是千分比：47 = 4.7%。低于 50（5%）算健康。
> 若接近或超过 50，说明画面偏亮，需降曝光（见下）。

## 二、再跑人工验收（需要人在场，10 分钟）

### 2.1 出图

- [ ] HDMI 有实时画面，无明显条纹/撕裂
- [ ] OSD 文字可读
- [ ] 热力图窗口有内容（不是纯色块）
- [ ] 环境参数有数值

### 2.2 AI 判定

用 `watch_p.bat` 实时看：

- [ ] **空场**：`p` 稳定在 −90 附近，判决 EMPTY
- [ ] **人站 1.5–2 m 全身入镜**：`p` 转正，判决 PERSON
- [ ] 走出画面后 1–2 帧内回到 EMPTY

**分离度判据**：

| 空场 p | 有人 p | 结论 |
|---|---|---|
| ≈ −90 | > +40 | 优秀，阈值放 0 稳 |
| ≈ −90 | 0 ~ +20 | 勉强，需调曝光或阈值 |
| ≈ −90 | 仍为负 | **检出失败**，优先解决 |

### 2.3 报警闭环

- [ ] 人进入 → OSD 红框出现
- [ ] 人进入 → LED 亮
- [ ] 人进入 → 蜂鸣器响
- [ ] 人离开 → 报警按设定保持时间后解除
- [ ] OSD 上显示置信度 / `AI=xx`

## 四、曝光出问题时的应急调整

`sensor` 长曝光寄存器在 `rtl/cam_i2c_ctrl/i2c/i2c_master_reg_rom.v`：

| 寄存器 | 当前值（已降） | 更亮 / 更暗 |
|---|---|---|
| `0x3e00` | `0x00` | 调 0x3e01 更省事 |
| `0x3e01` | `0xba` | 加大 → 更亮；减小 → 更暗 |
| `0x3e02` | `0xd0` | |

判据：**`sat_permil` 应 < 20**（2%），`mean` 落在 100–130 之间最舒服。
改完必须重编位流（曝光在 ROM 里）。

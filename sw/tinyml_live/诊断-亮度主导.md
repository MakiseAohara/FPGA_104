# 决定性实验：模型判决被亮度主导（曝光敏感性）

时间：2026-10-22/23 | 板级实测

---

## 1. 实验设计（无需人配合）

同一帧画面采样一次，然后用**同一个模型**跑三遍，输入分别缩放到
100% / 75% / 50%（在字节域缩放，饱和区因此回到量程内）。

这样可以在**完全相同的场景、完全相同的帧**上，只改变亮度，观察 p 的变化。

固件：`main_live12.cc`，CRC32 `D2955F46`，输出行：

```
MMT_EXP f=<帧> chk=<hex> b0m=<输入字节均值> sat=<千分比饱和率> p100=<> p75=<> p50=<>
```

---

## 2. 结果：判决随亮度单调变化

采集 32 帧（`v7_MERGE8.bit`，场景：空场无人，`b0m=108`，`sat=0‰`）：

| 缩放 | p 范围 | 判决 |
|---|---|---|
| 100% | −67 … −78 | 空 |
| 75% | −91 … −98 | 空（更笃定） |
| 50% | −103 … −104 | 空（贴底，接近量化下限） |

**逐帧一致、无一例外：亮度降低 ⇒ p 单调下降。**

---

## 3. 两次实测的亮度—判决对应关系

| 场景状态 | 输入字节均值 `b0m` | 饱和率 `sat` | p 典型值 | 判决 |
|---|---|---|---|---|
| 亮（之前那次） | **166** | **21%** | **+17 … +25** | **误判"有人"** |
| 暗（本次） | **108** | **0‰** | **−68 … −78** | 正确判"空" |

> 注意：这两次**场景/时段不同**（不是受控对照，中间隔了数小时）。
> 但 §2 的帧内缩放实验是受控的，**结论以 §2 为准**：判决强烈依赖整体亮度。

---

## 4. 结论

1. **模型的 person 分数被整体亮度主导** —— 画面偏亮时系统性偏向"有人"。
2. 当前光照下 `b0m≈166`、`21%` 像素削顶在 `0xff`，正好落在误报区。
3. 之前"得分随光照漂移"的现象由此得到解释：**不是随机漂移，是随亮度单调移动**。
4. 之前怀疑的"byte0 不是亮度导致偏置" —— **修正数据显示有符号均值 ≈ 0，没有偏置**；
   真正的问题是**动态范围被削顶 + 整体偏亮**。

---

## 5. 建议措施（按性价比）

| # | 措施 | 预期 |
|---|---|---|
| 1 | **降曝光/增益**，让 `sat` 接近 0、`b0m` 落在 110–130 | 直接把画面推出误报区，一行 sensor 寄存器即可验证 |
| 2 | 固定曝光（关自动曝光），保证 A/B 采集可比 | 避免采集期间亮度自己变 |
| 3 | 降完之后再定 `AI_TH` | 先让分布分开，再调阈值 |
| 4 | 若仍不够，再考虑硬件 Y 转换 | 但注意：当前问题不是色度/偏置，是亮度动态范围 |

**关键：先降曝光，不要先改阈值。** 阈值只能在分布已经分开时起作用；
现在两个状态的分数区间是重叠的，调阈值会同时压掉检出。

---

## 6. 复现命令

```powershell
# main_live12.cc 编译出的固件 CRC32 D2955F46
# 加载后串口每帧输出一行 MMT_EXP
# 观察 b0m / sat / p100 / p75 / p50
```

判读方法：
- 若 `p100` 为正而 `p75` 为负 ⇒ 该帧正处于亮度敏感区，需要调整曝光
- 若 `p100` 与 `p50` 同号且都远离 0 ⇒ 判决稳定，场景与训练分布匹配良好

# v26 红外源码诊断与上板阻塞

范围：只读冻结的 MERGE14 源码包、v19 源码和 v25 日志；本红外核查阶段未打开设备、编译/刷写红外固件或修改 RTL。最新用户要求的红外诊断优先于 v26 上板；独立的 v26 参数候选构建另见回放说明。

## 结论

`body=450` 是 RTL 对一个相对热量估算值的上限夹值，不是固件写入的默认温度。现有日志不能据此证明 MLX 没有原始数据，也不能证明数据仍在更新。当前位流没有将 MLX 帧计数、错误状态和像素 RAM 映射给 CPU；只改固件无法完成所要求的完整第二步诊断。

v25 日志已独立复算：876/876 个 MMT_LP 行 body=450，876/876 个 MMT_DEC 行 irhot=1；SHT 温度读数有 4 种值，ir_upd 有 32 种值。后者不表示取得了 32 帧红外数据。

## APB_EVT[15:4] 的完整来源

1. `mmt_mlx90640_ctrl` 通过传感器 I2C 地址 `0x33` 读取像素/辅助字，写入 `mmt_sensor_subsystem` 内的原始帧双口 RAM。
2. `v7_ir_proc` 读取该 RAM，将每像素原始计数与慢更新基线相减，取最大正差 `hot_delta`，同时生成相对热力图。它不是 Melexis 校准后的绝对温度计算。
3. `v7_mmt_core.v:123–131` 按默认 `IR_K=3, IR_SH=3` 计算约 `body_raw = ambient_x10 + ((hot_delta*3)>>3)`，再将大于 450 的值夹到 450。
4. `v7_mmt_core.v:238–240` 将 `body_x10_u` 拼入 `obs_evt[15:4]`；顶层 `u_apb_ext` 跨时钟锁存，CPU 从 `APB_BASE+0x2C = 0xF810002C` 读取。
5. v19 的 `EVT_BODY_X10()` 仅提取这个字段。决策写入的是 APB word14/15；word11 是只读，不存在 v19 向 body10 写 450 的路径。

因此，450 表示估算链路的顶格读数。热差长时间偏大、最大值被异常像素主导、基线被冻结或数据停止后保留旧值都需要进一步区分；本次没有将这些可能性认定为根因。

## 哪些状态可以读取

| 信号 | 实际连接 | CPU/现有日志能否读取 |
|---|---|---|
| 控制器 `frame_valid` | 每帧完成单拍脉冲，连内部 `ir_fv`，再送处理与时间对齐 | 没有 APB 帧脉冲寄存器 |
| 控制器 `frame_cnt` | `v7_mmt_core.v:105` 的 `.ir_frame_cnt()` 悬空 | 没有 APB 帧计数寄存器；不能假定实现中仍保留可访问计数器 |
| `ir_bus_err` | 连内部线，送 HDMI OSD 的 `dg_ir_err` 和合成 `sns_ok` | 无 CPU MMIO / 串口字段；可供现有屏幕诊断显示 |
| APB_EVT bit2 `ir_valid` | 来自 `v7_ir_proc.valid` | 可读，但处理完成置 1 后只在复位时清 0，是“曾处理过一帧”保持位，不是新帧计数或新鲜度 |
| 原始帧 RAM | 传感器子系统写，`v7_ir_proc` 独占现有读端口 | 未连接 CPU 地址空间 |
| `hot_delta`、未夹值 `body_raw` | 内部计算和 OSD 路径 | 未映射 CPU |
| APB_EVT bit1 `ir_hot` | `ir_valid && hot_delta >= HOT_ON`，默认 HOT_ON=24 | 可读；不等于当前存在人体或总线仍正常 |

`v7_ir_proc.valid` 在处理完成后保持 1；出现后续总线错误时没有清除该位、hot_delta 或 body。因此旧的 450/irhot=1 可以继续显示。v19 的 `ir_upd` 统计 `(evt & 0xF) ^ (body10 << 8)` 的变化，其中还包含运动 bit0；它不是 MLX 帧计数。

顶层 APB 读译码只提供 word0..13、16..18 的既有状态。word16..18 是摄像头 SCCB，接 `io_cam_*`，不是传感器 `io_sns_*` 总线；SoC 自带 I2C 引脚输入被接常高、输出未用。不能通过相机 I2C 命令或读取未映射地址取得 MLX 像素/错误状态。

## v19 是否计算 MLX 温度

没有。v19 不读取 MLX 原始帧、EEPROM 标定数据，也没有 Melexis `ExtractParameters/CalculateTo/GetFrameData` 调用。现有热力图及估算体温完全在 RTL 相对基线链路内。要得到经校准绝对温度，还缺 EEPROM 标定参数、对应温度计算及有效性/新鲜度处理；这不是给日志新增几个 printf 就能补上的功能。

## 接线记录的可确认范围

- 源码配置：SCL=`io_sns_scl` / `GPIOL_11`；SDA=`io_sns_sda` / `GPIOL_09`；两个引脚均配置 `3.3 V LVCMOS`、`weak pullup`。SHT 与 MLX 共用该 RTL I2C 总线，默认 400 kHz；MLX 配置地址 `0x33`、8 Hz。
- 未现场确认：模块实际接到哪个接插件针脚、是否外接上拉及阻值、模块实际电压和接触状况。I/O 电平标准不能代替电源测量，内部 weak pullup 也不能证明外部上拉存在。
- 本次没有得到接线照片或测量数据；未把源码配置写成实物接线事实。

## 第二步的明确阻塞

所要求的每秒 `frame_valid 计数、bus_err、若干原始像素、body10` 中，CPU 只能取得 body10 和保持型 valid/hot 摘要。源码已足以定位这一接口缺口，缺的不是另一份同名固件文件。

完整第二步需要一个已存在、可由 CPU 访问的 MLX 诊断接口，或新增状态/原始帧的只读寄存器映射。后者需要改 RTL/位流，超出本次“不动 RTL”的红线，因此本次没有执行。未用保持位冒充 frame_valid 计数，也未把未映射地址返回的零当成像素/无错误。

由于没有取得当前 bus_err 和帧计数，尚不能按第三步判定硬件/总线故障或温度写回缺失；手靠近/移开 10 秒的原始帧响应试验也没有完成。没有烧录无法提供指定观测量的诊断固件。v26 上板保持暂停；原任务的离线参数回放可独立继续。

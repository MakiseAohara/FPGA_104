## 根因：RTL 发送缓冲预取错位（不是协议格式问题）

现象：`MMT_GE` 里的 `pkt_cnt` 一直涨，网卡 `ReceivedPacketErrors` 同步涨，应用层收不到任何包。
排查顺序与结论：

1. 长度字段（IP/UDP）与补齐 —— **已修**（心跳 18 B 负载补齐，长度按补齐后计算），但仍报错；
2. 最小帧 60 B —— 已满足，仍报错；
3. **真正的根因**在 `rtl/ge/ge_raw_tx.v` 的 `S_PRE`：

```verilog
// 改前：每一拍都重写 cur 和 rdaddr
S_PRE: begin
   gmii_txd <= (pre_cnt == 3'd7) ? 8'hD5 : 8'h55;
   cur      <= rddata;   // rddata 是"上一拍地址"的数据
   rdaddr   <= 1;        // 每拍都写 1
   ...
```

`ge_dpram32` 是**同步读**（`always @(posedge rd_clk) rd_data <= mem[rd_addr]`），
所以经过 8 拍前导码之后，`cur` 稳定地停在 **mem[1]**——首字（mem[0]）被跳过，
整帧相对缓冲区**前移 4 字节**：目的 MAC 变成垃圾，网卡按坏帧丢弃（`err+1`），
而 RTL 的 `pkt_cnt` 照常累加，于是出现"发了但全都错"的现象。

**修复**（只改 `S_PRE`，`S_DATA` 的流水线逻辑保持原样）：

```verilog
S_PRE: begin
   gmii_tx_en <= 1'b1;
   gmii_txd   <= (pre_cnt == 3'd7) ? 8'hD5 : 8'h55;
   pre_cnt    <= pre_cnt + 1'b1;
   if (pre_cnt == 3'd1) begin cur <= rddata; rdaddr <= 1'b1; end  // 这一拍 rddata 正好是 mem[0]
   if (pre_cnt == 3'd7) st <= S_DATA;
end
```

## 实测结果

抓包（`evidence/eth_rgmii/udp_probe.py`，绑定 8080）：

```text
from 169.254.47.62 len=18  magic=b'MT' ver=1 type=2 eid=0 seq=0/1 ts=199018 body=0000   ← 心跳
from 169.254.47.62 len=21  magic=b'MT' ver=1 type=1 eid=4 seq=0/1 ts=205474 body=0030300000 ← 报警事件
from 169.254.47.62 len=64  ...  ← 排查用的固定测试帧（GE_RAW_TEST_FRAME，已默认关闭）
```

- 心跳：**每 2 s 一条，0 B 负载，eid=0、total=1**，符合 `UDP_EVENT_FORMAT.md`；
- 报警事件：`type=1`、`eid` 递增、body 5 B `type,x,y,conf,obs`（大端）；
- 事件同时写入 `out/live2/events.jsonl`（`{"kind":"INTRUDE", ..., "x":28,"y":47,"conf":100,"obs":2}`）。

## 缩略图（type=3）

- 固件：`ge_thumb_prepare()` 在报警开始时置 9216 B 原始灰度、`total=10`、`seq=1..10`；
  `ge_thumb_pump()` 每轮主循环发一片（**本轮才接上主循环调用**，之前只 prepare 不 pump，所以一片都没发）；
- PC：`web_monitor.py` 按 seq 重组 9216 B → `png_gray(96,96,scale=2)` → `out/live/thumbs/*.png`。

## v5.2：纯网口模式下的实时画面（2026-11-03 15:50 实测）

报警缩略图只在有人时才有，纯 UDP 模式下 PC 页面会一直是黑的。v5.2 增加：

- **空场/低功耗时每 500 ms 推一帧** `type=3`、`eid=0xFFFF0001`（同样 9216 B / 10 片），
  报警缩略图优先：上一组没传完就不插入；
- PC 端 `web_monitor.py` 收到该 eid 就只刷新预览（`/frame.png` + `out/live/thumbs/live.png`），
  **不写事件列表**；页面用毫秒级 cache-buster 拉图。

实测（无串口，仅 `--udp 8080`）：`out/live4/thumbs/live.png` 生成，页面正常显示 96×96 画面
（截图 `evidence/web/dashboard_udp_2026-11-03.png`）。带宽：9216 B × 2 帧/s ≈ 18 KB/s。

## 遗留

- 板内 HTTP 协议栈仍在固件里（`http_app.h`/`net_core.h`），因 RX 方向 `ge_raw_rx` 尚未跑通，
  页面实际由 PC 端 `tools/web_monitor.py` 提供；上报结论按"上行已打通、下行链路已通（ping 有回复）"。 
- 固定测试帧默认关闭（`GE_RAW_TEST_FRAME 0`），避免污染事件流。

# 千兆网口事件上报（只用发送方向）— 2026-11-03 现状

## 结论

**代码完成、编译通过、上板可见发送计数在涨，但 PC 侧帧被判为错误帧，尚未验收通过。**

## 一、已实现（固件）

基线：`evidence/v30_mot/main_live30.cc`（v3.8 行为 + 网口发送），**未改**判决/低功耗/白平衡
（白平衡顺带修回收敛值 `WB_B=0x170`，原 `0x1A4` 偏蓝）。

- 发送路径：沿用 `ge_send()`（软件组帧：广播 MAC + IPv4 + UDP 8080 + 软件 FCS），目标 `169.254.47.61:8080`；
- 包格式（临时版，等 `UDP_EVENT_FORMAT.md` 对齐）：
  ```
  0  魔数 0x4D 0x54
  2  version = 1
  3  type: 1=事件 2=心跳 3=缩略图分片
  4  event id (4B, BE)
  8  seq (2B) / 10 total chunks (2B)
  12 timestamp ms (4B)
  16 body
  ```
  - 事件体：`ev(1) x(1) y(1) conf(1) obs(1) nd(1) 00 00`，ev=1 报警开始、2 结束；
  - 心跳体：`obs person alarm fps area_lo area_hi 00 00`，每 2 s 一条；
  - 缩略图：报警开始时把 96×96 灰度用 `png_gray()`（zlib stored）编码，按 900 B 分片，
    每轮主循环发一片，失败直接丢（不重试、不阻塞）。
- 编译结果：**360,434 B / CRC32 `CF54C2FF`**，烧录 `MMT_LOAD_PASS DDR_CRC` + `LOAD_OK` 均通过。

## 二、上板实测

| 项 | 结果 |
|---|---|
| 固件运行 | ✅ 串口 `MMT_MOT`/`MMT_LP`/`MMT_GE` 正常，`camfps=60` |
| 板子发送计数 | ✅ `MMT_GE ctrl=6684673` ⇒ 高 16 位 = **102 包已发** |
| PC 收包（0.0.0.0:8080） | ❌ 0 条；网卡 `rx=0`，`err=4`（6 s 内，正好≈心跳数） |

判定：**帧发出去了，但被网卡当作错误帧丢弃（FCS 不符）**。
同一套 `ge_send()` 之前发 110 字节固定帧是好的（1800+ 帧、err=0），所以差异在
**这次的负载长度/内容**（24 B 负载 vs 110 B 帧），最可能是：
1. `ge_send` 里 `f[]` 从 256 扩到 1200 后，某些长度分支没跟着改；
2. 事件包只有 24 B，帧长 66 B，**小于以太网最小帧 64 B（不含 FCS）**——66 是够的，
   但若 RTL 侧少发/多发一个字节，FCS 就对不上；
3. RTL TX 的 `txlen` 与实际写入字数不一致（之前修过 `waddr_r` 错位）。

# 网口最终状态（2026-11-03 傍晚）

## 一、发送：完全打通（有实测证据）

主设计上板，PC 抓到 1800+ 帧、`err=0`：

```
169.254.47.62:8080  len=64  MMT-RAW-TEST-0123456789abcdef...END
```

根因与修法：`ge_raw_tx` 的 APB 写地址比数据早一拍（`wptr` 同拍自增），整帧错位一个 32 位字，
FCS 必然不符 ⇒ 网卡丢帧。加 `waddr_r` 同拍寄存后立即正常。

## 二、接收：硬件层已打通，固件层未接上

| 层级 | 状态 | 证据 |
|---|---|---|
| PHY/RGMII | ✅ | NIC 显示 1 Gbps；PHY 侧链路正常 |
| util + **gmii_arbi** + mac_top | ✅ | **ping 拿到回复**（1/3，丢包来自固件在低功耗里 500 ms 一轮） |
| 固件读到 UDP 负载（APB 窗口） | ❌ | `MMT_GE ... rx=0`：`udp_rec_data_valid` 没有把 `u_ready` 拉起来 |
| 板内 TCP/HTTP | ❌ | 依赖上一条；且 mac_top 只把 UDP 交上来，TCP 会被丢，要做 HTTP 必须自研 raw RX |

**今天最重要的定位**：主设计里 RX 一直不通，**原因是少了 `gmii_arbi`**。
把 arbi 加回 RX 路径（util → arbi → mac_top，与厂商 demo 一致）后，ping 立刻有回复。
这条对后面所有 RX 工作都是前提。

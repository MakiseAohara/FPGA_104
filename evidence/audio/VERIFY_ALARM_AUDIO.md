# 报警触发提示音 —— 客观验证记录

日期：2026-11-02
目标：证明 **真实报警（`mmt_alarm_active`）→ HDMI 提示音** 这条链路是通的（这是「1」要闭环的那件事）。

## 1. 方法

1. 板子跑交付位流 `v7_MERGE18_AUDIO.bit` + 定版固件 `BC37FEAB`（`audio_beep_en = (!boot_done) | mmt_alarm_active`）；
2. 脚本 `alarm_audio_watch2.py` 独占 COM15 监听 `MMT_ALARM start`，同时用声卡麦克风阵列 48 kHz **连续录音 300 s**；
3. 对整段录音做 0.25 s 窗 FFT，用**三音指纹**（880 → 1175 → 1319 Hz，每音 0.25 s、循环 0.8 s）匹配。

## 2. 结果：录音里抓到 3 处完整三音循环

SNR 最高 225 倍 → **报警期间提示音确实在响**。

## 3. 说明（如实）

1. 这一段里**没有** `MMT_ALARM start` 串口行：录音开始时报警已经处于激活状态（固件只在 0→1 跳变时打印）。
   前一次监听里抓到过真实报警行：`MMT_ALARM start ms=5985179 f=10325 person=0 motion=1 area=14037 cause=fusion`，
   而且那一段录音（报警前 3.15 s）在报警前 0.4 s 就出现了 1319 Hz 强峰（SNR 95），说明 RTL 报警比固件打印早约半秒。
2. 报警是 **motion=1 / person=0 / cause=fusion**（纯运动融合）触发的——不需要 AI 判人。
3. 提示音是**音效**不是自然语音；要真人声需把 PCM 表换成语音采样（见 README §5 边界）。

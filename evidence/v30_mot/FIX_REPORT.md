# FIX_REPORT — v30 多目标跟踪三个 bug 修复（v1.3）

> 约束：只改 `evidence/v30_mot/mot_core.h` 与 `main_live30.cc` 的 MOT 相关代码；**不动 RTL、不动约束、不动白平衡**（WB 仍为 R=0x158 / G=0x118 / B=0x1A4）。

## 1. 三个 bug 的根因与改法

### Bug 1 —— 静止目标被鬼影过滤丢掉

**根因**：鬼影判据是"连通域内帧间运动像素 < 面积/8 就丢弃"。人站定以后帧间差分≈0，于是每帧都被判成"人走了留下的背景残留"，航迹被饿死。
板上日志 `board_v30f`：369 帧里 **163 帧 nd=0**，而这些帧的最大连通域面积在 60~8500（真有人）。

**改法**（`mot_label` + 新增 `mot_hit_confirmed()`）：连通域与某个**已确认航迹**的当前框 IOU ≥ 0.30（`MOT_GHOST_IOU=300`），
或质心距 ≤ `MOT_GHOST_GATE=10 px` 且包围盒面积不小于该航迹的 1/2 时，**跳过鬼影过滤**。
另加 `MOT_STILL_MAX=20`：同一目标静止超过 20 帧（≈10 s）后不再豁免，避免"幽灵航迹"永生（板上实测空场会因此出现常驻航迹）。

### Bug 2 —— 整幅前景让 MOT 卡死

**根因**：`MOT_MAX_AREA=9000` 把整幅前景直接丢掉；而背景在"前景像素"上只有 1/128 的更新速度，一旦整幅被判前景就永远学不回来 ⇒ 之后每一帧都是整幅前景、零检测。
板上日志：**66 帧前景面积 ≥ 8500**。

**改法**（`mot_step(..., ai_p)` 新增 AI 分数入参）：
- `raw_area > MOT_MAX_AREA` 且 **AI 判无人（p < 0）** ⇒ 立刻把背景重置为当前帧、本帧不出检测（`big_reset`）；
- `raw_area > MOT_MAX_AREA` 且 **AI 判有人（p ≥ 0）** ⇒ 输出一个包围整块前景的检测、**不重置背景**（`big_full`）。

配套两条护栏（都在 MOT 内）：整幅检测不参与速度更新（否则质心跳变会算出几百 px/帧 的假速度）；
整幅检测统一压进同一个航迹（IOU 天然匹配），不额外新建。

### Bug 3 —— 编号换得太多

**根因**：确认航迹 3 帧就删（2 fps ≈1.5 s），人一遮挡/一顿就换号；新建航迹只认 IOU，走快一点就断。
板上日志：67 条确认航迹里 32 条在 8 帧、25 px 内有新航迹出现。

**改法**：
- 已确认航迹 `MOT_MAX_MISS` 3 → **6**；未确认航迹保持 **3**（`MOT_MAX_MISS_UNCONF`）；
- 二级关联对"刚丢的已确认航迹"把重连半径从 16 px 放到 **25 px**（`MOT_REID_PX`），沿用原 ID 与速度；
- 从没被确认过的噪点航迹不打印 `MMT_TRK`（只留在表里做候选）。

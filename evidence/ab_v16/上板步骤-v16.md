> 配套位流：**MERGE11**（`project/v7_camera_ai/bitstream/v7_MERGE11.bit`）
> 固件目录：`sw/tinyml_live/v16/fw/`（六个变体）＋源码 `sw/tinyml_live/main_live16.cc`
> 前提：本机无板子；以下在队友那台有 FTDI + 摄像头的机器上执行。

## 1. 六个固件文件（都在 `sw/tinyml_live/v16/fw/`）

| 文件 | 用途 | 关键宏 |
|---|---|---|
| `tinyml_pdti8_v16_base.bin` | 基线：预处理与 v15 相同（整幅压缩、无归一化/拉伸）；②/⑤ 与 v15 一致 | 全默认 |

## 2. 一次对比实验怎么做（同一场景、同一站位）

1. **固定场景**：摄像头不动，人站固定位置（例如 1.5 m 正对），灯光不变。
2. **加载器先起**（每次换固件都要重灌）：
   ```powershell
   cd <仓库>\sw\tinyml_live
   python load_and_run.py --port COM15 --image v16\fw\tinyml_pdti8_v16_base.bin ^
       --out .\capture_v16_base --boot-timeout 45 --run-timeout 120
   ```
3. **再烧位流**（MERGE11，触发复位并开始灌固件）：
   ```powershell
   powershell -ExecutionPolicy Bypass -File <mmt>\tools\flash_vendor.ps1 ^
       -Bit <仓库>\project\v7_camera_ai\bitstream\v7_MERGE11.bit
   ```
4. 每个固件采 **≥120 帧** `MMT_OSD` 日志（约 50 s），再换下一个变体，重复 2–3 次。
5. 统计每个变体：`b0m` 均值/分布、`p` 的分布（空场 vs 有人）、AUC/分离度。

> 每次换固件都必须重新"起加载器→烧位流"，否则跑的还是上一份固件。

## 3. 日志怎么读

| 行 | 出现条件 | 关键字段 |
|---|---|---|
| `MMT_LIVE_BOOT v16 ...` | 开机 | 固件版本与编译期宏 |
| `MMT_CFG v16 CROP_MODE=… NORM_ON=… STRETCH_ON=… AUTOEXP_ON=… LP_CAMFPS_ON=… LP_VTS_MULT=… …` | **每个变体都有**（必需） | 确认灌进去的到底是哪个变体 |
| `MMT_CAM 320e=… 320f=… 3e00=… 3e01=… 3e02=… 3e03=… 3e08=… 3e09=… exp=… gain=…` | 仅当 `AUTOEXP_ON` 或 `LP_CAMFPS_ON` 被打开 | **启动时读到的相机寄存器原始值**；任何写相机前先核对这一行 |
| `MMT_CAM_VTS ok=… vts=… rom_vts=0` | 总是 | 只读 VTS（MERGE11 起保留） |
| `MMT_PP crop=… norm=… stretch=… gain_x100=… mean_sensor=… mean_in=… mean_out=… lo=… hi=…` | 任一预处理宏非 0 | `mean_sensor` 是原始取样均值（AE 用），`gain_x100=100` 表示未放大 |
| `MMT_AE init …` / `MMT_AE mean=… act=… exp 0x…->0x… gain 0x…->0x…` | AUTOEXP_ON=1 | `act`：1 曝光↑ 2 曝光↓ 3 增益↑ 4 增益↓；饱和时 `act=-1/-2` |
| `MMT_LPCAM init/enter/exit …` | LP_CAMFPS_ON=1 | VTS 初始值、进入后的新值、退出恢复值 |
| `MMT_LPCAM state=… vts=… mult=… camfps=…` | LP_CAMFPS_ON=1 且 low_pwr | 降帧状态与实测帧率（字13[31:24] 帧计数推算） |
| `MMT_OSD f=… p=… b0m=…` | 每帧 | 原有推理日志（b0m 是 96×96 输入图均值） |
| `MMT_LP f=… lowpwr=… paused=… camfps=… vts=…` | 每帧 | v15 已有的低功耗指标行 |

## 4. 上板前的硬性前提（务必先看）

1. **任何写相机之前先看 `MMT_CAM` 行的启动读数**：
   - VTS（0x320e/0x320f）必须在 `[0x0400, 0x0a00]` 才允许降帧；
   - 曝光（0x3e01:0x3e02）与增益（0x3e08:0x3e09）必须非 0 才允许自动曝光。
   不满足时固件会打印 `MMT_LPCAM init … DISABLED` / `MMT_AE_ERR boot regs invalid (AE disabled)`，
   **不会写相机**。
2. 写白名单只允许：`0x320e 0x320f 0x3e00 0x3e01 0x3e02 0x3e03 0x3e08 0x3e09`；
   其它地址的写入会返回错误并在日志里体现（`MMT_AE_ERR` / `MMT_LPCAM … FAILED`）。
3. 每次写入都会**读回校验**，不一致会回滚旧值；连回滚都失败时会永久关闭该功能并打印 `FAILED/ERR`。
4. 曝光/增益的"码值"按 16 位线性近似处理（`{0x3e01,0x3e02}`、`{0x3e08,0x3e09}`），
   **线性度未上板标定**——若发现 MMT_AE 动作方向相反或剧烈振荡，先关 AUTOEXP（见 §5）。

## 5. 出问题怎么关掉对应功能（改宏重编，不改 bin）

在 `main_live16.cc` 顶部：

```c
#define CROP_MODE        0    /* 0=整幅 1=正方形 2=1.5 倍宽 */
#define NORM_ON          0
#define STRETCH_ON       0
#define AUTOEXP_ON       0
#define LP_CAMFPS_ON     0
#define LP_VTS_MULT      3    /* 2..4 */
#define AE_DIM_ENABLE    0    /* 0=下限=初始值（任务书）；1=允许降到初始值/4 */
#define AE_SET_MANUAL    0    /* 1=尝试写 0x3e03 手动模式位（候选值，需确认） */
```

- 只想回到"v15 行为"：全部保持 0（本目录的 `base` 就是这个配置）。
- 自动曝光动作异常：`AUTOEXP_ON=0` 重编；相机寄存器不会被写。
- 降帧后画面异常/掉帧：`LP_CAMFPS_ON=0` 重编；VTS 不会被写。
- 归一化后画面发灰：`NORM_ON=0`。
- 裁剪切到人：换 `crop2` 或回 `base`。
- `AE_DIM_ENABLE=1` 才会允许把曝光/增益降到初始值的 1/4（主机测试的偏亮场景需要它）；
  任务书默认是"下限=初始值"，所以**默认只能变亮、不能变暗**。
- `AE_SET_MANUAL=1` 会尝试写 `0x3e03 = 初始值 | 0x01`；这个位定义**尚未上板确认**，
  第一次试的时候先看 `MMT_CAM` 的 0x3e03 读数，并准备好随时断电。

重编命令（与构建 v16 相同）：
```powershell
python build_variants.py --project <TinyML工程> --toolchain <riscv工具链bin> ^
    --build-script <仓库>\sw\tinyml_live\build_tinyml_firmware.py ^
    --src main_live16.cc --out .\dist
```

## 6. 明确"未上板验证"的部分（写报告时别夸大）

- 自动曝光控制器只做了**电脑端模型验证**（偏暗 45 → 17 次评估进入目标、偏亮 200 → 11 次进入、无振荡、全程在上下限内）；
  真实相机的曝光/增益线性度、生效延迟、0x3e03 模式位都**未验证**。
- 相机降帧只做了**模拟寄存器层验证**（进入 ×3 / 退出恢复 / 越界禁用 / 写失败回滚，全部 PASS）；
  真实 VTS 写入是否被 SC431HAI 接受、画面是否同步变化**未验证**。
- 预处理变体只做了**合成帧验证**（回归逐像素一致、裁剪落点、归一化/拉伸指标）；
  板上真实画面下的 p 分布变化**未验证**。
- 本固件**不含**任何新 RTL 依赖；位流仍是 MERGE11。
